## 总体目标

“AI 模型与用量”在视觉上应还原旧系统“AI 用量与费用”的完整控制台体验，而不是普通后台表格页。

关键判断标准：

1. 用户第一眼看到的是旧系统同款的“月度账单 + 每日消耗 + 单日构成 + 厂商模型 + 业务场景 + 机构排行”组合。
2. 页面密度、卡片圆角、浅蓝背景、弱边框、阴影、蓝色主视觉、紫色总金额 pill 与旧图保持一致。
3. 左侧导航和顶栏仍服从 `zmtg-clean` 当前平台壳层，但本页面内容区的排版、卡片层级、标题文案和交互状态按旧图还原。
4. 数据使用当前新系统低敏 API / mock contract；禁止为视觉还原引入旧 schema、旧权限和真实厂商调用。

## 与 zmtg-clean 当前实现的映射

推荐在当前 `OpenPlatformAiReadonlyPanel` / AI usage cost contract 的基础上重排 UI，不改变权限和数据边界。

数据映射：

1. 月度总览：从当前月度低敏 usage summary 映射 `totalCost`、`totalCalls`、`totalTokens`、`successRate`、`peakDayCost`。
2. 每日消耗：从 daily usage 聚合为按模型 / 厂商颜色堆叠的 day series。
3. 单日模型构成：从 selected day 的 model breakdown 映射模型名、调用次数、token、金额。
4. 厂商明细：从 vendor summary 映射厂商卡片和选中厂商模型表。
5. 业务场景：从 scenario usage summary 映射场景卡片，不暴露 prompt、请求体、secret、原始厂商响应。
6. 机构排行：从 institution usage summary 映射机构排名与场景明细。

实现约束：

1. 不增加真实厂商外呼。
2. 不调用 `decryptSecret`。
3. 不读取 `.env.local`、`DATABASE_URL`、`ZMTG_SECRET_ENCRYPTION_KEY`。
4. 响应和日志不包含 `apiKey`、`encryptedApiKey`、`ciphertext`、`authTag`、`iv`。
5. 继续通过 platform guard 和 scope 检查。
6. 只使用低敏统计字段，不把旧系统数据表结构作为新实现依据。

## 验收清单

视觉验收：

1. 2048px 桌面截图与旧图整体观感一致。
2. 首屏能同时看到月度账单、每日消耗、单日模型构成、厂商卡片首行。
3. 页面下半区为左侧业务场景、右侧机构排行的两列布局。
4. 厂商折叠态和展开态均可达到旧图效果。
5. 月份选择弹层与旧图结构一致。
6. 卡片不能变成厚重 dashboard，也不能变成普通表格页。
7. 文案使用中文，保留必要英文模型名和 `general chat`。

交互验收：

1. 点击每日图表某日后，单日模型构成日期与金额同步。
2. 点击厂商卡片切换选中厂商，展开模型明细表。
3. 月份选择器可以清除、选择月份、回到本月。
4. 导出按钮可以保留当前 dry-run / disabled 状态，但视觉必须存在。
5. 加载失败时输入和可变更按钮 disabled。

安全与测试验收：

1. 401 / 403 覆盖。
2. 低敏响应断言不含 secret 字段。
3. 断言无 POST / PUT / DELETE mutation。
4. 断言无真实外呼厂商 API。
5. 断言无真实 secret 解密。
6. 组件测试覆盖折叠态、展开态、月份弹层、空态和加载失败态。
