- 如需描述凭证来源，只能使用抽象占位说明，例如“服务端内部凭证句柄”或“后续单独审批的凭证后端”，不得提供可复制的具体值。
- credential provider 的输入只能在后续 runtime 任务中由服务端可信上下文构造，不能来自 HTTP body、query、header、cookie、localStorage、sessionStorage、前端表单或客户端可控字段。
- credential provider 的输出即使在后续 runtime 中也只能服务于同一服务端调用链，不得进入前端 DTO、audit payload、日志、错误对象、devlog 或健康摘要。

## runtime 前置问题清单

| 问题 | 复核口径 | 本轮结论 |
| --- | --- | --- |
| credential provider 输入边界 | 输入是否只来自服务端可信上下文，是否禁止客户端携带 credential handle、endpoint 覆盖或 provider 选项 | 后续必须先定义 contract，本轮不实现 |
| credential provider 输出边界 | 输出是否能被拆成“仅给 adapter 的短生命周期材料”和“可审计的脱敏状态” | 后续必须先定义脱敏结果，本轮不定义真实材料结构 |
| secret 生命周期 | secret 从读取、使用、失效、撤销到释放的时间窗口如何控制 | 后续必须明确生命周期，本轮不读取或缓存 |
| 配置开关 | 是否需要全局、环境、租户、source / vendor / system 维度开关 | 后续必须单独评审，本轮不新增配置 |
| 错误分类 | provider 不可用、凭证缺失、凭证撤销、权限不足、超时、未知错误如何映射为稳定错误码 | 后续必须只暴露稳定分类，本轮不接真实错误 |
| 日志脱敏 | 日志是否默认拒绝 credential handle、secret path、账号、token、password、header、连接串、provider 原始错误和 stack | 后续必须形成 denylist，本轮不新增日志 |
| 审计语义 | audit 是否只记录尝试读取、成功 / 失败、稳定错误码和非敏感 provider 枚举 | 后续必须单独确认，本轮不新增 audit runtime |
| 环境隔离 | 本地、测试、预发、生产是否必须使用不同 provider 后端和开关策略 | 后续必须先定义环境隔离，本轮不读取环境密钥 |
| 与 HIS adapter 的依赖边界 | provider 是否只负责凭证材料，adapter 是否只负责外部探测和错误归一 | 后续必须解耦 contract，本轮不实现 adapter |
| fallback / retry 行为 | provider 失败后是否允许 fallback、是否允许 retry、重试次数和退避策略是否会放大风险 | 后续必须独立评审，本轮不设计执行策略 |
| 初始化失败行为 | provider 初始化失败时系统应拒绝真实探测、降级为不可用还是继续 fake provider | 后续必须定义安全失败口径，本轮不接初始化 |
| system actor / service actor 关系 | 后台任务读取凭证时 actor 如何表达，是否能复用人工用户上下文 | 后续必须由 audit 语义任务确认，本轮不实现 actor |
| 单独审计事件 | provider 读取是否需要单独 audit event，还是附着在测试连接 / scheduled health check audit 中 | 后续必须单独决策，本轮不新增事件 |
| runtime 缓存凭证 | 是否允许进程内缓存，缓存上限、失效、撤销和多实例一致性如何处理 | 默认不允许，除非后续任务明确审批 |
| 敏感字段出现位置 | 日志、错误对象、devlog、测试快照、健康摘要、DTO、audit、PR 描述是否允许出现敏感字段 | 默认不允许，后续必须用脱敏检查证明 |

## 风险清单

- 泄露真实凭证：任何真实 secret、token、password、API key、OAuth token、private key、client_secret、连接串或凭证后端路径都可能通过日志、错误、DTO、audit、devlog、测试快照或 PR 描述泄露。
- 日志记录敏感字段：provider 原始错误、外部响应、header、stack、SQL 或 credential handle 若进入日志，会绕过前端和 DTO 的安全边界。
- provider 与 adapter 耦合过深：若 provider 同时决定外部网络、厂商协议或健康状态，会导致凭证读取和 HIS 探测难以独立验证与回滚。
- 生产配置误用测试凭证：本地 / 测试 provider、fake provider 或 placeholder 若被生产开关误用，会造成误判或真实外部调用失败。
- fallback / retry 导致异常放大：provider 不可用时若自动 fallback 到不安全来源，或无上限 retry，会扩大凭证泄露、外部压力和错误噪音。
- 未定义 system actor 审计语义：后台 runner 或 service actor 读取凭证时若冒充人工用户，会污染 audit 查询与追责口径。
- 本地调试绕过生产安全边界：开发环境的便利入口若未隔离，可能被误带到生产配置。
- 凭证生命周期不清导致长时间驻留：真实材料若长期驻留在内存、job payload、全局变量或缓存中，会增加撤销失效和泄露风险。
- 错误处理过度暴露 provider 细节：provider 名称、后端路径、权限错误、厂商认证响应或 stack 若透传，会泄露内部结构。
- 后续任务误把 plan 当作实现批准：本轮文档中的候选项和边界说明不是 runtime 批准。

## 后续拆分建议

以下仅为候选项，不自动执行。每个候选项都需要单独 PR、单独任务编号、单独允许文件、单独禁止范围和单独验收口径。任何 runtime 任务都必须在后续获得明确批准后才能进入。

| 候选项 | 目标 | 边界 |
| --- | --- | --- |
| credential provider contract plan | 定义 provider 输入、输出、稳定错误码、调用方和被调用方责任 | 只写 contract 边界，不写实现代码，不读取真实凭证 |
| secret redaction plan | 定义日志、audit、DTO、错误对象、devlog、测试快照和 PR 描述的脱敏规则 | 只写 denylist / allowlist 和检查口径，不接真实 provider |
| configuration gate plan | 定义真实 provider 启用前的全局、环境、租户、source / vendor / system 开关 | 不新增配置文件，不新增环境变量文件，不接生产配置 |
| audit semantics plan | 定义 provider 读取在手动测试连接、scheduled health check、system actor / service actor 中的 audit 语义 | 不修改 audit runtime，不新增 schema / migration |
| credential lifecycle plan | 定义读取、使用、释放、过期、撤销、轮换、失败和缓存禁止口径 | 不新增 credential storage，不定义真实后端路径 |
| provider / HIS adapter dependency boundary plan | 定义 provider 与 HIS adapter 的依赖方向、材料传递范围和错误归一责任 | 不实现 HIS adapter，不发起外部网络请求 |

建议顺序：

1. 先做 credential provider contract plan，避免后续 runtime 在输入输出上临时扩张。
2. 再做 secret redaction plan，先锁定敏感字段禁止落点。
3. 然后做 configuration gate plan 与 audit semantics plan，分别确认启用条件和审计语义。
4. 最后按需要拆 credential lifecycle plan 与 provider / HIS adapter dependency boundary plan。

上述顺序不是开发许可，不得自动创建后续分支、commit 或 PR。
