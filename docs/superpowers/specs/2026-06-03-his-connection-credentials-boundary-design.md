## 2. 连接配置建议边界

连接配置应表达“哪个租户、以什么受控状态、准备连接哪个外部系统”，但不在普通配置 DTO、审计、日志或错误中暴露凭证明文、连接串、token、secret 或 raw payload。

### 2.1 建议字段

以下是未来字段和边界规划，不是当前数据库 schema，也不是本 PR 的 API 契约。

| 字段 | 建议语义 | 边界 |
| --- | --- | --- |
| `connectionId` | 内部连接配置 ID，由服务端生成。 | 不使用外部系统 ID 作为内部主键。 |
| `tenantId` | 连接归属租户。 | 只能来自服务端可信上下文、平台受控配置流程或后续可信连接上下文，不接受外部 payload、前端 body、query、header 或 localStorage。 |
| `connectionName` | 机构或平台可识别的连接名称。 | 安全短文本，不包含凭证明文、连接串、真实客户信息或完整外部响应。 |
| `sourceSystem` | 来源系统大类，例如 `his`、`institution_system`、`sftp_import`、`manual_import`、`other`。 | 稳定枚举或安全短文本，不携带厂商字段全集。 |
| `vendorType` / `systemType` | 厂商或系统类型，例如通用 HIS、院内自研系统、第三方导入网关。 | 只用于治理和适配策略，不代表已接入或已认证。 |
| `status` | 连接状态：`draft`、`active`、`paused`、`revoked`、`error`。 | 状态变更必须可审计，`revoked` 不应被普通恢复操作直接转回 `active`。 |
| `createdBy` / `updatedBy` | 操作者 ID。 | 记录安全操作者引用，不记录操作者凭证或会话内容。 |
| `createdAt` / `updatedAt` | 创建和更新时间。 | 用于治理和审计。 |
| `lastCheckedAt` | 最近一次健康检查或测试连接时间。 | 只记录时间，不记录外部响应体全文。 |
| `lastHealthStatus` | 最近健康状态，例如 `unknown`、`healthy`、`degraded`、`failed`。 | 只展示稳定状态和 reason code。 |

未来如需保存 endpoint、host、回调地址、SFTP 路径、mTLS 证书引用、专线信息或 IP 白名单，这些字段必须单独评估敏感等级、脱敏展示、审计禁止项和权限边界。本 PR 不定义这些字段、不建表、不加 API。

### 2.2 多连接和多租户边界

建议未来允许一个租户配置多个连接，但必须满足：

- 每个连接都有独立 `connectionId`。
- 每个连接明确绑定单一 `tenantId`。
- 同一租户的多个连接必须能区分 `sourceSystem`、`vendorType` / `systemType`、状态和凭证引用。
- 默认不共享凭证。
- 同一租户同时存在多个 active 连接时，必须单独评估事件路由、幂等键、冲突处理和人工复核。

建议未来允许同一个外部厂商或系统类型服务多个租户，但必须满足：

- 每个租户使用独立连接配置。
- 每个租户使用独立凭证或独立受控 credential reference。
- 外部系统的机构号、门店号、租户号只作为外部引用，不作为智美天工授权依据。
- 不允许用外部 payload 中的租户字段切换内部 `tenantId`。
- 如未来确需平台级共享专线或网关，必须单独规划平台级连接上下文、租户绑定、授权策略、审计和故障隔离。

### 2.3 删除、停用、恢复和撤销

连接配置生命周期建议区分以下动作：

| 动作 | 建议语义 | 边界 |
| --- | --- | --- |
| 停用 / 暂停 | 将 `active` 连接转为 `paused`，停止同步、测试连接之外的业务读取或事件处理。 | 保留配置和审计，凭证是否仍可用于测试需单独评估。 |
| 恢复 | 将 `paused` 或部分 `error` 连接恢复为 `active`。 | 必须重新检查权限、健康状态和凭证有效性。 |
| 撤销 | 将连接转为 `revoked`，表示连接被安全吊销。 | 应触发凭证撤销或失效流程；普通恢复不应跳过重新审批和凭证重建。 |
| 删除 | 删除或隐藏连接配置元数据。 | 未来应优先采用软删除或归档；删除前必须确认凭证已撤销、同步任务已停止、审计仍可追溯。 |

连接配置删除不等于凭证安全撤销。凭证撤销、外部厂商侧吊销、密钥销毁、同步任务停止和审计保留必须分别规划。

## 3. 凭证类型规划

真实凭证必须先进入单独的凭证加密与密钥管理 Plan Mode，不能混入真实 HIS adapter 实现。

### 3.1 候选凭证类型

| 类型 | 用途 | 主要风险 | 规划边界 |
| --- | --- | --- | --- |
| API Key | 外部系统固定密钥调用。 | 长期有效、泄露后可被重放。 | 需要最小权限、版本化、轮换、撤销和仅一次安全录入。 |
| Basic Auth | 用户名加密码。 | 密码复用和明文误展示风险高。 | 默认不推荐；如厂商只能支持，必须加密、遮罩、限制展示和强制轮换。 |
| OAuth token | access token / refresh token。 | token 生命周期、scope、刷新和撤销复杂。 | token 明文只在受控服务端流程短暂使用；scope、过期、刷新失败必须审计。 |
| 签名密钥 | 请求签名或回调验签。 | 签名密钥泄露会导致伪造请求。 | 入站验签密钥和出站调用凭证应分离；轮换需要双版本窗口。 |
| mTLS / 专线配置 | 证书、私钥、专线或网络隧道。 | 私钥、证书链和网络拓扑敏感。 | 只保存受控引用或加密材料；前端默认只展示状态和指纹摘要。 |
| IP 白名单 | 限制来源或出站 IP。 | IP 信息可能暴露网络边界。 | 作为网络安全配置记录，展示需最小化，变更必须审计。 |
| SFTP / 文件导入凭证 | 用户名、密码、私钥、路径。 | 文件内容和私钥泄露风险高。 | 文件导入必须另行规划文件类型、大小、预览、删除和 raw 文件不保存策略。 |
| 其他厂商专用凭证 | 厂商特定 token、机构号、签名盐、应用 ID 等。 | 语义不标准，容易误当普通配置展示。 | 按最高敏感等级处理，先分类再决定是否可展示遮罩元数据。 |

### 3.2 明文边界

凭证明文必须遵守以下不可越界规则：

- 凭证明文永不返回前端。
- 凭证明文永不写审计。
- 凭证明文永不写日志。
- 凭证明文永不进入错误信息。
- 凭证明文永不进入 PR、文档示例或 demo seed。
- 凭证明文永不进入普通 API DTO。
- 凭证明文永不进入测试截图、演示数据或 smoke fixtures。
- 凭证明文永不作为 `connectionName`、`vendorType`、`status`、`reason`、`mappingWarnings` 或审计 reason 文案。

文档示例只能使用占位符，例如 `<REDACTED>`、`***`，不得出现真实 token、secret、API key、basic auth、签名密钥、连接串或 `DATABASE_URL`。

### 3.3 展示边界

未来前端和审计最多可展示以下安全元数据：

- `connectionId`。
- `tenantId`，仅在平台受控视图中作为归属字段；机构端不应把它做成可切换维度。
- `connectionName`。
- `sourceSystem`。
- `vendorType` / `systemType`。
- `status`。
- `lastCheckedAt`。
- `lastHealthStatus`。
- 安全 reason code。
- 凭证类型，例如 `api_key`、`oauth_token`、`mtls`。
- 凭证是否已配置。
- 凭证版本号或安全指纹摘要。
- `expiresAt`、`rotatedAt`、`revokedAt` 等安全时间戳。

未来前端和审计不得展示：

- token。
- secret。
- API key。
- OAuth access token。
- OAuth refresh token。
- basic auth 用户名和密码组合。
- 签名密钥。
- 私钥。
- 连接串。
- 完整 endpoint 带敏感参数。
- raw HIS payload。
- SQL。
- stack。
- `DATABASE_URL`。

## 4. 凭证生命周期

以下生命周期只做规划，不实现。

### 4.1 创建

凭证创建应是一次受控录入流程：

- 明文只在服务端受控请求内短暂存在。
- 服务端应立即加密或交给密钥管理系统保存。
- 存储层只保留 credential reference、版本、类型、安全指纹摘要和时间戳。
- 创建成功只返回安全元数据，不返回明文。
- 创建失败只返回稳定错误类型，不返回输入内容或外部错误全文。

### 4.2 测试连接

测试连接必须后续单独进入 Plan Mode。本 PR 不实现测试连接。

未来测试连接建议：

- 只能由有权限的操作者触发。
- 只使用受控 credential reference。
- 不把凭证明文发回前端。
- 不展示外部响应体全文。
- 不展示连接串、token、secret、SQL、stack 或 `DATABASE_URL`。
- 只返回稳定 reason code，例如 `credential_invalid`、`network_unreachable`、`external_timeout`、`tls_handshake_failed`、`ip_not_allowlisted`、`vendor_scope_denied`。
- 成功 / 失败都写安全审计。

### 4.3 启用

连接启用前建议至少满足：

- 连接配置归属租户明确。
- 凭证已配置且未过期。
- 最近健康检查通过或由人工审批覆盖。
- 审计已记录启用操作。
- 后续同步 / Webhook / adapter 只能通过受控连接上下文使用该连接。

### 4.4 暂停

暂停用于临时停止连接：

- 停止业务同步和事件处理。
- 可保留配置和凭证引用。
- 暂停原因使用安全 reason code。
- 暂停不应删除审计历史。
- 恢复前应重新评估健康状态和权限。

### 4.5 轮换

凭证轮换建议支持版本化：

- 新凭证进入 `pending` 或轮换窗口。
- 旧凭证在受控时间窗内保留。
- 切换后旧凭证撤销或失效。
- 轮换失败不能暴露新旧凭证明文。
- 轮换全过程写审计，只记录版本、时间、操作者和 reason code。
- 高风险轮换是否需要双人复核，后续单独评估。

### 4.6 过期

凭证过期应导致连接降级或暂停：

- 记录 `credential_expired` 安全 reason code。
- 前端展示稳定状态，不展示 token 内容。
- 不继续自动同步，除非后续明确允许只读健康检查。
- 过期后恢复必须通过凭证更新或轮换。

### 4.7 撤销

撤销表示凭证不应再被使用：

- 系统内 credential reference 标记为 revoked。
- 如外部厂商支持，应同步完成厂商侧吊销。
- 撤销后连接状态应进入 `revoked` 或受控 `paused`。
- 撤销不可通过普通恢复跳过审批。
- 撤销审计不得记录凭证明文。

### 4.8 删除

删除应谨慎区分“删除配置”和“销毁凭证”：

- 删除连接配置前应先暂停同步并撤销凭证。
- 审计记录保留，支持追溯谁在何时删除或归档。
- 删除不应导致历史审计丢失。
- 如未来支持硬删除，必须单独评估合规保留、密钥销毁、备份清理和审计可追溯性。

### 4.9 连接失败降级

连接失败应按安全 reason code 降级：

- 网络失败：`network_unreachable`、`external_timeout`。
- 凭证失败：`credential_invalid`、`credential_expired`。
- 权限失败：`vendor_scope_denied`。
- 验签失败：`signature_invalid`、`replay_detected`。
- mTLS / 专线失败：`tls_handshake_failed`、`private_link_unavailable`。
- 白名单失败：`ip_not_allowlisted`。
- 外部系统异常：`vendor_error_degraded`。

降级后不应自动创建治疗摘要、随访任务或触达客户。需要人工判断的情况应进入后续人工复核 / 标准事件预览规划。

### 4.10 凭证泄露应急处理

未来凭证泄露应急至少需要：

- 立即暂停或撤销相关连接。
- 触发凭证轮换或厂商侧吊销。
- 查询相关审计事件和同步任务。
- 评估是否有跨租户影响。
- 标记安全 incident reason code。
- 通知有权限的安全 / 平台负责人。
- 控制排障信息保留时间。
- 避免在 incident 文档、PR、聊天记录和日志中粘贴凭证明文。

本 PR 不创建 incident 流程，只记录必须单独规划。

## 5. 权限与可见性

当前 PR 不改权限、认证或租户隔离。以下是未来权限边界建议。

| 操作 | 建议角色 | 边界 |
| --- | --- | --- |
| 创建连接配置 | 机构管理员可为本租户发起；平台管理员可在受控流程中为租户配置。 | `tenantId` 由服务端上下文或平台受控选择确定，不接受外部 payload。 |
| 查看连接状态 | 机构管理员查看本租户连接状态；平台管理员 / 安全审计员查看安全元数据；平台运营默认只看聚合健康。 | 不展示凭证明文、连接串、raw payload 或外部响应体。 |
| 更新连接元数据 | 机构管理员可更新本租户低风险元数据；平台管理员可更新受控平台配置。 | 厂商类型、状态和 endpoint 类字段需按敏感等级评估。 |
| 添加 / 更新凭证 | 默认只允许机构管理员或平台管理员在受控流程中录入；是否需要审批后续评估。 | 明文只允许一次性提交给服务端，不返回前端。 |
| 测试连接 | 默认仅机构管理员、平台管理员或被授权的安全 / 集成角色可触发。 | 返回稳定 reason code，不返回外部响应体全文。 |
| 停用 / 暂停连接 | 机构管理员可暂停本租户连接；平台管理员可因安全或交付原因暂停。 | 必须写审计。 |
| 撤销连接 | 平台管理员或具备授权的机构管理员；高风险场景建议平台 / 安全复核。 | 必须写审计并进入凭证撤销流程。 |
| 删除连接 | 后续单独评估，默认高风险。 | 建议先软删除 / 归档，保留审计可追溯。 |

平台管理员和机构管理员边界：

- 机构管理员只能管理本租户连接配置和状态。
- 机构管理员不能看到凭证明文。
- 机构人员不能看到凭证明文。
- 平台人员默认不能看到凭证明文。
- 平台管理员可查看安全元数据和状态，但不应读取客户业务明细、raw HIS payload 或凭证明文。
- 安全审计员可查看安全审计和 reason code，不应轮换凭证或修改租户状态。
- 平台运营默认只查看聚合健康，不应查看凭证元数据细节。

双人复核或高危操作审计：

- 凭证创建、轮换、撤销、连接恢复、删除、共享专线绑定、厂商侧权限升级等操作是否需要双人复核，后续必须单独评估。
- 当前只规划需要评估，不新增审批流或权限模型。

## 6. 审计事件规划

未来连接配置和凭证管理必须写安全审计。审计只记录安全元数据，不记录明文和 raw payload。

### 6.1 建议审计事件

- 创建连接配置。
- 更新连接元数据。
- 添加凭证。
- 更新凭证。
- 测试连接成功。
- 测试连接失败。
- 启用连接。
- 暂停连接。
- 恢复连接。
- 撤销连接。
- 删除连接。
- 凭证轮换。
- 凭证过期。
- 连接异常。
- 外部系统错误降级。
- 凭证泄露应急处理。

### 6.2 审计允许记录

审计 payload 只能记录安全元数据：

- `tenantId`。
- `connectionId`。
- `sourceSystem`。
- `vendorType` / `systemType`。
- `status`。
- `lastHealthStatus`。
- 安全 reason code。
- 操作者。
- 操作者角色。
- 时间。
- 连接配置版本号或凭证版本号。
- 安全 credential reference 或安全指纹摘要。

### 6.3 审计禁止记录

审计中禁止记录：

- 凭证明文。
- token。
- secret。
- API key。
- OAuth token。
- OAuth refresh token。

- 签名密钥。
- 私钥。
- 连接串。

- 完整请求体。

## 7. 错误降级和展示边界

测试连接、健康检查、同步任务和 adapter 错误都必须使用稳定错误类型或 reason code，不展示敏感详情。

### 7.1 前端可展示

前端可展示：

- 连接状态：草稿、启用、暂停、撤销、异常。
- 健康状态：未知、健康、降级、失败。
- 稳定错误类型：凭证失效、网络不可达、外部系统超时、白名单不匹配、证书握手失败、厂商权限不足。
- 最近检查时间。
- 建议人工处理动作，例如“联系平台管理员”或“更新凭证后重试”。

### 7.2 前端禁止展示

测试连接失败或同步失败时，不能展示：

- 外部响应体全文。
- 凭证明文。
- 连接串。
- token。
- secret。
- API key。
- OAuth token。
- basic auth。
- 签名密钥。
- 私钥。
- raw HIS payload。
- 完整请求体。
- 完整响应体。
- SQL。
- stack。
- `DATABASE_URL`。

### 7.3 排障细节

详细错误如需用于排障，必须单独评估：

- 脱敏规则。
- 可见权限。
- 保留时间。
- 审计记录。
- 删除策略。
- 是否允许平台人员查看。
- 是否允许机构人员查看。
- 是否涉及真实客户数据或医疗隐私。

本 PR 不建立排障详情存储或展示能力。

## 8. 和后续真实 HIS adapter 的关系

连接配置与凭证边界是 HIS adapter 的前置条件。

未完成以下规划前，不应进入真实 HIS adapter：

- 连接配置与凭证边界。
- 连接配置 schema / API Plan Mode。
- 凭证加密与密钥管理 Plan Mode。
- 连接健康检查 / 测试连接 Plan Mode。
- Webhook / 同步任务 Plan Mode。
- 患者身份匹配 Plan Mode。
- 人工复核 / 标准事件预览 Plan Mode。

adapter 后续必须遵守：

- adapter 只能使用受控连接上下文。
- adapter 使用的 `tenantId` 只能来自连接上下文或服务端可信上下文。
- adapter 不应绕过 mapper 直接写治疗摘要、随访任务或运营分析。
- adapter 不应保存 raw HIS payload。
- adapter 不应把 raw HIS payload、完整治疗正文、完整病历正文、咨询全文、图片 / 文件原文传给业务下游。
- adapter 不应自动认定患者身份匹配成功。
- adapter 不应自动创建治疗摘要。
- adapter 不应自动创建随访任务。
- adapter 不应自动触达客户。

未来真实外部系统接入 PoC 必须另行批准，且必须明确具体系统、测试租户、测试数据、凭证管理、回滚策略和安全审计。

## 11. 前置结论

连接配置与凭证边界是未来真实 HIS / 机构系统接入前必须先收口的安全边界。

当前结论：

- 连接配置可以先作为受控元数据规划，但不能把凭证明文、连接串或 raw HIS payload 混入普通配置展示。
- `tenantId` 必须来自服务端可信上下文或连接上下文，不能来自外部系统 payload。
- 凭证管理必须独立于 adapter 业务实现，先解决加密、轮换、撤销、展示和审计边界。
- 测试连接和健康检查必须只返回稳定 reason code，不展示外部响应体全文或敏感详情。
- 真实 HIS adapter 只能在连接配置、凭证、健康检查、Webhook / 同步、身份匹配和人工复核等前置规划完成后再进入。

越界风险当前可控，因为本 PR 只做文档规划；真正风险会出现在后续任何试图同时保存真实凭证、接真实系统、保存 raw payload、做患者身份匹配或自动创建业务对象的 PR。
