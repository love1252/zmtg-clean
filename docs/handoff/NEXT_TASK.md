# 下一任务

## 当前任务

执行第十八阶段：API 调用方与兼容策略基线。

## 目标

在不修改或移动 API 文件的前提下，对当前 API 版本治理候选建立统一的调用方、兼容期、退役条件和回退要求，为第十九阶段选择单一低风险试点提供依据。

## 当前权威数据

- 全仓 `route.ts`：145 个。
- 版本化路由：56 个。
- 非版本化路由：89 个。
- 路由族：144 个。
- 精确版本化／非版本化重叠族：1 个。
- 主 `API_VERSION_REVIEW`：146 条。
- 辅助治理标记：2 条。
- 迁移矩阵总行数：1509。

## 必须输出

1. API 调用方与兼容策略说明文档。
2. 逐候选机器可读清单。
3. 调用方证据类型：
   - 运行时代码；
   - 页面或组件；
   - 测试；
   - 脚本；
   - 文档或外部未知调用。
4. 兼容策略分类：
   - 保持当前；
   - 需要兼容入口；
   - 需要客户端迁移；
   - 需要观测后退役；
   - 阻断，等待人工决策。
5. 回退条件、退役条件和最小观测要求。
6. 第十九阶段只能推荐一个低风险试点，不得实施迁移。

## 验收重点

1. 145 个路由范围不得缩小。
2. 146 条主治理候选和 2 条辅助标记必须保持可追溯。
3. 不得把辅助标记解释为允许迁移、删除、代理或重定向。
4. 不得修改 `file-migration-matrix.csv`。
5. 不得修改或移动任何 API 文件。
6. 不得改变运行时行为。
7. 不得连接数据库或真实外部服务。

## 后续阶段

第十九阶段根据第十八阶段证据，选择一个单一、低风险、可回退的 API 路由族，只形成试点迁移设计，不直接批量实施。
