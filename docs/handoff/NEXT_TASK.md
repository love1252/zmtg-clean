# 下一任务

## 当前任务

执行第二十九阶段：下一模块选择与审计启动决策。

## 审计范围

只读扫描 `src/modules/` 下除以下已闭环模块外的一级模块：

- `src/modules/institution/`
- `src/modules/open-platform/`

## 必须输出

1. 候选模块清单；
2. 每个候选模块的 TypeScript 文件数；
3. 每个候选模块的跨模块入向和出向依赖面；
4. 每个候选模块的运行时边界面；
5. 每个候选模块的测试文件数和测试覆盖入口；
6. 唯一下一模块；
7. 下一模块职责与依赖审计的精确范围、禁止范围和回退边界。

## 默认边界

- 本阶段 audit-only；
- 不修改或移动任何 `src/` 文件；
- 不修改 API；
- 不修改 `file-migration-matrix.csv`；
- 不修改 Schema、Migration、package 或锁文件；
- 不连接真实数据库或外部服务；
- 不读取或输出真实凭证；
- 不改变权限、租户隔离、错误响应或真实渠道行为；
- 不自动实施下一模块源码试点。

## 选择规则

唯一下一模块必须基于机器证据选择，至少考虑：

1. 文件规模；
2. 领域边界清晰度；
3. 跨模块依赖复杂度；
4. 运行时边界比例；
5. 测试覆盖面；
6. 是否已有稳定入口或契约层；
7. 是否与已闭环模块形成高风险耦合。

不得仅按目录名称主观选择。

## 验证

1. `git diff --check`
2. 候选模块集合与实际一级模块一致
3. 每个候选模块均有机器可读统计
4. 唯一下一模块选择规则可追溯
5. 无源码、API、迁移矩阵或运行时配置修改
6. `pnpm typecheck`
7. `pnpm lint`
8. 代表性测试
9. `pnpm build`

## 退出条件

- 所有候选模块均有统计；
- 唯一下一模块已选定；
- 下一模块审计范围和边界已明确；
- 后续模块审计必须单独授权。
