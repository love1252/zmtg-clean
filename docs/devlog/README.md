# Devlog 命名与滚动日志边界

## 目标

devlog 用于记录开发阶段、PR 收尾、验证结果和后续边界。文件名应帮助读者判断记录范围，避免把单日文件长期当作所有后续 Phase 的默认追加位置。

## 命名规则

日期型 devlog 应只记录对应日期或短周期内容：

```text
docs/devlog/YYYY-MM-DD.md
```

阶段型 devlog 可用于跨日期但边界清晰的阶段记录：

```text
docs/devlog/phase-xx-topic.md
```

示例：

```text
docs/devlog/2026-06-03.md
docs/devlog/phase-22-customer-timeline-review.md
```

## 滚动日志边界

- 不再把长期 Phase / PR 记录持续追加到旧日期文件。
- 后续 Codex 写 devlog 时，优先新建当前日期文件或阶段命名文件。
- 不再默认追加到 `docs/devlog/2026-05-31.md`。
- 如果某个文件因历史原因作为滚动日志使用，必须在文件顶部明确说明：
  - 文件是历史滚动开发日志。
  - 文件最初创建日期。
  - 后续持续记录了多个 Phase / PR。
  - 文件名保留是为了避免破坏历史引用。
  - 后续新阶段应优先使用当前日期或阶段命名文件。

## 历史文件

`docs/devlog/2026-05-31.md` 是历史滚动开发日志。该文件不重命名、不拆分，也不迁移历史内容，以保留已有引用和审阅上下文。

后续如需整理历史 devlog，应单独评估迁移方案，不在普通功能或文档收尾 PR 中顺手拆分。

## 边界

devlog 命名规范只影响文档记录方式，不代表进入业务实现。

本规范不要求：

- 重命名旧文件。
- 迁移大量历史内容。
- 拆分历史 PR 记录。
- 修改代码、测试、API、数据库 schema、migration、权限、认证、租户隔离或 demo seed 数据。
