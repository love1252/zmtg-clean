# V0.8 目标 4F-PLAN：单机构真实通道 proof 执行清单与人工确认门槛

## 1. 文档目的

本文用于在任何真实通道 proof 开始前，明确单机构 proof 的执行条件、人工确认门槛、材料准备边界、安全开关、回滚方案、验收口径和停止条件。

本文只做 docs-only 规划，不开发功能，不修改代码，不新增 API，不新增 UI，不新增 schema / migration，不接真实企业微信，不接真实微信，不接短信、HIS 或 webhook，不配置 secret、token 或 API key，不写真实 callback，不真实发送，不真实出网，不同步真实客户、外部联系人或聊天记录，不接入会话内容存档，也不开始真实 proof 实现。

本文的核心结论是：当前仍不能直接接真实企业微信；真实 proof 必须先由用户人工确认；默认不打开真实发送；真实发送必须是后续独立授权任务。

## 3. 已完成能力回顾：4A / 4B / 4C / 4D / 4E

4A 已完成需求方向对齐：用户需要的是机构端 AI 会话工作台和客户运营能力，不是企业微信登录，也不是单纯发消息按钮。青焱参考能力可用于产品拆解，但扫码托管、端口、机器编号、uip、群发、主加触达和聊天记录同步必须后置风险评估。

4B 已完成 AI 会话工作台模拟版：包含账号列、会话列表、聊天窗口、AI / 档案面板、推荐回复、人工接管、风险预警、推荐项目、用户画像、低敏时间线和低敏统计。页面明确当前仅模拟，不接真实企业微信 / 微信，不接短信、HIS、webhook，不真实发送，不真实出网。

4C 已完成自动回复与自动随访策略模拟版：定义 L0 AI 推荐、L1 AI 草稿 + 人工确认、L2 低风险自动回复、L3 受控自动随访、L4 营销自动化 / 群发 / 加好友 / 裂变。策略已覆盖退订、频控、授权、安全开关、`allowRealSend=false`、`externalChannelEnabled=false`、低敏输出、audit 和阻断原因。

4D 已完成客户触达通道路线统一核验：官方企业微信自建应用、第三方应用、服务商路线更适合长期合规交付；账号托管路线、扫码、端口、机器编号、uip 风险高，必须单独评估；会话内容存档必须后置。

4E 已完成真实通道验证前置能力与安全门禁：新增 real-channel preflight domain / API / 页面模块，明确 `mock_ready` 只代表可以进入模拟 proof 前置流程，不代表真实通道打开；敏感配置输入、账号托管路线、未人工确认、安全开关、授权、退订、频控、高风险和 4C 阻断策略都会进入门禁。

## 4. 为什么 4F 不能直接开始真实开发

4F 不能直接开始真实开发，原因包括：

- 用户尚未人工确认测试机构、测试账号、测试企业微信环境、授权范围和责任人。
- 当前仓库禁止写入任何真实 secret / token / callback / webhook 信息。
- 当前系统默认仍为 `allowRealSend=false`、`externalChannelEnabled=false`、`realSendAllowed=false`。
- `mock_ready` 只表示模拟 proof 前置条件可进入，不表示真实通道已经打开。
- 真实出网、真实回调、真实发送、真实客户同步都涉及额外授权、审计、回滚和数据安全责任。
- 会话内容存档、真实自动回复、真实群发、真实自动加好友的风险等级高，不能和单机构官方路线 proof 混做。
- 账号托管路线不能和官方路线混在一起做，否则责任边界、技术边界和合规边界都会混乱。

## 5. proof 定义：本阶段只验证什么

本阶段 proof 只验证“是否具备进入后续真实实现任务的前置条件”，不是验证真实发送成功。

本阶段只验证：

- 单机构是否可作为受控测试对象。
- 单官方通道路线是否被用户确认。
- 测试企业微信环境或测试账号是否准备完毕。
- 授权状态占位是否可低敏记录。
- 低敏客户映射占位是否可定义。
- preflight API / 页面门禁是否可解释阻断原因。
- 人工确认后是否可得到模拟 proof eligibility。
- `allowRealSend=false`、`externalChannelEnabled=false`、`realSendAllowed=false` 是否仍为默认值。
- MessageDelivery、timeline、audit、dashboard 的低敏验收口径是否明确。
- emergency stop 和回滚责任是否明确。

## 6. proof 不验证什么

本阶段 proof 不验证：

- 真实企业微信已接入。
- 真实微信已接入。
- 真实短信、HIS 或 webhook 已接入。
- 真实 secret、token、callback 或 webhook 已配置。
- 真实消息发送成功。
- 真实客户或外部联系人已同步。
- 真实聊天记录已同步。
- 会话内容存档已接入。
- 真实自动回复、真实随访、真实群发或真实自动加好友。
- 账号托管、扫码、端口、机器编号、uip 或第三方托管服务商可用。
- 聊天内容进入 AI。
- 多机构灰度或生产上线。

## 7. 单机构选择条件

单机构必须同时满足：

- 机构已明确同意参与受控 proof。
- 机构管理员明确知晓 proof 范围和不能宣称的能力。
- 机构能提供测试企业微信环境或测试账号，但真实标识不得写入仓库。
- 机构能指定测试员工、测试客户和回滚责任人。
- 机构能接受单机构、单通道、单员工、单客户、单条消息的最小范围。
- 机构能确认不误触达真实客户。
- 机构能确认 proof 失败时立即回退到模拟版。
- 机构能确认日志只保留低敏字段。

如无法确认以上任一条件，必须停留在模拟版。

## 8. 通道路线选择条件

第一阶段只能选择一个通道路线，不允许多个路线并行。

推荐顺序：

1. 官方企业微信自建应用路线：适合单机构 proof。
2. 官方企业微信第三方应用路线：适合长期 SaaS，但第一阶段只做契约和准备。
3. 官方企业微信服务商路线：适合长期多机构交付，但不建议直接进入 proof。
4. 账号托管路线：不进入本 proof，只做单独风险评估。

通道路线选择必须满足：

- 用户明确选择官方路线或明确要求另开账号托管风险评估。
- 官方路线不得与账号托管路线混做。
- 真实 proof 初始阶段只能选择一个机构、一个通道、一个测试账号或测试企业微信环境。
- 未完成用户人工确认前，不得进入任何真实实现。

## 9. 企业微信官方路线人工确认清单

进入官方企业微信路线前，用户必须人工确认：

1. 选择哪一家测试机构。
2. 机构是否明确授权参与 proof。
3. 选择自建应用、第三方应用还是服务商路线。
4. 是否只做单机构、单通道、单员工、单客户、单条消息。
5. 是否具备测试企业微信环境或测试账号。
6. 是否具备测试员工。
7. 是否具备不会误触达真实客户的测试客户。
8. 是否允许配置测试回调地址。
9. 是否允许在本地或测试环境配置 secret。
10. secret 由谁保管。
11. 是否允许接收测试回调。
12. 是否允许读取外部联系人低敏信息。
13. 是否允许建立低敏客户映射。
14. 是否允许发送测试消息。
15. 测试消息发送给谁。
16. 发送前是否必须人工二次确认。
17. 出现异常由谁执行 emergency stop。
18. 出现异常由谁负责回滚。
19. 是否允许保留日志。
20. 日志允许保留哪些低敏字段。
21. 哪些字段必须脱敏或禁止保存。
22. proof 成功后是否进入真实实现任务。
23. proof 失败后是否回退到模拟版。

## 10. 账号托管路线人工确认清单

账号托管路线不进入本 proof。如果用户希望评估账号托管路线，必须另开风险评估任务，并至少确认：

1. 是否明确选择账号托管而不是官方企业微信路线。
2. 是否涉及扫码登录。
3. 是否涉及端口购买、端口续费或端口托管。
4. 是否涉及机器编号。
5. 是否涉及 uip 或类似外部程序。
6. 是否涉及第三方托管服务商。
7. 是否涉及员工个人账号、平台号、助手号或扫码号。
8. 是否涉及账号密码、登录态或设备绑定。
9. 是否涉及掉线、封号、限流或风控责任。
10. 是否涉及自动群发、自动加好友、主加触达或裂变。
11. 是否涉及聊天记录全量查看。
12. 是否有供应商安全、退出和数据删除方案。
13. 是否能接受高风险等级和单独审批流程。

结论：账号托管路线不能和官方路线混在一起做。

## 13. secret / token / callback / webhook 管理原则

secret / token / callback / webhook 必须遵守：

- 本任务不读取、不配置、不输出任何 secret。
- 真实值不得写入仓库。
- 真实值不得写入文档。
- 真实值不得写入测试 fixture。
- 真实值不得写入 PR body。
- 真实值只能在后续独立授权任务中，通过受控测试环境配置。
- 配置前必须明确保管人、轮换策略、撤销策略、最小权限、日志脱敏和泄露应急方案。
- callback / webhook 必须单独设计验签、重放防护、低敏日志、错误处理和关闭开关。

## 14. 安全开关与回滚条件

必须保留以下安全开关：

- emergency stop 默认可随时阻断。
- 租户级真实通道开关默认关闭。
- 机构级真实通道开关默认关闭。
- 企业微信真实发送开关默认关闭。
- 短信真实发送开关默认关闭。
- webhook 开关默认关闭。
- `allowRealSend=false` 默认不变。
- `externalChannelEnabled=false` 默认不变。
- `realSendAllowed=false` 默认不变。

触发以下任一情况必须回滚：

- 用户未完成全部人工确认。
- 测试机构、员工、客户或消息对象不明确。
- 发现任何真实 secret 写入仓库风险。
- preflight 返回 blocked 状态。
- 出现误触达真实客户风险。
- 出现真实出网未授权风险。
- 出现客户隐私字段泄露风险。
- 出现回调验签、日志脱敏或权限边界不清。
- 出现账号托管路线混入官方路线。
- 出现真实自动回复、群发、自动加好友或会话内容存档越界。

## 15. allowRealSend / externalChannelEnabled / realSendAllowed 的默认策略

默认策略必须是：

- `allowRealSend=false`。
- `externalChannelEnabled=false`。
- `realSendAllowed=false`。

即使 preflight 返回 `mock_ready`，也只表示可以进入模拟 proof 前置流程，不代表真实通道打开，不代表真实 proof 已开始，不代表真实发送允许。

真实发送必须是后续独立授权任务。任何把 `allowRealSend`、`externalChannelEnabled` 或 `realSendAllowed` 改为 true 的动作，都必须另开任务、单独审批、单独验收。

## 16. 4C 自动化等级在 proof 中的使用边界

4C 自动化等级在 proof 中必须按以下方式使用：

- L0 AI 推荐：允许作为内部参考，不发送。
- L1 AI 草稿 + 人工确认：允许作为 proof 的最高默认使用边界，仍不真实发送。
- L2 低风险自动回复：本 proof 不启用真实自动回复，只允许保留模拟策略结论。
- L3 受控自动随访：本 proof 不启用真实自动随访，只允许验证门禁和人工确认口径。
- L4 营销自动化 / 群发 / 加好友 / 裂变：继续阻断，不进入 proof。

所有客户可见内容必须经过人工确认。医疗建议、投诉、价格承诺、术后异常、隐私字段必须转人工，不得自动发送。

## 17. 4E preflight 通过条件

4E preflight 只允许证明模拟 proof eligibility。进入下一步前必须满足：

- 通道路线是官方企业微信路线。
- 不是账号托管路线。
- 没有敏感配置输入。
- 没有真实 secret / token / callback / webhook 值。
- 有人工确认。
- 有客户授权。
- 客户未 opt-out。
- frequency cap 通过。
- 没有高风险标签。
- 4C 策略不是 L4，不是 `blocked_*`。
- emergency stop 没有阻断 proof。
- `allowRealSend=false`。
- `externalChannelEnabled=false`。
- `realSendAllowed=false`。

`mock_ready` 只代表满足模拟 proof 前置条件，不代表真实通道打开。

## 19. 单机构 proof 停止条件

出现以下任一情况，proof 必须停止：

- 用户未明确授权。
- 测试机构不明确。
- 测试企业微信环境或测试账号不明确。
- 测试员工、测试客户或测试消息对象不明确。
- 发现真实 secret / token / callback 信息可能进入仓库。

- 发现 L4、群发、自动加好友、营销裂变或真实自动回复需求混入。
- preflight 返回阻断状态。
- emergency stop 开启。
- 回滚责任人不明确。
- 日志脱敏和保留策略不明确。

## 21. 回滚方案

回滚方案必须包括：

- 保持 `allowRealSend=false`。
- 保持 `externalChannelEnabled=false`。
- 保持 `realSendAllowed=false`。
- emergency stop 可立即阻断。
- 删除或停用测试环境中的临时配置。
- 撤销测试授权或停用测试应用可见范围。
- 停止接收测试回调。
- 停止任何真实出网任务。
- 不保留敏感日志。
- 只保留低敏 audit / timeline / dashboard 结果。
- 如果 proof 失败，回退到 AI 会话工作台模拟版、4C 策略模拟版和 4E preflight 门禁。

## 23. 需要用户人工确认的问题清单

## 25. 阶段结论

V0.8 目标 4F-PLAN 的结论是：

- 当前仍不能直接接真实企业微信。
- 当前只能完成真实 proof 前置清单和人工确认门槛。
- 真实 proof 必须先由用户人工确认。
- proof 初始阶段只能选择一个机构、一个通道、一个测试账号或测试企业微信环境。
- 默认不打开真实发送。
- `allowRealSend=false` 必须仍是默认值。
- `externalChannelEnabled=false` 必须仍是默认值。
- `realSendAllowed=false` 必须仍是默认值。
- `mock_ready` 只代表可以进入模拟 proof 前置流程，不代表真实通道打开。
- 真实发送必须是后续独立授权任务。
- 真实自动回复、真实群发、真实自动加好友必须后置。
- 会话内容存档必须后置。
- 账号托管路线不能和官方路线混在一起做。
- 任何 secret / token / `corpId` / `encodingAESKey` / callback token / webhook secret 不能写入文档、代码、测试或 PR body。

在用户完成本文人工确认清单之前，系统必须继续停留在模拟版和 preflight 门禁状态，不应开始真实 proof、真实出网或真实发送。
