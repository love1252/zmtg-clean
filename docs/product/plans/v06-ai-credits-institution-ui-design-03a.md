# V0.6-AI-CREDITS-INSTITUTION-03A：机构端 AI 服务使用 UI 设计与接入边界确认

## 1. 背景与页面定位

平台端 AI 用量 V0.6 已完成运营侧只读分析能力，机构端 AI 用量可见范围设计也已完成。当前已合并机构端只读 API：`GET /api/institution/ai-service-usage`，该 API 只返回面向机构的低敏 DTO，不返回平台内部的模型、供应商、Token、成本、原始问答或客户敏感内容。

本轮只确认机构端 AI 服务使用 UI 的产品口径和接入边界，不开发 UI，不改 API，不改数据库，不进入正式实现。

机构端页面面向机构用户，表达重点应是“AI 服务使用 / AI 服务额度”，用于帮助机构理解本机构在当前时间范围内使用了哪些 AI 服务、使用次数和额度消耗情况。页面不应表现为平台内部的“AI 用量与费用”，也不展示平台运营侧的模型厂商、内部计量、成本或结算口径。

## 2. 建议页面名称

建议页面名称优先使用：

1. `AI 服务使用`
2. `AI 服务额度`

如果页面首版更偏运营查看，推荐使用 `AI 服务使用`。如果后续套餐额度联动完成，并能展示套餐额度、已用额度、剩余额度和告警状态，再考虑将入口或二级标题调整为 `AI 服务额度`。

## 3. 建议入口

建议入口可以放在以下位置之一：

1. 机构端设置 / 套餐权益：适合将 AI 服务使用视为套餐能力的一部分。
2. 机构工作台 AI 服务模块：适合将 AI 服务使用视为日常运营能力的一部分。

当前仓库中机构端已有面向机构的工作台和知识库相关入口，后续实现时应遵循既有机构端导航约定。首版建议把入口放在机构端“套餐权益 / 服务权益”附近，理由是当前 API 的 `quota.isLinked=false` 已明确套餐额度暂未接入，UI 需要给机构管理员一个只读查看入口，而不是在业务工作流里制造可操作预期。

本轮不实现导航接入，不新增菜单，不修改机构端 UI。

## 4. API 数据源与接入边界

机构端 UI 只能使用：

`GET /api/institution/ai-service-usage`

接入边界：

1. 不直接读取平台端 `GET /api/open-platform/ai-usage-credits`。
2. 不复用平台端 DTO。
3. 不在前端传入 `tenantId` 作为查询依据。
4. 如果 URL query 中出现 `tenantId`，也不能覆盖登录态中的租户和机构范围。
5. 所有机构端数据范围必须由服务端基于登录态解析。
6. 套餐额度未接入时，UI 只展示 API 返回的 `quota.isLinked=false` 状态，不伪造剩余额度。

当前 API 已提供：

1. `summary`
2. `trend`
3. `serviceProjects`
4. `quota`
5. `notes`
6. `period`

机构端 UI 只消费这些低敏字段。

## 5. 首屏卡片

首屏建议使用 3 到 4 个紧凑指标卡：

1. 本月 AI 服务使用次数：来自 `summary.totalUsageCount`。
2. AI 服务额度使用量：来自 `summary.aiServiceUnitsUsed`。
3. 成功率：来自 `summary.successRate`。
4. 拒绝 / 失败摘要：可用 `summary.rejectedCount`、`summary.failedCount` 做低敏说明。

如后续接入套餐额度，可再增加“套餐额度剩余”或“额度使用率”。在当前 `quota.isLinked=false` 的阶段，不显示“剩余额度”，不展示“已扣减套餐额度”，不暗示真实套餐扣减已经完成。

卡片文案建议：

1. `AI 服务使用次数`
2. `AI 服务额度使用量`
3. `成功率`
4. `未完成调用`

避免出现 `AI Credits`、`Token`、`成本`、`费用`、`模型单价` 等平台内部或财务口径。

## 6. 趋势区域

趋势区域用于展示机构端低敏服务使用变化。建议支持以下时间范围：

1. 今日
2. 近 7 天
3. 本月
4. 上月
5. 自定义时间范围

首版建议默认先做 `近 7 天` / `本月` 两个高频范围，并保留 API 对其他范围的支持。UI 可以使用轻量折线、柱状或列表式趋势，重点表达“使用次数”和“AI 服务额度使用量”，不展示 Token，不展示平台内部计量细节。

趋势区域建议展示：

1. 日期
2. 使用次数
3. AI 服务额度使用量

## 7. 服务项目排行

服务项目排行来自 `serviceProjects`，用于展示机构端可理解的服务项目消耗结构。

可展示的服务项目包括：

1. AI 问答
2. 知识库问答
3. 智能随访相关服务项目，仅当已有 usage record 中出现时展示
4. 未归因服务
5. unknown

服务项目排行建议字段：

1. 服务项目名称：`serviceName`
2. 服务分类：`serviceCategory`
3. 使用次数：`usageCount`
4. 成功率：`successRate`
5. AI 服务额度使用量：`aiServiceUnitsUsed`
6. 占比：`sharePercent`

`unknown` 可以展示为“未识别分类”，但应保留必要的低敏提示，说明这是历史或未归因数据。`未归因服务` 可以直接展示，并通过 helper 文案说明“部分历史记录暂未标记服务项目”。

## 8. 明细是否展示

第一版不建议做明细表。原因：

1. 当前 API 已聚合为机构端低敏 DTO。
2. 明细容易诱导用户期待查看原始问答、客户、模型或费用。
3. 机构端首版目标是运营概览，不是审计明细。

如果后续确实要做明细，必须单独设计 API 和低敏 DTO，且只能展示：

1. 时间
2. 服务项目
3. 状态
4. AI 服务额度

明细不得展示原始问题、回答、prompt、answer、rawResponse、客户姓名、手机号、身份证、病历详情、治疗摘要原文或随访建议原文。

## 9. 空状态

建议空状态文案：

1. `暂无 AI 服务使用记录`
2. `本月暂无使用记录`
3. `套餐额度暂未接入`

当 `summary.totalUsageCount=0` 且 `serviceProjects=[]` 时，页面应保持完整结构，展示空状态，而不是显示错误。

当 `quota.isLinked=false` 时，展示“套餐额度暂未接入”或“当前仅展示 AI 服务使用情况，套餐额度联动后置”，不要展示剩余额度。

## 10. 错误状态

错误状态建议文案：

`AI 服务使用数据暂时不可用`

错误状态不得展示：

1. SQL
2. DB
3. stack trace
4. 数据库连接信息
5. 内部错误对象
6. request cookie
7. token

UI 可提供“重试”按钮，但不应提供导出、补算、刷新计费或同步数据等高风险操作。

## 11. UI 低敏边界

机构端 UI 不得出现：

1. `provider`
2. `model`
3. `Token`
4. `totalTokens`
5. AI Credits 内部折算规则
6. RMB
7. `¥`
8. 真实成本
9. `prompt`
10. `answer`
11. `rawResponse`
12. `metadata` 原文
13. `meteringDetails` 原文
14. `apiKey`
15. `baseUrl`
16. credential
17. 客户姓名
18. 手机号
19. 身份证
20. 病历详情
21. 治疗摘要原文
22. 随访建议原文

机构端允许展示：

1. 服务项目名称
2. 服务分类
3. 使用次数
4. 成功率
5. AI 服务额度使用量
6. 占比
7. 日期趋势
8. 低敏空状态和错误状态

## 12. 智能随访口径

智能随访相关口径必须谨慎表达：

1. AI 生成随访建议：后续可以作为服务项目展示，但必须有对应 usage record 和 service project 归因。
2. AI 生成随访任务草稿：后续可以作为服务项目展示，但必须由写入口径显式标记。
3. 人工创建随访任务：不计入 AI 服务使用。
4. 当前 UI 不能宣称自动随访统计已完成。
5. 当前 UI 只能展示已有 usage record 中已经归因的智能随访相关服务项目。

如果服务项目中没有智能随访记录，UI 不应硬编码展示“智能随访已使用 0 次”来暗示能力已接入。

## 13. 权限与角色

机构端 AI 服务使用页面是否对所有机构员工可见仍需产品确认。

建议首版默认面向：

1. 机构管理员
2. 运营负责人

不建议默认开放给所有普通员工。原因是该页面虽不展示平台内部敏感字段，但仍属于机构运营和套餐权益视角。

本轮不实现权限控制，不新增角色，不修改机构端 API 权限。

## 14. 后续开发拆分

建议后续拆分：

1. `V0.6-AI-CREDITS-INSTITUTION-03`：机构端 AI 服务使用 UI 最小实现。
2. `V0.6-AI-CREDITS-INSTITUTION-04`：本地 / 测试服验收。
3. 可选：套餐权益联动。
4. 可选：智能随访 service project 写入口径补齐。
5. 可选：额度告警。
6. 可选：导出，默认后置。

`INSTITUTION-03` 建议只实现 UI 最小闭环：入口、指标卡、趋势、服务项目排行、空状态、错误状态和低敏边界测试。不要在同一个 PR 中加入导出、套餐扣减、额度告警或智能随访写入口径。

## 15. 明确不包含

本设计 PR 不包含：

1. 不开发 UI。
2. 不新增 API。
3. 不改 DB/schema/migration。
4. 不做套餐扣减。
5. 不做额度告警。
6. 不做导出。
7. 不补智能随访写入口径。
8. 不部署测试服。
9. 不执行 migration。
10. 不执行 db:seed。
11. 不写数据库。
12. 不调用 provider。
13. 不真实 AI smoke。
14. 不改平台端 AI 用量页面。
15. 不进入 `INSTITUTION-03` 正式开发。

## 16. 待确认问题

1. 页面名称最终采用 `AI 服务使用` 还是 `AI 服务额度`。
2. 页面入口放在“设置 / 套餐权益”，还是放在机构工作台 AI 服务模块。
3. 首版是否仅机构管理员可见，还是运营负责人也可见。
4. `AI 服务额度使用量` 的中文命名是否需要与套餐权益文案统一。
5. 后续套餐额度联动时，是否需要展示剩余额度、额度使用率和额度告警。
6. 智能随访相关服务项目的写入口径是否先补齐，再进入 UI 展示增强。
