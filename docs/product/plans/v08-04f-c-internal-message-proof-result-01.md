## 1. 任务背景

本次 proof 用于验证企业微信官方自建应用路线：在单机构、单应用、单个内部成员和单条固定测试消息的受控范围内，经人工确认后完成一次真实发送验证。

本次验证对象是企业微信内部成员，不是客户联系、外部联系人或生产触达；结果不代表客户运营真实通道、群发能力或生产发送能力已经可用。

本文仅归档已经完成的 proof 事实，不开发功能，不读取凭证，不再次真实出网，不再次发送消息，也不授权开始 4F-D。

## 2. 前置条件

proof 执行前已确认：

- `CorpID`、`AgentId`、`AgentSecret` 和单个内部成员配置完整。
- token / auth preflight 已通过。
- 自建应用可见范围包含指定测试成员。
- 可信域名已经启用。
- 企业可信 IP 已完成配置。
- 真实网络和真实发送仅在本次人工 proof 时短暂、显式开启。
- 测试范围限定为单机构、单个内部成员和单条固定消息。

上述配置的真实值不进入本文，不进入仓库，也不进入 PR 描述。

## 3. 过程记录

1. 首次调用 `message/send` 时，企业微信返回数字错误码 `60020`。
2. 系统返回的低敏诊断阶段为 `message_send`，未返回企业微信原始响应全文。
3. 根据错误码与执行阶段，将 `60020` 定位为企业可信 IP 不匹配。
4. 完成企业可信 IP 调整后，仅重新执行一次人工确认发送。
5. 本文不记录调整前后的具体公网 IP，不记录企业微信后台配置截图。

## 4. 最终结果

最终 API 返回以下低敏结果：

```txt
messageProofStatus = internal_message_proof_sent
reason = internal_message_proof_sent
```

指定内部成员已在企业微信客户端实际收到固定测试消息：

> 这是一条智美天工企业微信内部通道联调测试消息，无需回复。

结论：V0.8 目标 4F-C 的单机构、自建应用、单个内部成员、单条消息 proof 通过。
