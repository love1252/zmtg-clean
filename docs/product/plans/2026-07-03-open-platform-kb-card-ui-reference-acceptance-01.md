## 参考图观察要点

平台端参考图重点体现：

1. 顶部指标卡需要能快速读出接入机构、知识条目、累计命中、训练 / 解析覆盖、待优化等运营信号。
2. 左侧运营对象卡需要能承载机构范围、知识数、命中数、覆盖率和状态，便于切换运营范围。
3. 当前范围应有清晰的范围摘要和健康信号，避免用户只看到分散表格。
4. 文件管理区域适合使用卡片网格承载文件名、机构、状态、类型、大小、分类、文件夹、解析字符数、错误信息和操作入口。
5. 右侧运营信号应卡片化表达高频问题、热门分类、零命中知识和导入成功率等运营判断。
6. 信息密度应偏运营后台，不做营销式 hero，不为了视觉复刻牺牲扫描效率。

机构端参考图仅记录为后续机构端知识库体验参考。本轮不以机构端视觉差异作为平台端验收阻断项。

## 本地 5010 验收结论

本轮在 `http://127.0.0.1:5010/open-platform` 做只读浏览器验收，确认：

1. 页面可打开，无白屏、无 500、无编译错误。
2. 顶部指标卡可见，覆盖接入机构、知识条目、累计命中、训练 / 解析覆盖、待优化。
3. 当前范围运营摘要可见，并明确显示“数据来自新版知识库 contract，未新增统计 API”。
4. 左侧机构运营卡可见，展示运营状态、知识数、命中数、覆盖率，并支持当前范围感知。
5. 文件管理 tab 中的文件卡片网格可见，相比原表格更适合运营快速查看。
6. 文件卡片展示文件名、机构、解析状态、类型 / 大小、解析字符数、解析片段、保留原始文件、分类、文件夹、更新时间、错误信息、下载能力和受控操作状态。
7. 原有文件表格能力仍保留，卡片网格没有替代或删除原有管理能力。
8. 右侧运营信号卡片可见，包含高频问题、热门分类、零命中知识、导入成功率，并展示风险等级。
9. 桌面宽屏下整体信息密度可接受，卡片化表达已明显接近平台端参考图的信息架构。
10. 768px 窄屏下关键卡片区域仍可读取，未发现明显横向溢出。
11. 390px 移动视口下页面无白屏、无 500、无明显横向溢出，但目标菜单未直接展开到知识库管理，移动端深入验收建议后续单独做。
