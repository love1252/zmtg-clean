# 智美天工 V1 机构端与平台端管理能力规划 01

任务编号：`ZMTG-V1-INSTITUTION-PLATFORM-MANAGEMENT-PLAN-DOCS-ONLY-01`

生成日期：2026-06-11

本文档用于规划 V1 机构端管理、平台端管理、权限、租户隔离、功能开关、配额、审计、风控、监控、知识库配置和 AI 配置的能力边界。本文档是 docs-only 规划，不是 runtime 授权，不是上线准备，不是试点授权，也不是后续任务队列。

## 1. 当前阶段结论

- 智美天工不是 HIS 系统。
- 智美天工是面向医美 / 美业机构的 AI 客户运营中台。
- 当前主线是治疗后客户运营闭环。
- 当前已有内部 demo / 局部 runtime 基础，但 V1 主业务闭环仍未真实端到端跑通。
- 当前机构端管理尚未形成完整后台，仍缺机构设置、员工、角色、运营配置、知识库配置、AI 配置、HIS connection 配置、用量查看和审计可见范围的规划边界。
- 当前平台端管理尚未形成完整 SaaS 管理后台，仍缺租户生命周期、套餐 / 配额、功能开关、平台知识库、平台 AI、审计、风控、监控和平台运营配置的规划边界。
- 当前不能接真实 HIS、真实 credential、真实客户数据或真实模型。
- 本文档是 docs-only 规划，不是 runtime 授权。

## 2. 管理能力总体边界

| 管理域 | 目标 | 权限边界 | 审计边界 | 租户隔离边界 |
|---|---|---|---|---|
| 机构端管理 | 让机构在授权范围内管理自身组织、人员、运营规则、知识库配置、AI 配置和 HIS connection 配置。 | 机构端只面向本机构授权角色，不具备平台级租户管理权限。 | 记录机构内配置、权限、知识库、AI 和 HIS connection 相关变更的低敏摘要。 | 机构端只能作用于当前租户，不得跨租户读取或配置。 |
| 平台端管理 | 让平台规划租户、套餐、配额、功能开关、平台知识库、平台 AI、审计、风控和监控能力。 | 平台端用于 SaaS 管理边界，不替代机构日常运营。 | 记录租户、套餐、配额、功能开关、平台配置和高风险操作的低敏摘要。 | 平台配置下发必须遵守租户隔离，不得暴露机构间数据。 |
| 机构端与平台端协作 | 平台定义能力边界，机构在授权范围内使用能力。 | 管理能力不得绕过 RBAC / tenant guard / quota / feature flag。 | 权限拒绝、超限、禁用和配置冲突必须可审计。 | 平台端不得把跨租户能力下放成机构端能力。 |

- 机构端不是平台后台。
- 平台端不是机构运营替代品。
- 管理能力不得绕过 RBAC / tenant guard / quota / feature flag。
- 管理能力不得被解释为真实客户上线条件已具备。

| 随访 SOP 配置 | 规划随访步骤、风险升级、人工确认和禁用表达。 | 不自动触达客户。 |
| 内部任务规则配置 | 规划任务建议、去重、过期、完成和人工确认边界。 | 不自动创建任务 / 预约 / 成交。 |
| 机构知识库配置 | 规划机构知识栏目、审核、发布、停用、权限和租户隔离。 | 不实现知识库 runtime，不跨租户使用。 |
| 机构 AI 配置 | 规划 AI 使用场景、角色授权、人工审核、禁用策略和成本提示。 | 不接真实模型，不自动触达客户。 |
| HIS connection 配置 | 规划连接元数据、状态、配置可见性和错误提示边界。 | 不接真实 HIS，不处理真实 credential。 |
| 审计可见范围 | 规划机构内可查看的低敏审计类型、范围和权限。 | 不泄露 credential、token、secret、HIS raw payload、DB URL、SQL 或 stack。 |
| 额度 / 用量查看 | 规划租户内 AI、知识库、功能和用量摘要的展示边界。 | 不实现 quota runtime，不作为真实计费结算。 |

## 5. 权限与租户隔离规划

| 项目 | 规划内容 | 边界 |
|---|---|---|
| tenant guard | 所有机构端管理能力必须绑定当前租户范围。 | 不允许跨租户读取、配置或推断对象存在。 |
| RBAC | 机构端和平台端必须分别规划角色、权限和拒绝口径。 | 不允许用平台角色绕过机构内权限。 |
| 平台角色 | 规划平台管理员、平台运营、平台审核、平台只读等职责边界。 | 不代表可直接处理真实客户数据。 |
| 机构角色 | 规划机构管理员、运营、咨询、客服、只读等职责边界。 | 不代表可访问平台后台。 |
| 跨租户访问禁止 | 规划跨租户访问、配置、知识引用和审计查询的禁止边界。 | 不暴露目标租户是否存在。 |
| 机构内角色权限矩阵 | 规划员工、角色、配置、知识库、AI 和审计的最小权限矩阵。 | 不实现权限矩阵 runtime。 |
| 平台操作机构数据的限制 | 规划平台只能在授权、低敏、可审计范围内处理机构配置。 | 不绕过机构权限直接使用真实客户数据。 |
| 平台配置下发到机构的边界 | 规划平台能力开关、套餐、配额和标准知识下发边界。 | 不覆盖机构自有配置和租户隔离。 |
| 权限拒绝时不泄露对象详情 | 规划拒绝输出只能说明无权限或不可用。 | 不泄露客户、员工、知识、配置或租户详情。 |
| 审计记录的低敏边界 | 规划审计只记录低敏摘要、操作者、时间、动作类型和结果。 | 不记录 credential、token、secret、HIS raw payload、DB URL、SQL 或 stack。 |

## 7. 机构端与知识库 / AI 的关系

| 关系 | 规划内容 | 边界 |
|---|---|---|
| 机构知识库配置 | 机构端可规划机构自有知识库栏目、内容审核、发布、停用和权限边界。 | 机构知识库不得跨租户使用。 |
| 机构 AI 使用边界 | 机构端可规划 AI 场景、角色授权、人工审核和禁用策略。 | 机构知识库 / AI runtime 必须另行授权。 |

| 治疗后运营辅助 | AI 可规划为辅助总结、解释、提醒和风险提示。 | 不得承诺疗效，不得替代医疗判断。 |
| 内部任务建议 | AI 可规划内部任务建议的人工确认边界。 | 不得自动创建任务 / 预约 / 成交。 |
| 知识引用边界 | 机构 AI 只能在授权范围内引用机构知识或平台授权知识。 | 不跨租户引用，不泄露知识全文或真实客户数据。 |

机构端与知识库 / AI 的关系只能作为管理规划，不是知识库 runtime、AI runtime、自动营销或自动触达授权。

## 12. Go / No-Go 规则

| 类型 | 结论 | 规则 |
|---|---|---|
| docs-only | GO | 可以继续，但只能写明确授权的文档。 |
| read-only | GO | 可以继续，用于复核机构端、平台端、权限、租户、审计、风控、监控和配置边界。 |
| test-plan-only | GO | 可以继续，用于定义后续管理能力、知识库和 AI 的测试计划，不实现测试或 runtime。 |
| test-only | CONDITIONAL-GO | 可以继续，但必须最小，且不得要求生产代码改动。 |
| 机构端管理 runtime | NO-GO before plan and test plan | 必须先有 plan 和 test plan，并由用户单独授权。 |
| 平台端管理 runtime | NO-GO before plan and test plan | 必须先有 plan 和 test plan，并由用户单独授权。 |
| UI / API / DB / schema | NO-GO without approval | 必须单独授权，不得夹带在 docs-only、read-only、test-plan-only 或 test-only 任务中。 |
| 真实 HIS / credential / 客户数据 / 模型 | NO-GO without approval | 必须单独授权，并先完成安全、权限、审计、低敏和回滚边界规划。 |
