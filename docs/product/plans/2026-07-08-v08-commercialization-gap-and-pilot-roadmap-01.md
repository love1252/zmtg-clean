# V0.8 商用化差距评估与真实试点路线图

## 1. 文档目的

本文用于在 V0.7 closeout 后，评估智美天工距离真实试点和商用上线仍缺少哪些能力，并规划 V0.8 的推进结构。

本文只回答三个问题：

1. V0.7 closeout 后，现在距离商用还差什么。
2. V0.8 应该按哪些大目标推进。
3. 哪些条件满足后，才能进入真实试点或商用上线。

本文是 docs-only 规划，不开发功能，不新增 API，不新增 UI，不新增 schema / migration，不接真实企业微信、短信、HIS 或 webhook，不读取或写入真实渠道 secret / API key，不真实发送消息，不真实出网，也不启动真实试点。

## 3. 当前可进入的阶段

当前可以进入：

- 内部受控演示。
- 准试点准备。
- 真实试点方案设计。

内部受控演示只能使用 mock 数据、低敏数据和受控环境，演示重点是消息草稿、人工确认、触达安全治理、`MessageDelivery` mock 状态、企业微信授权状态 mock、企业微信客户联系 mock、企业微信随访触达 mock、timeline 低敏沉淀、audit 低敏审计和 dashboard 低敏统计。

准试点准备只能做试点机构候选、测试企业微信主体、服务商 / 第三方应用路径、单机构灰度范围、授权边界、权限审计、回滚策略和交付材料准备。

真实试点方案设计可以讨论真实接入路径，但不能在未完成前置条件前直接接真实接口或真实客户数据。

## 4. 当前不能进入的阶段

当前不能直接进入：

- 真实企业微信接入。
- 真实客户同步。
- 真实消息发送。
- 会话内容存档。
- 生产上线。

原因是企业微信、客户联系、企业微信触达仍为 mock，真实渠道、真实数据、真实凭证均未接入。当前系统还没有完成真实机构配置、真实客户低敏导入、权限矩阵、生产审计、真实 secret 管理、webhook 安全边界、备份恢复和生产监控告警。

因此，V0.8 不能从“继续扩企业微信功能”直接开始。没有真实机构和低敏客户数据入口，企业微信和 AI 只能停留在 mock / demo。

## 5. 距离商用的主要差距

当前距离商用的主要差距有六类：

1. 机构和租户开通差距：缺少真实机构 / 租户配置能力、机构初始化流程、员工账号和角色权限矩阵。
2. 客户数据入口差距：缺少真实客户数据导入 / 同步、字段白名单、低敏导入、去重、失败回滚和导入审计。
3. 商业权益配置差距：缺少套餐、权益、配额、功能开关和机构可用能力的配置闭环。
4. 真实渠道差距：企业微信授权、外部联系人同步、真实消息灰度发送、webhook / 回调安全边界仍未完成。
5. 安全合规差距：会话内容存档、AI 内容生成边界、人工确认、敏感字段防泄露、操作审计、删除 / 导出 / 留存策略仍需补齐。
6. 交付运维差距：生产部署、备份、监控、告警、回滚、客户交付材料、试点协议、使用手册和演示脚本仍未完成。

这些差距决定了 V0.8 的第一开发重点不应是继续堆叠企业微信 mock 功能，而应先补真实机构和低敏客户数据入口。

## 7. V0.8 推荐目标结构

V0.8 不建议拆成零散支线，建议按五个大目标推进：

- 目标 1：商用化差距评估与试点路线图。
- 目标 2：真实机构与低敏客户数据导入闭环。
- 目标 3：权限 / 审计 / 安全开关商用最小闭环。
- 目标 4：单机构企业微信真实灰度 proof 方案与最小实现。
- 目标 5：试点交付包与商用准备收口。

目标之间的关系是递进的：

- 目标 1 是当前 docs-only 任务，只做路线图和边界确认。
- 目标 2 是下一步真正开发优先级。
- 目标 3 在目标 2 的真实机构和客户数据基础上补足商用安全底座。
- 目标 4 才进入单机构企业微信真实灰度 proof。
- 目标 5 负责试点交付、材料、运维和阶段收口。

不建议直接继续扩企业微信功能。没有真实机构和低敏客户数据入口，企业微信和 AI 只能停留在 mock / demo。

## 9. V0.8 目标 2：真实机构与低敏客户数据导入闭环

目标 2 是 V0.8 下一步真正开发优先级。

目标 2 应解决真实试点最基础的问题：系统如何安全地开通一个真实机构，并导入或同步一批低敏客户数据。

建议范围：

- 真实机构 / 租户配置能力。
- 机构开通与初始化流程。
- 员工账号基础配置。
- 客户字段白名单。
- 低敏客户导入。
- 客户去重策略。
- 导入失败回滚。
- 导入审计。
- 导入结果进入 dashboard 或低敏运营视图。

目标 2 仍不应直接接真实企业微信、短信、HIS 或 webhook。它应先把“真实机构和低敏客户数据入口”做稳，否则后续企业微信和 AI 都缺少真实承接面。

## 10. V0.8 目标 3：权限 / 审计 / 安全开关商用最小闭环

目标 3 应在目标 2 的基础上补齐商用安全底座。

建议范围：

- 员工账号、角色、权限矩阵。
- 租户隔离验证。
- 机构级功能开关。
- 套餐 / 权益 / 配额配置。
- 敏感字段白名单验证。
- 操作审计。
- 真实渠道开关预留。
- 灰度开关和回滚开关。
- 敏感字段防泄露检查。
- dashboard 中的低敏安全状态汇总。

目标 3 的目标不是做完整企业级权限平台，而是形成商用最小闭环：谁能看什么、谁能操作什么、哪些功能可用、哪些敏感字段不可见、发生了什么可被审计。

## 11. V0.8 目标 4：单机构企业微信真实灰度 proof 方案与最小实现

目标 4 才建议进入企业微信真实灰度 proof。

目标 4 只能限定为单机构、单员工、单客户、单条消息的最小真实灰度，不是企业微信全面接入，不是自动营销系统，也不是生产级渠道上线。

建议范围：

- 明确测试企业微信主体。
- 明确是否走企业微信服务商 / 第三方应用。
- 明确授权范围。
- 明确真实 secret 管理方案。
- 明确 webhook / 回调安全边界。
- 明确人工确认机制。
- 明确 `MessageDelivery` 状态回写。
- 明确 timeline / audit / dashboard 审计链路。
- 明确灰度开关和回滚开关。
- 明确异常时立即关闭真实渠道。

目标 4 不应同时接短信，不应同步真实聊天记录，不应接入会话内容存档，不应做客户自动回复，不应做群发。

目标 5 用于把 V0.8 的真实试点准备整理成可交付、可审计、可回滚、可复盘的阶段成果。

建议范围：

- 试点协议和客户告知材料。
- 使用手册。
- 演示脚本。
- 运营 SOP。
- 权限矩阵说明。
- 数据字段白名单说明。
- 渠道灰度开关和回滚说明。

## 13. 真实试点前置条件

真实试点前至少需要：

- 明确试点机构。
- 明确测试企业微信主体。
- 明确单租户、单机构、单员工、单客户、单条消息。
- 明确测试客户，不得误发真实客户。
- 明确客户授权和员工知情。
- 明确真实 secret 管理方案。
- 明确 webhook 安全边界。
- 明确人工确认机制。
- 明确 `MessageDelivery` 状态回写。
- 明确 timeline / audit / dashboard 审计链路。
- 明确灰度开关和回滚开关。
- 明确不做客户自动回复。
- 明确不做群发。
- 明确不做真实聊天记录同步。

如果以上条件未满足，真实试点不能启动。即使可以做内部受控演示，也不能把 mock 状态作为真实试点证据。

## 14. 商用上线前置条件

商用上线前至少需要：

- 生产环境部署方案。
- 数据库备份与恢复策略。
- 日志、监控、告警。
- 版本回滚机制。
- 租户隔离验证。
- 权限矩阵验证。
- 敏感字段白名单验证。
- 真实渠道开关与熔断。
- 客户数据删除 / 导出 / 留存策略。
- 试点协议与客户告知材料。
- 使用手册和交付流程。
- 售后支持机制。

商用上线还需要完成真实试点复盘，证明真实数据、真实权限、真实审计、真实渠道开关和异常回滚在受控范围内可运行。

## 15. 明确暂不做事项

V0.8 当前阶段暂不做：

- 直接接入真实企业微信。
- 直接同步真实客户。
- 直接发送真实消息。
- 直接接入会话内容存档。
- 直接生产上线。
- 同时接入企业微信和短信。
- 接真实 HIS。
- 接真实 webhook。
- 自动营销。
- 自动群发。
- 客户自动回复。
- AI 自动生成并直接发送客户可见建议。
- 未经授权读取或写入真实渠道 secret / API key。
- 未经试点边界确认同步真实外部联系人或真实聊天记录。

这些事项不是永远不做，而是不能在目标 1 或目标 2 阶段越权实现。

## 16. 推荐下一开发目标

推荐下一开发目标是：

V0.8 目标 2：真实机构与低敏客户数据导入闭环。

推荐理由：

- 真实试点必须先有明确机构和租户承接面。
- 企业微信授权、客户联系同步和 AI 运营都需要真实客户低敏数据入口。
- 权限、审计、安全开关和交付材料都依赖真实机构配置。
- 没有真实机构和低敏客户数据入口，继续扩企业微信功能只会停留在 mock / demo。

目标 2 的开发仍应保持受控范围：先做机构开通、低敏客户导入、字段白名单、去重、失败回滚和导入审计，不接真实企业微信，不接真实短信，不接真实 HIS，不接真实 webhook。

V0.7 已完成，可以 closeout。

- 内部受控演示。
- 准试点准备。
- 真实试点方案设计。

当前不能直接进入：

V0.8 应按五个大目标推进：商用化差距评估与试点路线图、真实机构与低敏客户数据导入闭环、权限 / 审计 / 安全开关商用最小闭环、单机构企业微信真实灰度 proof 方案与最小实现、试点交付包与商用准备收口。

下一步真正开发优先级是目标 2：真实机构与低敏客户数据导入闭环。只有补齐真实机构、低敏客户数据入口、权限审计和安全开关，企业微信真实灰度 proof 才有稳固承接面，后续才可能进入真实试点或商用上线准备。
