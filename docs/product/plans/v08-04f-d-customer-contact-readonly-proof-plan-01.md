# V0.8-04F-D 单机构企业微信客户联系只读 proof 规划

## 1. 文档目的

本文规划企业微信官方客户联系 / 外部联系人的单机构只读 proof，明确最小验证范围、官方接口与权限候选、低敏字段白名单、安全门禁、失败处理和后续任务切分。

本任务仅新增规划文档，不开发代码，不配置或读取真实 secret，不真实调用企业微信接口，不真实读取或同步外部联系人，不发送消息，也不修复 `/api/institution/entitlement-usage` `503`。

本文不是 4F-D 运行时开发授权，也不是 4F-E 开发授权。

## 2. 4F-C 已完成范围与边界

4F-C 已完成的 proof 仅包括：

- 单机构企业微信主体下的自建应用。
- 单个内部成员。
- 单条固定内部测试消息。
- 人工确认后的最小真实发送验证。
- 低敏记录 `message_send` 阶段、数字错误码和最终状态。

4F-C 证明了自建应用内部消息最小链路可用，但没有验证：

- 客户联系能力是否开通。
- 应用是否拥有客户联系相关接口权限。
- 测试员工是否在客户联系可调用范围内。
- 外部联系人列表或详情是否可读取。
- 客户联系数据是否可低敏映射。

因此，4F-C 成功不能被解释为客户联系、外部联系人同步、客户触达、聊天记录或生产持续同步已经可用。

## 3. 4F-D 第一阶段目标

4F-D 第一阶段只规划以下最小 proof：

- 单机构。
- 单个测试员工。
- 单个测试外部联系人。
- 只读。
- 低敏。
- 人工触发。
- 单次执行，不持续同步。
- 不发送任何消息。
- 不写入正式客户表或客户档案。

真实 proof 必须后续另开任务并逐项授权。当前文档阶段保持真实网络关闭、客户同步关闭和真实发送关闭。

## 4. 推荐 proof 链路

后续获得单独授权后，推荐按以下顺序执行最小只读 proof：

1. 核验测试企业是否已开通客户联系能力。
2. 核验测试自建应用是否被配置为可调用客户联系接口的应用，并且权限范围仅覆盖本次测试所需能力。
3. 获取可访问客户联系的成员范围，只确认目标测试员工是否在范围内。
4. 仅针对该测试员工获取外部联系人标识列表。
5. 由人工从结果中选择一个明确的测试外部联系人。
6. 仅获取该测试外部联系人的低敏只读详情。
7. 在响应进入 proof 结果前执行字段白名单过滤、标识掩码或不可逆 hash、文本敏感信息阻断。
8. 不把结果写入正式客户表，不建立正式客户档案。
9. 只形成一次性 proof 结果和后续映射建议。
10. proof 完成或失败后立即恢复真实网络和客户读取开关为关闭。

任一步骤越过单机构、单员工、单外部联系人范围，或出现敏感字段无法可靠过滤时，必须立即停止。

## 5. 官方接口与权限候选

以下接口仅用于定义后续实现前需要核对的官方契约，本任务不调用。进入 4F-D1 或 4F-D3 前必须再次以企业微信官方文档和测试企业后台实际权限为准。

| 目的 | 官方接口候选 | proof 使用边界 |
| --- | --- | --- |
| 获取访问凭证 | `/cgi-bin/gettoken` | 只作为后续受控调用的鉴权前置；凭证不返回、不记录、不落盘 |
| 获取配置了客户联系功能的成员列表 | `/cgi-bin/externalcontact/get_follow_user_list` | 只判断单个测试员工是否在允许范围内，不形成全员目录 |
| 获取单个员工的客户列表 | `/cgi-bin/externalcontact/list` | 只传入一个已确认测试员工，不做批量员工遍历 |
| 获取单个客户详情 | `/cgi-bin/externalcontact/get` | 只读取一个人工选择的测试外部联系人，并在返回后立即执行白名单过滤 |
| 获取企业标签库 | `/cgi-bin/externalcontact/get_corp_tag_list` | 非必需；仅当 proof 明确需要验证低敏标签名称时单独授权，不读取无关标签范围 |

后续 proof 至少需要核对以下权限与后台配置：

- 测试企业已开通客户联系能力。
- 自建应用已被配置为客户联系可调用接口的应用。
- 应用具备读取客户基础信息、客户与员工关系及必要企业标签的最小权限。
- 单个测试员工处于应用可见范围和客户联系可调用范围内。
- 测试外部联系人确实由该员工维护，并由负责人确认可用于最小只读 proof。
- 不申请消息发送、客户群发、朋友圈、自动加好友、会话内容存档等与本 proof 无关的权限。

如官方权限模型、接口字段或后台配置方式发生变化，应在后续独立任务中更新契约；不得以扩大权限代替核对。

## 6. 测试员工与测试外部联系人选择规则

测试员工必须满足：

- 仅选择一个员工。
- 由测试机构管理员明确指定。
- 位于自建应用可见范围内。
- 位于客户联系可调用成员范围内。
- 确认其维护的测试外部联系人不会造成真实业务干扰。
- 企业微信员工标识原文不得写入仓库、日志、PR 或普通页面。

测试外部联系人必须满足：

- 仅选择一个外部联系人。
- 必须是明确用于测试、由相关人员可控并已知情的对象。
- 必须由选定测试员工维护。
- 不得通过遍历、猜测或批量筛选选择。
- 不得使用包含医疗隐私、真实咨询内容或高敏备注的对象。
- 外部联系人原始标识不得写入仓库、正式客户表、日志、PR 或普通页面。

无法同时满足以上规则时，停留在 mock 阶段。

## 7. 低敏字段白名单

真实只读 proof 如后续获得授权，最终 proof 结果只允许包含以下字段：

| 字段 | 允许形式 | 说明 |
| --- | --- | --- |
| 内部派生 proof ID | 随机或任务内派生低敏标识 | 不使用企业微信原始标识作为 ID |
| `external_userid` | 掩码、不可逆 hash 或完全不落盘 | 默认优先不落盘；禁止原文返回和展示 |
| 客户类型 | 有限枚举 | 只保留企业微信返回类型对应的低敏枚举 |
| 添加时间 | 标准时间或日期 | 不与其他高敏数据组合形成画像 |
| 添加员工的内部低敏标识 | 系统内部派生标识 | 不记录企业微信员工 `userid` 原文 |
| 删除状态 | `active`、`deleted`、`unknown` 等低敏枚举 | 只表达关系状态，不保留删除事件原始 payload |
| 企业标签低敏名称 | 经敏感词和长度过滤后的名称 | 仅保留本次测试对象相关标签，禁止备注和标签原始全文批量落盘 |
| 客户关系状态 | `visible`、`unavailable`、`unknown` 等低敏枚举 | 不推断客户身份、治疗状态或营销意向 |

任何不在白名单内的字段默认丢弃。字段无法确认是否低敏时，不返回、不记录、不落盘。

## 8. 禁止返回或落盘的字段

严禁返回、记录、展示或写入正式数据表：

- 手机号。
- 身份证号。
- 微信号。
- `unionid` / `openid` 原文。
- `external_userid` 原文。
- 企业微信员工 `userid` 原文。
- 地址。
- 聊天内容、聊天摘要或咨询原文。
- 备注中的姓名、手机号、病历、治疗信息等敏感内容。
- 企业微信原始响应全文。
- `CorpID`、`AgentId`、secret、token、access token。
- `.env.local` 内容。
- 任何可反推出真实客户、员工或企业身份的组合字段。

不得把禁止字段暂存到普通日志后再清洗；过滤必须发生在形成可观察 proof 结果之前。

## 9. 权限与安全门禁

默认状态必须保持：

- 真实网络关闭。
- 客户联系真实读取和同步关闭。
- 真实发送关闭。
- 未取得显式人工确认时不执行。
- 未确认单机构、单员工、单测试外部联系人时不执行。

后续真实只读 proof 必须满足：

- 每次操作由具备受控连接测试权限的机构管理员显式触发。
- 请求必须绑定唯一 `tenantId` 和 `institutionId`，禁止跨租户、跨机构。
- 操作目标必须绑定一个低敏员工引用和一个 proof 内部 ID。
- 外部联系人原始标识只能在受控调用的最小生命周期内使用，不进入普通响应和日志。
- 任何范围不确定、权限变化或字段超出白名单均触发阻断。

明确禁止：

- 批量或全量同步。
- 遍历多个员工或多个外部联系人。
- 定时任务、scheduler、worker 或 queue。
- 后台轮询。
- 自动重试。
- webhook 或 callback 持续接收。
- 写入正式客户档案、客户表或客户标签表。
- 真实消息发送。

## 10. 失败状态与低敏诊断

后续实现可采用有限、低敏状态枚举，不返回企业微信原始错误文本或 payload：

| 状态候选 | 含义 | 处理 |
| --- | --- | --- |
| `real_network_disabled` | 真实网络未显式开启 | 保持阻断 |
| `manual_confirmation_required` | 缺少本次人工确认 | 保持阻断 |
| `customer_contact_not_enabled` | 测试企业未开通客户联系 | 停止 proof |
| `application_permission_missing` | 应用缺少最小客户联系权限 | 停止 proof，不扩大权限 |
| `employee_out_of_scope` | 测试员工不在可调用范围 | 停止 proof |
| `external_contact_not_selected` | 未人工选择唯一测试外部联系人 | 停止 proof |
| `external_contact_unavailable` | 目标关系不可读、已删除或不可用 | 停止 proof |
| `sensitive_payload_blocked` | 返回数据包含禁止字段且无法安全过滤 | 立即停止并丢弃结果 |
| `readonly_proof_completed` | 单对象低敏只读 proof 完成 | 只保留允许的低敏结果 |
| `emergency_stopped` | 人工执行紧急停止 | 关闭真实网络和客户读取开关 |

失败时不得自动重试，不得改用其他员工或其他外部联系人继续尝试。

## 11. Emergency Stop 与回滚

后续真实 proof 开始前必须指定 emergency stop 负责人，并确保其能够立即：

1. 关闭真实网络开关。
2. 关闭客户联系读取和同步开关。
3. 确认真实发送开关保持关闭。
4. 终止当前请求，不启动自动重试。
5. 丢弃包含禁止字段的临时结果。
6. 只保留低敏状态、阶段枚举、时间和回滚结论。
7. 确认没有写入正式客户表、客户档案、timeline 或普通业务日志。
8. 回退到 mock 只读列表与详情。

以下任一情况必须触发 emergency stop：

- 目标机构、员工或外部联系人不唯一。
- 应用权限范围与预期不一致。
- 出现批量数据、无关客户或聊天内容。
- 响应包含无法安全过滤的敏感字段。
- 发现凭证、原始标识或原始响应可能进入日志。
- 请求超出一次人工触发范围。
- 发生未授权真实发送、回调、轮询或后台任务风险。
