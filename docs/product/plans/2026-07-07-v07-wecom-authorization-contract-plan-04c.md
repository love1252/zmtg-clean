# V0.7 企业微信授权接入契约文档

任务编号：V0.7-WECOM-AUTHORIZATION-CONTRACT-PLAN-04C

日期：2026-07-07 CST +0800

任务类型：docs-only / 授权接入契约 / 不开发功能

## 1. 文档目的

本文档用于规划 V0.7 目标 4 后续企业微信授权接入的契约边界，明确平台、机构、员工、客户和随访触达链路之间的关系。

本任务只做文档规划，不开发代码，不新增接口，不新增页面，不新增 schema / migration，不申请企业微信服务商，不接真实企业微信接口，不读取或保存真实密钥，不同步真实客户，不发送真实消息。

## 2. 当前 V0.7 状态摘要

V0.7 已完成的前置工作主要包括：

- 目标 1：随访消息草稿与人工确认链路已具备基础规划和验收口径。
- 目标 2：客户 timeline 能够承接低敏随访事件汇总。
- 目标 3：触达安全治理与渠道灰度前置已完成默认关闭、人工确认、低敏记录和 dashboard 汇总边界。
- 目标 4A：真实渠道小范围灰度前置确认已明确真实渠道必须后置。
- 目标 4B：企业微信方向已修正为客户运营接入，不是企业微信登录。

目标 4C 的任务是把企业微信授权接入拆成可审查、可灰度、可回滚的契约文档，为后续 mock 模型、沙箱适配和单机构灰度提供边界。

## 3. 企业微信授权接入的正确定位

本项目要做的是：

机构授权其自有企业微信主体

→ 平台保存低敏授权状态

→ 平台按授权范围同步企业微信客户联系 / 外部联系人 / 客户归属员工

→ 后续单独规划会话内容存档

→ 后续人工确认后通过企业微信进行回访 / 随访触达

→ MessageDelivery 状态回写

→ timeline / audit / dashboard 汇总

这个方向服务于机构的客户运营与随访触达，不是登录能力替换，也不是自动营销系统。

## 4. 明确排除：企业微信登录不是本任务目标

本任务明确排除以下方向：

- 不是企业微信登录。
- 不是机构员工扫码登录智美天工。
- 不是用企业微信替代账号密码登录机构端。
- 不是只做企微扫码登录。
- 不是同步员工个人微信好友。
- 不是同步普通微信聊天记录。
- 不是自动营销群发。
- 不是 AI 自动生成后直接发给客户。

机构员工登录智美天工后台，与机构授权企业微信客户运营能力是两件事。前者是系统用户身份认证，后者是机构企业微信主体对平台的客户运营能力授权，不能混为一个能力。

## 5. 多机构授权模型

长期目标不是让每家机构手动填写企业微信密钥。长期方向应按以下模型设计：

平台方提供企业微信第三方应用 / 服务商应用

→ 机构管理员授权

→ 平台获得授权范围内的企业微信客户运营能力

→ 平台仅保存低敏授权状态和必要标识

→ 真实密钥、回调、加解密、权限范围必须后续单独设计

该模型需要支持多租户、多机构隔离。每个 tenantId / institutionId 下的授权状态、员工范围、客户联系范围、触达开关和审计记录都必须独立，不允许跨机构复用授权能力。

本任务不申请企业微信服务商，不创建第三方应用，不接真实接口，不保存真实密钥。

## 6. 授权主体与角色

后续契约至少需要区分以下角色：

- 平台方：智美天工，提供企业微信客户运营接入能力的承载平台。
- 机构方：医美 / 美业机构，拥有自己的企业微信主体。
- 机构管理员：代表机构完成企业微信授权、撤销、范围调整和灰度确认的人。
- 机构员工：企业微信员工，可能对应系统内员工，也可能只作为客户归属关系中的员工标识。
- 外部联系人 / 客户：企业微信客户联系中的客户，可能映射到智美天工 customerId。
- 系统用户：登录智美天工后台的人。

机构员工登录智美天工后台，不等于机构授权企业微信客户运营能力。授权必须由机构管理员在明确授权流程中完成，并且要留下低敏审计记录。

## 7. 授权流程建议

后续开发前建议先按 mock 契约跑通以下流程：

1. 平台侧为机构展示企业微信客户运营授权入口，默认关闭。
2. 机构管理员阅读授权范围、数据边界、触达边界和回滚方式。
3. 机构管理员发起授权，后续真实实现中应跳转到企业微信官方授权流程。
4. 授权完成后，平台只保存低敏授权状态和必要标识。
5. 平台按授权范围展示客户联系、员工映射、触达权限和最近同步状态。
6. 若授权撤销、过期、失效或被平台禁用，所有真实触达能力立即关闭。
7. 每一次授权状态变化都进入 audit，并在 dashboard 呈现低敏摘要。

当前阶段只能规划流程，不允许真实跳转企业微信授权页，不允许读取或写入真实 secret / API key。

## 8. 平台侧授权状态模型建议

本节只做字段方向规划，不代表 schema 设计，不在本任务中实现。

建议后续授权状态模型至少覆盖：

- tenantId
- institutionId
- 授权企业标识
- 授权企业名称低敏展示
- 授权状态
- 授权能力范围
- 客户联系是否授权
- 会话内容存档是否授权
- 消息触达是否授权
- 授权员工范围
- 授权时间
- 失效时间
- 最近同步时间
- 最近错误原因
- 是否进入灰度
- 是否允许真实发送
- 是否默认关闭
- 创建时间
- 更新时间

可选必要标识包括 corpId、agentId、userid、external_userid、open_userid，但展示和记录必须遵循低敏原则。真实密钥、令牌、回调加解密参数、原始接口全文不得进入普通页面、timeline、audit 或 dashboard。

## 9. 授权能力范围

授权能力范围应拆分为多个独立开关，不能因为机构授权了一个能力就默认打开全部能力。

建议至少拆分：

- 客户联系读取：用于外部联系人、客户联系、客户归属员工、客户标签等低敏同步。
- 员工映射读取：用于企业微信员工与系统内员工的关联判断。
- 会话内容存档：高风险能力，默认关闭，后置单独规划。
- 企业微信触达：高风险能力，默认关闭，必须经过灰度、人工确认和 MessageDelivery 状态回写。
- 状态回写：用于记录发送成功、失败、禁用、撤销、过期等低敏结果。

任何能力都必须绑定 tenantId / institutionId，不能跨租户、跨机构使用。

## 10. 客户联系 / 外部联系人同步契约

这里不是同步个人微信好友。

这里只能规划企业微信客户运营范围内的数据：

- 企业微信外部联系人。
- 企业微信客户联系。
- 客户归属员工。
- 客户标签。
- 客户备注。
- 客户来源。
- 客户添加时间。
- 客户与员工关系。

同步契约必须满足：

- 默认只做低敏同步。
- 不展示真实手机号原文。
- 不展示身份证。
- 不展示病历号。
- 不展示完整聊天内容。
- 不展示企业微信原始接口返回全文。
- 不展示密钥、令牌、加解密参数。
- 不把 external_userid、userid、open_userid 直接当作客户身份结论。
- 不在未授权机构中展示任何客户联系数据。

客户联系数据进入系统后，只能作为随访运营的关联线索，不能绕过既有 consent、opt-out、frequency cap 和人工确认规则。

## 11. 客户归属员工同步契约

客户归属员工同步用于回答“某个企业微信客户当前由哪个机构员工维护”，不用于证明系统用户身份。

后续契约建议记录：

- tenantId / institutionId 下的客户归属关系。
- external_userid 与企业微信员工 userid 的关系。
- 员工关系的最近同步时间。
- 员工关系是否失效。
- 是否存在多员工共同维护。
- 是否能映射到系统内员工。

当客户归属员工关系变化时，timeline / audit / dashboard 只展示低敏摘要，不展示完整企业微信原始数据。

## 12. 企业微信员工映射契约

企业微信员工映射不是登录替代方案。它只用于把企业微信员工 userid 与系统内员工或操作人建立受控关联。

后续开发前需要明确：

- 员工映射是否由机构管理员确认。
- 一个系统员工是否可对应多个企业微信员工标识。
- 员工离职、禁用、换岗后如何失效。
- 员工映射错误时如何回滚。
- 触达前是否必须存在有效员工映射。
- 触达审计中如何低敏展示操作人、确认人和企业微信员工关系。

没有明确映射或映射已失效时，不应放行真实触达。

## 13. 会话内容存档边界

会话内容存档是独立高风险能力，不属于本任务开发范围。

后续如果接入，必须单独开任务，并至少明确：

- 企业授权。
- 员工知情。
- 客户合规边界。
- 内容脱敏。
- 权限控制。
- 审计。
- 数据保留期限。
- 删除策略。
- 导出策略。
- 敏感词与医疗建议风险。
- 不允许 AI 自动回复客户。

目标 4C 只规划边界，不接入会话内容存档，不同步真实聊天记录，不展示完整聊天内容。

## 14. 企业微信触达边界

后续企业微信触达必须接在现有链路之后：

治疗摘要

→ 随访路径

→ 阶段任务

→ 消息草稿

→ 人工确认

→ 触达安全治理

→ MessageDelivery

→ 企业微信触达

→ 状态回写

→ timeline / audit / dashboard

触达边界必须写入后续开发验收：

- 没有人工确认不发送。
- 没有机构企业微信授权不发送。
- 没有客户联系授权不发送。
- 没有 consent 不发送。
- 客户 opt-out 不发送。
- frequency cap 命中不发送。
- 未进入灰度不发送。
- 外部渠道未启用则 external_disabled。
- 默认不真实发送。
- 不允许 AI 自动生成后直接发送客户可见医疗建议。

企业微信触达不是自动营销群发，也不是全量客户运营上线。第一阶段只能做单机构、单员工、单客户、单条消息的 gated proof。

## 15. 与 MessageDelivery 的关系

MessageDelivery 是真实触达前后的统一状态承载点。企业微信授权状态不能绕过 MessageDelivery 直接发送。

后续契约应要求：

- 触达前写入待确认或待发送状态。
- 人工确认后才允许进入真实发送尝试。
- 未授权、授权过期、授权撤销、外部渠道关闭等情况写回失败或阻断状态。
- 外部渠道未启用时写回 external_disabled。
- 发送结果只记录低敏状态，不记录密钥、令牌、完整接口请求或完整接口响应。
- 发送失败要记录低敏错误原因、重试建议和回滚状态。
- MessageDelivery 状态要能被 timeline / audit / dashboard 汇总。

## 16. 与 timeline / audit / dashboard 的关系

timeline 用于展示客户维度低敏随访事件，不展示高敏原文。

audit 用于记录机构授权、人工确认、发送尝试、阻断、撤销、回滚等操作链路。

dashboard 用于汇总机构维度的授权状态、灰度状态、触达成功失败摘要、阻断原因和风险提示。

三者都不得展示：

- 真实手机号原文。
- 身份证。
- 病历号。
- 完整聊天内容。
- 企业微信原始接口返回全文。
- 密钥、令牌、加解密参数。
- provider / model / token / cost / vendor 等不属于本任务的外部调用信息。

白名单之外的字段默认不得展示。任何新增展示字段都必须单独审查。

## 18. 高敏字段与禁止展示字段

后续实现必须禁止普通页面、timeline、audit、dashboard 展示或记录以下内容：

- 真实手机号原文。
- 身份证。
- 病历号。
- 完整聊天内容。
- 企业微信原始接口返回全文。
- 真实 secret / API key。
- 访问令牌。
- 回调加解密参数。
- 签名密钥。
- 完整请求体。
- 完整响应体。
- 未脱敏客户备注中的敏感内容。
- 未脱敏医疗建议。
- 员工或客户的隐私聊天内容。

高敏字段如确需后续处理，必须进入独立设计、权限控制、脱敏、审计和保留策略评审。

## 19. 授权失效、撤销、过期与禁用处理

后续契约必须覆盖授权异常状态：

- 机构主动撤销授权。
- 企业微信授权过期。
- 平台侧主动禁用。
- 机构不在 allowlist。
- 员工范围变化。
- 客户联系能力未授权。
- 消息触达能力未授权。
- 会话内容存档能力未授权。
- 最近同步失败。
- 回调验签失败。
- 触达安全治理阻断。

一旦发生撤销、过期、禁用或不在灰度范围内，真实触达必须立即关闭，MessageDelivery 写回阻断状态，dashboard 展示低敏原因，audit 记录低敏操作链路。

## 20. 安全边界与默认关闭策略

企业微信授权接入必须坚持默认关闭：

- 未进入灰度不触达。
- 未授权不触达。
- 授权范围不包含客户联系不触达。
- 授权范围不包含消息触达不触达。
- 没有人工确认不触达。
- 没有 consent 不触达。
- opt-out 不触达。
- frequency cap 命中不触达。
- 外部渠道未启用则 external_disabled。
- 默认不真实发送。

当前不建议立刻盲目申请或接入真实企业微信服务商能力。建议先完成契约、mock 状态模型、客户联系同步 mock、企业微信触达 mock / 沙箱适配，再准备测试企业微信主体，最后评估是否申请企业微信服务商 / 第三方应用。

进入后续开发前，至少需要满足：

- 本文档已完成评审。
- 已确认企业微信方向不是登录能力。
- 已确认长期模型不是机构手动填写密钥。
- 已确认多机构授权隔离模型。
- 已确认只保存低敏授权状态和必要标识。
- 已确认真实密钥、回调、加解密、权限范围后置单独设计。
- 已确认客户联系 / 外部联系人同步边界。
- 已确认会话内容存档后置单独规划。
- 已确认企业微信触达必须接在 MessageDelivery 之后。
- 已确认默认关闭、人工确认、consent、opt-out、frequency cap 和 external_disabled 规则。
- 已确认当前不申请企业微信服务商。
- 已确认后续只从 mock / 沙箱 / 单机构 / 单员工 / 单客户 / 单条消息灰度开始。
