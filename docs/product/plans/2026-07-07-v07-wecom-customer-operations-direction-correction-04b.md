# V0.7 企业微信客户运营接入方向修正文档

任务编号：V0.7-WECOM-CUSTOMER-OPERATIONS-DIRECTION-CORRECTION-04B
日期：2026-07-07 CST +0800
任务类型：docs-only / 方向修正 / 接入边界澄清 / 不开发功能

## 1. 文档目的

本文档用于澄清 V0.7 目标 4B 的企业微信方向，避免把「企业微信客户运营接入」误理解成「企业微信登录机构端系统」。

本任务只做文档，不开发功能，不新增接口，不新增页面，不修改数据库结构，不申请企业微信服务商，不接真实企业微信接口，不读取或写入真实渠道密钥，不真实发送消息，不真实出网测试。

目标 4B 的核心任务是建立正确产品方向和后续开发契约：机构授权其自有企业微信主体后，平台在授权范围内获得企业微信客户运营能力，用于客户联系、外部联系人、员工客户关系、后续会话内容存档规划，以及经人工确认后的随访触达和状态回写。

## 2. 背景：为什么需要方向修正

前置讨论中容易出现一个误区：把企业微信接入理解为「让机构员工用企业微信扫码登录智美天工」。

这个方向不是 V0.7 目标 4B 的重点。机构端账号登录可以继续使用现有账号体系，企业微信登录即使未来要做，也属于身份认证体验优化，不等同于客户运营能力接入。

V0.7 目标 4B 真正需要解决的是客户运营链路：机构自己的企业微信主体如何授权给平台，平台如何在授权边界内同步客户联系资料、员工与客户关系，并在后续灰度中通过人工确认完成企业微信随访触达。

## 3. 正确目标：企业微信客户运营接入

正确方向是：

机构授权其自有企业微信主体
→ 平台获得授权范围内的企业微信客户运营能力
→ 同步企业微信客户联系 / 外部联系人 / 员工客户关系
→ 后续在合规授权下接入会话内容存档
→ 人工确认后通过企业微信完成回访 / 随访触达
→ MessageDelivery 状态回写
→ timeline / audit / dashboard 汇总

这条链路服务于机构客户运营和随访闭环，而不是替换机构端登录方式。

## 4. 明确排除：企业微信登录不是本阶段目标

本阶段不是：

1. 不是企业微信登录。
2. 不是机构员工扫码登录智美天工。
3. 不是用企业微信替代账号密码登录机构端。
4. 不是只做“企微 OAuth 登录”。
5. 不是员工个人微信好友同步。
6. 不是普通微信聊天记录同步。
7. 不是自动营销群发。
8. 不是 AI 自动生成后直接发给客户。

如果后续需要企业微信登录，应另行定义认证目标、账号绑定、安全审计和登录回退策略，不应混入目标 4B。

## 5. 多机构授权模式说明

长期目标不是让每家机构手动填写企业微信密钥。更合理的方向是：

- 平台方提供企业微信第三方应用 / 服务商应用。
- 机构管理员在企业微信侧授权自己的企业微信主体。
- 平台只保存低敏授权状态和必要标识。
- 每个机构的授权、客户联系、员工客户关系、触达能力严格按租户和机构隔离。

多机构授权模式需要能够表达：

- 哪个租户已授权。
- 哪个机构已授权。
- 授权属于哪个企业微信主体。
- 授权范围包含哪些客户运营能力。
- 授权是否可用、是否暂停、是否撤销。

本文档不申请、不开发、不接入第三方应用或服务商应用，只确认方向。

## 6. 企业微信客户联系同步边界

这里说的客户联系同步，不是员工个人微信好友列表，也不是普通微信聊天记录。

更准确的产品口径是：

- 企业微信外部联系人。
- 企业微信客户联系。
- 客户归属员工。
- 客户标签。
- 客户备注。
- 客户关联关系。

同步目标是让机构在智美天工中看到低敏客户运营关系，例如某个客户是否属于某个企业微信员工、有哪些低敏标签、是否可以作为后续人工随访触达候选。

同步边界必须遵守：

- 不同步员工个人微信好友。
- 不同步普通微信聊天记录。
- 不展示未授权客户关系。
- 不展示不必要的外部原始标识。
- 不把客户联系同步当成触达许可。

客户联系同步只能证明客户运营关系存在，不能直接证明可以发送随访消息。

## 7. 会话内容存档边界

会话内容存档是独立高风险能力，不能混入目标 4B 直接开发。

该能力涉及：

- 聊天记录。
- 客户隐私。
- 员工知情。
- 企业授权。
- 合规存储。
- 脱敏展示。
- 权限控制。
- 审计。
- 数据保留策略。
- 删除与导出策略。

目标 4B 只做方向澄清和契约规划，不接入会话内容存档。

后续如需接入，必须单独开任务，并至少满足：

- 企业授权。
- 员工知情。
- 客户合规边界。
- 内容脱敏。
- 权限控制。
- 审计。
- 数据保留策略。
- 删除与导出策略。

在这些条件未明确前，不得同步真实聊天记录。

## 8. 企业微信随访触达边界

企业微信随访触达必须接在现有随访链路之后：

治疗摘要
→ 随访路径
→ 阶段任务
→ 消息草稿
→ 人工确认
→ MessageDelivery
→ 企业微信触达
→ 状态回写
→ timeline / audit / dashboard

必须遵守：

- 没有人工确认不发送。
- 没有授权不发送。
- 没有 consent 不发送。
- 客户 opt-out 不发送。
- frequency cap 命中不发送。
- 未进入灰度不发送。
- 默认不真实发送。

企业微信触达不是自动营销，不是自动群发，不是 AI 生成后直接发给客户。任何客户可见内容都必须先经过人工确认。

## 9. 机构授权流程建议

后续可按以下顺序设计机构授权流程：

1. 平台侧展示企业微信客户运营接入说明。
2. 机构管理员确认授权目的和授权范围。
3. 机构管理员跳转到企业微信授权页完成授权。
4. 平台接收授权结果，只保存低敏授权状态。
5. 平台展示授权状态、可用能力、最近同步时间和撤销提示。
6. 机构可暂停或撤销授权。
7. 授权变化写入 audit。

授权流程必须让机构清楚知道：授权是为了客户联系、外部联系人、员工客户关系和后续随访触达治理，不是为了企业微信登录机构端。

## 10. 平台侧授权状态模型建议

平台侧建议先规划低敏授权状态，不保存真实密钥原文。

建议状态字段方向：

- `tenantId`：租户隔离。
- `institutionId`：机构隔离。
- `corpId`：企业微信主体低敏标识。
- `agentId`：应用低敏标识。
- 授权状态：未授权、已授权、已暂停、已撤销、异常。
- 授权范围：客户联系、外部联系人、员工客户关系、后续触达候选。
- 最近同步时间。
- 最近失败原因低敏码。
- 操作者和审计编号。

真实密钥、票据、回调签名等敏感内容必须进入专门凭证边界，不得出现在普通页面、接口响应、timeline、audit 或 dashboard。

## 11. 低敏字段白名单

方向规划阶段建议只允许以下低敏字段进入页面和汇总：

- `tenantId`
- `institutionId`
- `customerId`
- `corpId`
- `agentId`
- `external_userid` 的低敏引用
- `userid` 的低敏引用
- 授权状态
- 授权范围
- 最近同步时间
- 低敏失败原因
- 低敏客户标签摘要
- 低敏客户归属员工摘要
- MessageDelivery 状态摘要

低敏引用不得等同于客户手机号、客户微信号、员工真实手机号或聊天内容原文。

## 12. 高敏字段与禁止展示字段

以下内容不得在普通页面、接口响应、timeline、audit、dashboard 中展示：

- 企业微信密钥。
- 回调签名密钥。
- 访问票据原文。
- 刷新票据原文。
- 客户手机号原文。
- 员工手机号原文。
- 客户微信号原文。
- 聊天记录原文。
- 普通微信聊天记录。
- 员工个人微信好友列表。
- 供应商原始响应。
- 完整请求载荷。
- 未脱敏错误堆栈。

如果需要存储敏感凭证，必须另行设计凭证存储边界、加密、审计和轮换策略。

## 13. 与 MessageDelivery 的关系

企业微信客户运营接入本身不等于发送消息。真实触达必须从 MessageDelivery 开始治理。

建议关系：

- 客户联系同步只提供客户运营关系。
- 消息草稿只提供待确认内容。
- 人工确认后才创建或推进 MessageDelivery。
- MessageDelivery 再检查授权、consent、opt-out、frequency cap、灰度开关。
- 未授权、未进入灰度或外部渠道关闭时，状态保持 `external_disabled`。
- 发送成功、失败、跳过、回滚都必须回写 MessageDelivery。

MessageDelivery 是企业微信随访触达的状态锚点，不应绕过它直接调用真实渠道。

## 14. 与 timeline / audit / dashboard 的关系

timeline 应记录：

- 授权状态变化的低敏摘要。
- 客户联系同步结果的低敏摘要。
- 人工确认节点。
- MessageDelivery 状态变化。
- 企业微信触达成功、失败、跳过、回滚的低敏结果。

audit 应记录：

- 授权操作人。
- 授权状态变化。
- 同步触发人。
- 触达确认人。
- 灰度开关判断结果。
- 失败原因低敏码。

dashboard 应展示：

- 已授权机构数。
- 授权异常机构数。
- 客户联系同步数量的低敏汇总。
- MessageDelivery 中企业微信触达相关状态计数。
- `external_disabled`、skipped、成功、失败、回滚等低敏汇总。

这些展示不得泄露密钥、客户手机号、聊天记录或供应商原始响应。

## 15. 是否需要先申请企业微信服务商 / 第三方应用

当前不建议立刻盲目申请或接入真实服务商能力。

建议顺序：

1. 先完成方向修正文档，本任务。
2. 再做企业微信授权接入契约文档。
3. 再做本地模拟授权状态模型。
4. 再准备测试企业微信主体。
5. 再评估是否申请企业微信服务商 / 第三方应用。
6. 再做单机构、单员工、单客户、单条消息灰度。

原因是：如果方向未修正，过早申请或接入会把工作带偏到登录、扫码、密钥配置或真实接口联调，而不是客户运营和随访触达闭环。

## 16. 目标 4B / 4C / 4D 后续拆分建议

建议后续拆分如下：

1. 目标 4B：企业微信客户运营接入方向修正与契约规划。
2. 目标 4C：企业微信授权状态本地模拟模型与低敏展示。
3. 目标 4D：单机构、单员工、单客户、单条消息企业微信触达灰度 proof。
4. 后续独立任务：会话内容存档合规方案。
5. 后续独立任务：企业微信服务商 / 第三方应用申请与测试主体准备。

每个任务必须单独授权，不得因为本文档存在就自动开始开发。

## 17. 禁止能力清单

本阶段禁止：

1. 企业微信登录机构端。
2. 用企业微信替代账号密码登录机构端。
3. 员工个人微信好友同步。
4. 普通微信聊天记录同步。
5. 真实会话内容存档接入。
6. 真实企业微信接口接入。
7. 真实短信接入。
8. 真实 HIS 接入。
9. 真实 webhook 接入。
10. 读取或写入真实渠道密钥。
11. 同步真实客户。
12. 同步真实聊天记录。
13. 真实发送消息。
14. 自动营销。
15. 自动群发。
16. AI 自动生成后直接发送给客户。
17. 开始目标 5。

## 18. 是否可以进入开发的判断标准

只有同时满足以下条件，才可以进入后续开发：

- 已确认目标不是企业微信登录。
- 已确认目标是企业微信客户运营接入。
- 已确认多机构授权模式方向。
- 已确认客户联系同步边界。
- 已确认会话内容存档不在目标 4B 直接开发范围内。
- 已确认企业微信触达必须经过人工确认和 MessageDelivery。
- 已确认授权、consent、opt-out、frequency cap、灰度开关、审计和回滚要求。
- 已确认当前不盲目申请企业微信服务商 / 第三方应用。
- 已明确只做本地模拟或测试主体准备，不触达真实客户。
- 已获得用户单独授权进入 runtime 开发。

未获得明确 runtime 授权前，工作只能停留在文档、契约和评审阶段。
