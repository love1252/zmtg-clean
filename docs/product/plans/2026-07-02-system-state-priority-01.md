# ZMTG-SYSTEM-STATE-PRIORITY-01：全系统当前完成状态盘点与下一阶段优先级排序

## 1. 当前系统定位

基线日期：2026-07-02（Asia/Shanghai）

当前 main / origin/main：`1f90aeb3f899006f0d7523f35c2b628e701daf6f`

智美天工当前定位为面向医美 / 美业机构的 AI 客户运营中台。现阶段的重点不是完整 HIS，也不是把现有 HIS、SCRM、支付、财务、客服系统一次性替代，而是围绕机构客户运营、知识库、治疗后跟进、智能随访、平台治理和 AI 用量运营，先形成低敏、可验收、可演示的运营闭环。

因此，当前系统更适合被描述为“医美 / 美业机构的 AI 客户运营与平台治理中台”，不适合被描述为“已接通真实 HIS 的生产级医疗业务系统”。

## 6. 当前主要风险

1. 只读 / mock / demo 边界容易被误认为生产能力，需要在演示和文档中反复标注。
2. 测试库 tunnel 依赖本地 SSH，环境稳定性不等于生产级运维能力。
3. 测试服虽然已有域名和证书，但仍需要正式发布流程、运维检查和回滚预案。
4. 智能随访写入口径未完全闭环，后续如果展示智能随访消耗，必须先补齐归因。
5. 套餐权益与 AI 服务额度尚未联动，当前 `套餐额度暂未接入` 是正确提示，不应伪造成真实剩余额度。
6. 真实 provider 调用和成本核算未验收，不能把 AI Credits 运营统计解释为真实成本账单。
7. 权限体系和机构角色可见范围仍需进一步确认，尤其是机构员工、运营负责人、机构管理员之间的可见差异。
8. 全系统演示路径尚未固定，局部模块通过不代表端到端体验已经稳定。

## 7. 下一阶段优先级排序

### P0：全系统测试服阶段验收和演示路径固定

优先级原因：平台端 AI 用量和机构端 AI 服务使用已经连续收口，继续开发前应先确认测试服整体体验、登录入口、平台端、机构端、客户运营、知识库和 AI 服务使用之间的演示路径是否稳定。

是否建议立即开发：不建议开发新功能，建议立即做验收和演示路径固定。

建议下一刀任务类型：验收 + docs-only 记录。

禁止顺手扩展范围：不得趁验收补功能、改 UI、改 API、执行 migration、调用 provider 或写入业务数据。

### P1：套餐权益 / AI 服务额度联动设计

优先级原因：机构端已经展示 AI 服务使用和 `套餐额度暂未接入`，用户很容易追问额度、剩余次数和套餐扣减。需要先设计口径，避免前端伪造剩余额度。

是否建议立即开发：不建议直接开发，建议先做 docs-only 设计，再拆 API / UI / 验收任务。

建议下一刀任务类型：docs-only，后续可拆 schema/API/UI。

禁止顺手扩展范围：不得直接实现套餐扣减、计费、支付、额度告警或真实账单。

### P1：智能随访 service project 写入口径补齐

优先级原因：智能随访是机构运营核心场景之一，但当前不能宣称智能随访写入口径已完全补齐。若后续要在机构端或平台端展示智能随访消耗，需要先保证写入口径受控。

是否建议立即开发：建议在 P0 后单独立项，不建议和 UI、额度、导出混做。

建议下一刀任务类型：docs-only 口径确认，随后 API / 写入口径 / 测试。

禁止顺手扩展范围：不得新增自动随访业务、不得调用 provider、不得把人工创建随访任务计入 AI 服务使用。

### P1：机构端知识库体验继续完善

优先级原因：知识库是 AI 问答、RAG 问答和客户运营辅助的重要基础，直接影响机构端 AI 服务使用的可解释性和演示价值。

是否建议立即开发：建议先在 P0 后做体验盘点，再决定是 UI 优化、数据态验收还是 API 补强。

建议下一刀任务类型：只读摸底 / 验收，必要时再拆 UI。

禁止顺手扩展范围：不得扩大到真实外部知识源、敏感原文展示、生产级全文治理或 provider 大规模调用。

### P2：额度告警

优先级原因：额度告警依赖套餐权益和真实额度口径，当前基础还不完整。

是否建议立即开发：不建议立即开发。

建议下一刀任务类型：docs-only 设计，等待套餐权益联动口径稳定后再进入 API / UI。

禁止顺手扩展范围：不得伪造剩余额度、不得发送真实通知、不得接入真实短信 / 微信 / 邮件。

### P2：导出能力

优先级原因：平台端和机构端都有用量数据，但当前明确不可宣称导出完成。导出涉及权限、脱敏、审计和格式稳定性。

是否建议立即开发：不建议立即开发。

建议下一刀任务类型：docs-only 设计，后续再拆平台端导出或机构端导出。

禁止顺手扩展范围：不得导出敏感字段、不得输出 provider key、prompt、answer、rawResponse、客户隐私或成本明细。

### P2：真实 provider smoke / 成本口径验收

优先级原因：当前不应宣称真实 provider 调用已验收，也不应宣称真实成本核算。若后续要进入生产前验收，必须有独立 smoke 与成本口径任务。

是否建议立即开发：不建议马上做大规模真实调用，可先设计 smoke 范围和安全阈值。

建议下一刀任务类型：docs-only 安全方案，后续小范围受控 smoke。

禁止顺手扩展范围：不得真实大规模调用 provider、不得写入真实业务数据、不得把测试调用当生产成本依据。

### P3：更多平台运营栏目

优先级原因：平台端 AI 用量 V0.6 已足够支撑当前运营分析，更多栏目应等核心演示链路、套餐权益和智能随访归因稳定后再推进。

是否建议立即开发：不建议立即开发。

建议下一刀任务类型：产品设计 / docs-only。

禁止顺手扩展范围：不得新增复杂 BI、图表化大盘、财务闭环或多方向并行开发。

## 8. 推荐下一刀

建议下一刀优先做：

`ZMTG-SYSTEM-STAGING-ACCEPTANCE-01：全系统测试服阶段验收与演示路径固定`

1. 最近平台端和机构端 AI 用量均已完成。

推荐该任务保持验收和文档性质，不进入新功能开发。
