# 智美天工 V1 知识库与 AI 能力规划 01

任务编号：`ZMTG-V1-KNOWLEDGE-AI-CAPABILITY-PLAN-DOCS-ONLY-01`

生成日期：2026-06-11

本文档用于规划 V1 知识库、AI、平台端 AI 管理、机构端 AI 使用、权限、审计、安全、成本、RAG 边界和后续任务顺序。本文档是 docs-only 规划，不是 runtime 授权，不是上线准备，不是试点授权，也不是后续任务队列。

## 1. 当前阶段结论

- 智美天工不是 HIS 系统。
- 智美天工是面向医美 / 美业机构的 AI 客户运营中台。
- 当前主线是治疗后客户运营闭环。
- 当前已有内部 demo / 局部 runtime 基础，但 V1 主业务闭环仍未真实端到端跑通。
- 当前知识库尚未产品化，平台知识库、机构知识库、内容治理、权限、审计和检索边界仍待规划。
- 当前 AI 能力尚未形成完整 AI 中台，机构端 AI 使用、平台端 AI 管理、成本、安全、审计和知识引用边界仍待规划。
- 当前不能接真实模型、真实客户数据、真实 HIS 或真实 credential。
- 当前不能做自动营销 / 自动触达。
- 本文档是 docs-only 规划，不是 runtime 授权。

## 2. 知识库能力边界

| 类型 | 目标 | 待完成功能 | 权限边界 | 审计边界 | 不允许提前进入的 runtime 内容 |
|---|---|---|---|---|---|
| 平台知识库 | 统一沉淀标准项目、护理、FAQ、SOP、话术、风险提示和合规规则。 | 内容分类、版本、发布、下架、回滚、适用租户范围、平台审核。 | 平台角色可管理，机构只能在授权范围内使用。 | 记录内容变更、审核、发布、下架和回滚的低敏摘要。 | 不直接实现知识库 runtime、检索、索引、embedding、RAG 或真实内容分发。 |

## 3. 平台知识库规划

平台知识库是面向多租户的标准知识来源，目标是提供可治理、可审核、可回滚的标准内容。当前只规划能力，不写实现方案。

| 能力 | 规划内容 | 边界 |
|---|---|---|
| 平台标准项目知识 | 规划标准项目名称、适用场景、护理要点、风险提示和禁用表达。 | 不作为医疗诊断，不承诺疗效。 |
| 术后护理知识 | 规划通用护理注意事项、异常提示和人工复核建议。 | 不替代医生判断，不自动触达客户。 |
| FAQ | 规划平台通用问题、答案、适用范围和低敏说明。 | 不包含真实客户个案。 |
| 标准 SOP | 规划内部操作步骤、人工确认点和风险升级规则。 | 不自动生成任务或预约。 |
| 标准话术 | 规划客服辅助话术、提醒话术和禁止话术。 | 不自动发送外部消息。 |
| 风险提示规则 | 规划风险词、异常场景、人工复核和拒答边界。 | 不做自动医疗判断。 |
| 合规禁用词 / 敏感词 | 规划禁用表达、敏感表达和人工审核规则。 | 不输出促销承诺、疗效承诺或高敏信息。 |
| 内容版本管理 | 规划版本号、变更摘要、有效期和回滚说明。 | 不直接写版本 runtime。 |
| 发布 / 下架 / 回滚 | 规划平台审核后发布、下架和回滚流程。 | 不直接实现内容分发。 |
| 适用租户范围 | 规划内容适用的租户、套餐、地区和能力开关边界。 | 不绕过租户隔离。 |
| 平台审核机制 | 规划编辑、审核、发布和复核责任边界。 | 不把审核缺失内容作为可用知识。 |

## 4. 机构知识库规划

机构知识库是租户内自有知识来源，目标是让机构沉淀内部资料并在授权范围内辅助运营。当前只规划能力，不接真实机构资料或真实客户数据。

| 能力 | 规划内容 | 边界 |
|---|---|---|
| 机构项目资料 | 规划机构自有项目介绍、适用说明、注意事项和禁用表达。 | 不承诺疗效，不替代医疗判断。 |
| 机构价格 / 套餐说明 | 规划价格、套餐、权益和有效期的管理边界。 | 不实现支付、合同或发票能力。 |
| 医生 / 咨询师资料 | 规划人员介绍、专长、可见范围和审核边界。 | 不展示不应公开的人员隐私。 |
| 机构术后注意事项 | 规划机构自有护理说明和异常升级提示。 | 不自动发送客户消息。 |
| 机构服务 SOP | 规划客服、咨询、随访和人工确认流程说明。 | 不自动创建任务或预约。 |
| 机构客服话术 | 规划内部辅助话术、禁用话术和人工复核边界。 | 不自动营销 / 自动触达。 |
| 机构 FAQ | 规划机构常见问题、答案、版本和适用范围。 | 不包含真实客户详情。 |
| 文件上传 | 规划文件来源、格式、权限和审核要求。 | 不处理真实客户数据。 |
| 文档解析 | 规划解析后的低敏摘要、失败 fallback 和人工复核。 | 不直接实现解析 runtime。 |
| 知识审核 | 规划审核角色、审核结论、驳回原因和风险提示。 | 不绕过机构内权限。 |
| 知识发布 / 下架 | 规划机构内发布、停用、下架和回滚机制。 | 不影响平台标准知识。 |
| 机构内角色权限 | 规划查看、编辑、审核、发布和配置权限。 | 不把员工权限当平台权限。 |
| 租户隔离 | 规划知识内容、引用和审计只在租户内生效。 | 不跨租户共享机构知识。 |

## 5. AI 能力边界

| 类型 | 目标 | 必须遵守的边界 |
|---|---|---|
| 机构端 AI 能力 | 为机构人员提供客户运营、治疗后跟进、客服话术和内部任务建议。 | AI 只做辅助建议，输出必须低敏，不得自动触达客户，不得自动医疗判断，不得承诺疗效。 |
| 平台端 AI 管理 | 为平台配置 AI 能力、成本、权限、安全和灰度策略。 | AI runtime 必须另行授权，不接真实模型，不处理真实客户数据。 |
| AI 与知识库结合 | 规划未来基于平台和机构知识的辅助回答、引用和拒答边界。 | 知识引用必须可追踪，AI 不确定时必须拒答或转人工。 |
| AI 审计 / 成本 / 权限 / 安全 | 规划调用记录、权限判断、成本归属、失败记录和安全策略。 | 输出必须可审计，不允许绕过权限、成本和安全策略。 |

AI 输出必须以内部辅助为定位，不得写成自动决策、自动执行或面向客户的自动触达结果。AI runtime 必须另行授权。

## 6. 机构端 AI 能力规划

| 能力 | 规划内容 | 边界 |
|---|---|---|
| AI 客户画像总结 | 辅助总结低敏客户运营状态、阶段和关注点。 | 不使用完整病历、完整联系方式或真实客户原文。 |
| AI 治疗摘要辅助 | 辅助整理治疗后低敏摘要和人工复核要点。 | 不生成医疗诊断。 |
| AI 随访建议 | 辅助提示内部随访方向、风险点和人工确认建议。 | 不自动创建任务，不自动触达客户。 |
| AI 复诊建议 | 辅助识别复诊观察窗口和内部提醒口径。 | 不自动约诊，不同步 HIS。 |
| AI 复购建议 | 辅助说明复购观察理由和人工判断提示。 | 不做成交预测，不自动营销。 |
| AI 沉睡客户唤醒建议 | 辅助解释沉睡观察原因和内部跟进建议。 | 不自动外呼，不自动发送消息。 |
| AI 客服话术辅助 | 辅助生成低敏内部话术建议。 | 必须人工确认，不得直接对外发送。 |
| AI 内部任务建议 | 辅助提出可由人员判断的内部行动建议。 | 不自动创建任务 / 预约 / 成交。 |
| AI 风险提示 | 辅助提示敏感词、合规风险和人工复核点。 | 不替代风控审核。 |
| AI 客户分层解释 | 辅助解释客户运营分层依据。 | 不输出黑箱评分或高敏画像。 |
| AI 运营日报 / 周报 | 辅助生成内部低敏运营摘要。 | 不代表真实经营统计或 BI。 |
| 人工确认机制 | 所有 AI 建议必须保留人工确认边界。 | AI 不直接执行任何业务动作。 |
| 禁止自动触达 | 明确 AI 输出不得直接触达客户。 | 外部消息、营销、外呼必须禁止。 |

## 8. AI 与知识库结合规划

| 能力 | 规划内容 | 边界 |
|---|---|---|
| 平台知识库检索 | 规划 AI 使用平台标准知识作为辅助引用来源。 | 不实现检索 runtime。 |
| 机构知识库检索 | 规划 AI 使用机构自有知识作为租户内辅助引用来源。 | 不跨租户引用。 |
| 混合检索 | 规划平台知识和机构知识的组合引用顺序。 | 不写具体 RAG 策略。 |
| 租户隔离 | 规划检索、引用和审计均按租户隔离。 | 不泄露其他租户知识。 |
| 角色权限过滤 | 规划不同角色能使用的知识范围。 | 不绕过机构内权限。 |
| 知识引用来源 | 规划 AI 输出中保留低敏知识来源摘要。 | 不暴露内部全文或高敏资料。 |
| 知识版本追踪 | 规划引用知识版本和变更追踪。 | 不写版本 runtime。 |
| 检索失败 fallback | 规划未命中时给出低敏空态或转人工。 | 不凭空编造。 |
| AI 不确定时拒答 | 规划不确定、冲突或高风险内容的拒答边界。 | 不输出医疗判断或承诺。 |
| 禁止泄露敏感信息 | 规划禁止泄露真实客户数据、credential、HIS raw payload、DB URL、SQL、stack。 | 不使用真实客户或凭证材料。 |

| 输出字段白名单 | 规划 AI / 知识输出只能包含低敏摘要、建议和人工确认提示。 | 不输出高敏字段或可执行动作。 |

| 敏感词 / 合规词检查 | 规划敏感词、合规词和禁用表达的检查边界。 | 不承诺疗效，不诱导营销。 |
| AI 调用审计 | 规划调用场景、低敏摘要、结果和失败原因。 | 不记录 prompt / completion 高敏全文。 |
| 知识命中审计 | 规划命中知识来源、版本和租户范围。 | 不暴露跨租户知识。 |
| 权限审计 | 规划权限拒绝、角色不足和租户不匹配记录。 | 不泄露对象存在性。 |
| 成本审计 | 规划用量、成本归属、超限和降级记录。 | 不作为真实财务结算。 |
| 失败审计 | 规划模型失败、检索失败、拒答和降级原因。 | 不暴露外部系统错误全文。 |
| 人工确认记录 | 规划人工确认、驳回、修改和转人工摘要。 | 不自动执行客户触达。 |
| 不允许自动营销 / 自动触达 | 明确 AI 和知识输出只能辅助内部人员。 | 不发送消息、不外呼、不自动建任务。 |

## 10. 不得提前进入的能力

本文档不得被解释为以下能力的开发授权：

- 知识库 runtime。
- AI runtime。
- 真实模型接入。
- embedding / 向量库实现。
- RAG runtime。
- UI。
- API / route。
- service / repository / DTO。
- schema / migration / SQL。
- 真实 HIS。
- 真实 credential。
- 真实客户数据。
- 自动营销 / 自动触达。
- 任务 / 预约 / 成交 / 支付 / 合同 / 发票扩展。

## 11. 推荐后续任务顺序

1. 机构端 / 平台端管理能力规划 docs-only。
2. 知识库 test plan。
3. AI capability test plan。
4. 知识库最小只读 slice 候选只读评审。
5. AI 配置最小只读 slice 候选只读评审。
6. 最小知识库 readonly runtime，必须单独授权。
7. 最小 AI 配置 readonly runtime，必须单独授权。
8. AI 与知识库结合 runtime，必须延后并单独授权。

上述顺序只是后续建议，不是自动开发许可。任何非文档任务都必须由用户在新的当前任务中明确授权。

## 12. Go / No-Go 规则

| 类型 | 结论 | 规则 |
|---|---|---|
| docs-only | GO | 可以继续，但只能写明确授权的文档。 |
| read-only | GO | 可以继续，用于复核知识库、AI、安全、审计和权限边界。 |
| test-plan-only | GO | 可以继续，用于定义后续知识库 / AI 测试断言，不实现测试。 |
| test-only | CONDITIONAL-GO | 可以继续，但必须最小，且不得要求生产代码改动。 |
| 知识库 runtime | NO-GO without prerequisites | 必须先有 plan 和 test plan，并由用户单独授权。 |
| AI runtime | NO-GO without prerequisites | 必须先有 plan 和 test plan，并由用户单独授权。 |
| UI / API / DB / schema | NO-GO without approval | 必须单独授权，不得夹带在 docs-only 或 test-only 任务中。 |
| 真实模型 / 真实客户数据 / 真实 HIS / credential | NO-GO without approval | 必须单独授权，并先完成安全、权限、审计和低敏边界规划。 |
