## 1. 总体结论

知识库 V1 当前已经形成完整内部闭环，可以用于内部受控演示、内部验收和产品评审。

当前闭环是：

```text
平台知识库管理
→ 机构授权
→ 文件上传 / 下载 / 归档
→ 文档解析
→ chunk 切分
→ 关键词检索
→ mock embedding
→ 向量检索
→ mock/local QA
→ 引用来源
→ QA 审计写入
→ QA 审计查询
→ QA 用量限制
→ 最终验收缺口文档
```

这条链路覆盖了知识库管理从平台治理、机构可见范围、文件生命周期、解析分块、检索、问答、引用、审计到用量治理的内部产品验证路径。

同时必须明确：当前仍不是生产级 AI 知识库。当前 QA 是 mock/local QA，embedding 是本地 deterministic mock embedding，未接真实第三方 AI、未做 OCR、未做 runtime ingestion、未做训练链路、未接真实第三方向量数据库，也未进入真实客户生产数据场景。

## 7. 权限隔离与安全边界

当前权限隔离以 access context、service 过滤和 repository 条件共同保证。

### tenant 隔离

平台端 API 要求明确 tenant 范围。repository 查询以 `tenantId` 为必要条件，service 再按 tenant 过滤。机构端 tenant 只来自 access context，不信任 query 或 body 中伪造的 tenant。

### institution 隔离

平台端绑定机构可见范围前校验目标机构属于当前 tenant。机构端只读取 access context 中的 `institutionId`，只能查看本机构归属或 `visibleInstitutionIds` 包含本机构的知识库。机构 QA 审计查询同样只使用 access context 中的 tenant / institution。

### scope 隔离

平台端 QA 审计查询要求 platform scope。非 platform scope 调用平台端审计 API 返回 403。机构端 QA 和审计 API 要求 tenant scope 且必须存在 tenantId / institutionId。

### 错误边界

底层异常统一转为固定中文安全错误文案，不向前端暴露数据库连接、SQL、stack、token、secret、真实路径或内部异常详情。

## 13. 下一阶段任务优先级建议

推荐下一阶段优先级如下：

### P0：生产级安全策略与权限矩阵

先补齐 tenant / institution / role / actor / API scope 的权限矩阵，明确每类账号可读、可写、可审计、可导出、可配置的边界。

### P0：真实 AI 接入方案评审

先做方案评审，不直接接入真实 AI。评审内容包括 provider、密钥治理、调用审计、成本预算、熔断降级、prompt / completion 保留策略和数据脱敏。

### P0：QA 质量评估与安全评估

建立 QA 样例集、引用准确率评估、拒答策略、敏感信息检测、人工抽检流程和回归标准。

### P1：浏览器级 E2E

补齐平台端与机构端真实浏览器路径，包括平台授权、机构查看、文件管理、检索、QA、审计查询和超限提示。

### P1：runtime ingestion 预研

只做预研和设计，不直接实现队列、worker、scheduler 或自动索引。需要明确失败重试、死信、幂等、回滚、可观测性和租户隔离。

### P2：OCR / 多格式解析方案评审

OCR、PDF、Word、图片、扫描件解析都应独立评审，先明确数据安全、错误补偿、成本和质量验收标准。
