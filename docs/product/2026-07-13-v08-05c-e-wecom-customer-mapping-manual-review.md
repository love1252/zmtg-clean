# V0.8 05C-E 企业微信客户匹配与人工复核边界契约

## 1. 结论摘要

05C-E 只定义企业微信外部联系人与系统客户档案之间的候选匹配和人工复核契约，不实现同步、匹配运行时、客户关系写入或任何外部对接。

- 本阶段不真实同步外部联系人，不调用企业微信。
- 本阶段不读取会话内容，也不接入会话内容存档。
- 本阶段不连接数据库，不写入真实客户关系。
- 不自动合并客户，不自动覆盖系统客户档案。
- 不把企业微信外部联系人直接写入系统客户档案。
- 不把候选匹配结果当作已确认客户关系。
- 低置信度、冲突和多候选情形必须进入人工复核。

本文中的对象、字段、状态、动作和视图均为规划契约，不代表任何能力已经实现或已接入真实数据。

## 2. 产品目标

后续能力可在本契约约束下，为企业微信外部联系人与系统客户档案建立**低敏候选关系**，并保留人工复核与审计边界。规划目标包括：

- 输出低敏候选关系，而不是写入已确认客户关系。
- 支持人工确认、驳回和需要更多信息三类复核结果。
- 支持识别一个外部联系人对应多个系统客户、或一个系统客户对应多个外部联系人的冲突。
- 支持以低敏审计事件追踪候选生成、复核和阻断结果。
- 为后续 05C-E mock domain、只读 API 与 UI 提供边界；这些后续切片需分别获得授权。

## 3. 非目标范围

本契约不授权下列能力：

- 真实企业微信同步、真实 provider runtime 或 repository。
- 聊天记录读取、会话内容存档接入或会话内容展示。
- 生产、staging 或云数据库连接。
- 自动客户合并、自动覆盖客户档案或写入真实客户关系。
- 真实客户触达、真实发送或自动营销动作。
- 继续 05B 的 `send_result` 查询。
- 使用真实企业微信 API response、未脱敏 webhook payload 或任何凭证作为匹配输入。

## 4. 匹配对象

以下对象只定义规划语义，不构成 schema、数据库、API、repository 或 provider 实现授权。

| 对象 | 规划职责 | 可用于低敏视图或审计的示例字段 | 必须禁止的内容 |
| --- | --- | --- | --- |
| `WeComExternalContactReadonly` | 外部联系人的只读低敏摘要 | 展示名、来源类型、添加日期、备注低敏摘要、外部联系人 digest | 原始 `external_userid`、手机号、聊天内容、原始响应 |
| `SystemCustomerReadonlyCandidate` | 系统客户档案的只读候选摘要 | mock/demo 客户编号、客户低敏摘要、状态摘要 | 真实客户敏感资料、联系方式明文、证件信息 |
| `WeComCustomerMappingCandidate` | 外部联系人与系统客户之间的候选关系 | 候选 digest、匹配状态、置信度区间、原因码、创建时间 | 未复核关系写入、敏感匹配依据 |
| `WeComCustomerMappingReview` | 单个候选的人工复核状态与动作记录 | 复核状态、固定原因码、操作者角色、复核时间 | 敏感自由文本、原始身份标识 |
| `WeComCustomerMappingAuditEvent` | 候选与复核动作的低敏审计记录 | 事件类型、状态前后值、对象 digest、时间、来源类型 | 原始 payload、聊天内容、凭证 |
| `WeComCustomerMappingConflict` | 多候选或相互矛盾的匹配摘要 | 冲突类型、冲突状态、候选 digest、待复核标记 | 可反推身份的原始标识或敏感字段 |
| `WeComCustomerMappingDecision` | 人工复核后的规划决定 | 动作、状态变更、固定 reason code、审计引用 | 直接合并、自动写入真实客户关系或触达授权 |

## 5. 匹配依据与字段边界

本节沿用 05C-A 的字段分类：

| 分类 | 在客户匹配中的使用规则 |
| --- | --- |
| `allow` | 仅可用于本节明确列出的低敏匹配依据、固定状态和低敏摘要展示。 |
| `masked_or_digest_only` | 仅可在受控匹配中使用 digest 或内部不透明引用，不展示原值。 |
| `forbidden` | 不得进入匹配输入、候选输出、审计详情、接口响应或页面。 |

未明确列入 `allow` 或 `masked_or_digest_only` 的字段默认属于 `forbidden`。

### 5.1 允许的低敏匹配依据

后续 mock/demo 规划只能使用下列低敏依据，并且仅用于排序、提示和人工复核：

- 展示名相似度。
- 备注低敏摘要。
- 标签名称。
- 来源类型。
- 添加日期。
- 归属员工摘要。
- 已脱敏 digest。
- mock/demo 客户编号。
- 系统客户低敏摘要。

`digest` 仅可用于受控匹配或内部不透明引用，页面不得展示原始值，也不得借此恢复或推断原始标识。

### 5.2 禁止的匹配依据

下列字段不得进入匹配输入、候选输出、审计详情、接口响应或页面：

- 明文手机号、身份证号或其他证件信息。
- 原始 `external_userid`、原始 `userid`。
- 聊天内容、会话内容存档或其密钥。
- 未脱敏 webhook payload。
- 原始企业微信 API response。
- `secret`、`token`、credential 或其他凭证。

任何敏感字段进入匹配 payload 时必须 fail-closed；匹配输出不能包含禁止字段。未明确列入本节低敏依据的字段默认禁止使用。

## 6. 匹配状态枚举

以下枚举仅定义契约语义，不代表状态机已经实现：

| 状态 | 规划语义 |
| --- | --- |
| `unmatched` | 尚未发现可供人工判断的候选。 |
| `candidate` | 已形成低敏候选，尚未得到人工确认。 |
| `matched` | 已经人工确认的候选匹配；不等于真实客户触达授权，也不等于客户档案已自动合并。 |
| `conflict` | 一个外部联系人对应多个系统客户，或一个系统客户对应多个外部联系人的未决冲突。 |
| `rejected` | 人工驳回的候选。 |
| `manual_review_required` | 依据不足、低置信度或存在需要人工判断的情况。 |
| `needs_more_info` | 当前低敏信息不足，需要补充合规信息后才能继续人工判断。 |
| `stale` | 候选已过期，需重新生成或复核。 |
| `disabled` | 匹配能力被关闭，不能生成或推进候选。 |

## 7. 置信度与冲突规则

- 置信度只能用于候选排序和提示，不得自动确认客户关系。
- 高置信度候选仍必须支持人工确认；不得据此自动合并客户或覆盖客户档案。
- 多个系统客户命中同一外部联系人时，必须标记为 `conflict`。
- 一个系统客户命中多个外部联系人时，必须标记为 `conflict`。
- 标签或姓名相似但缺少足够低敏依据时，必须为 `manual_review_required`。
- 任意敏感字段污染、未知字段或 parser 失败时，必须 fail-closed。
- mock/demo 数据不得与真实客户、真实外部联系人或真实员工数据混用。

## 8. 人工复核动作

规划的人工复核动作如下：

| 动作 | 规划语义与限制 |
| --- | --- |
| `approve` | 确认候选关系，用于后续系统关系的候选确认；不等于真实客户触达授权，不自动合并客户。 |
| `reject` | 驳回候选，不删除原始 mock 外部联系人。 |
| `request_more_info` | 标记需要更多信息；不触发真实同步或外部查询。 |
| `mark_conflict` | 标记一个或多个候选之间的冲突，等待人工处理。 |
| `clear_candidate` | 清除候选关系，不删除 mock 源对象，不写入真实客户档案。 |
| `reopen` | 重新打开已处理候选供人工复核。 |

所有动作必须记录低敏审计。不得提供批量自动 `approve`，也不得通过复核动作直接写入真实客户关系。

## 9. 审计事件契约

规划事件类型：

- `mapping_candidate_generated`
- `mapping_conflict_detected`
- `mapping_manual_review_requested`
- `mapping_approved`
- `mapping_rejected`
- `mapping_more_info_requested`
- `mapping_reopened`
- `forbidden_field_blocked`
- `mapping_provider_disabled`

每个审计事件只允许包含下列低敏字段：

- `tenantId`（内部受控租户引用）。
- `reviewerRole`。
- `action`。
- `reasonCode`（固定枚举）。
- `mappingStatusBefore`。
- `mappingStatusAfter`。
- `candidateDigest`。
- `timestamp`。
- `sourceKind`。
- `mockDemo`。

审计事件禁止包含明文手机号、原始 `external_userid`、原始 `userid`、聊天内容、`secret`、`token` 或原始 API response。

## 10. 机构端只读视图规划

未来机构端只读视图可在获得单独授权后，仅在可验证的同租户、已授权范围内展示下列低敏内容：

- 明确的 mock/demo 标记。
- 外部联系人低敏摘要。
- 系统客户候选低敏摘要。
- 匹配状态与置信度区间。
- 冲突提示与人工复核状态。
- 低敏审计摘要。

机构端不得展示手机号、`external_userid`、`userid`、聊天内容、原始 payload、`secret` 或 `token`。不得提供真实同步、自动合并、自动发送或会话内容入口。

## 11. 平台端治理视图规划

未来平台端治理视图只能展示跨租户治理所需的低敏摘要，不得用全局列表、默认租户或跨租户回退绕过隔离：

- 租户匹配健康状态。
- 候选数量、冲突数量与人工复核待处理数量摘要。
- `forbidden_field_blocked` 数量。
- 低敏审计摘要。
- mock/demo 状态。

平台端不得查看客户敏感明细、原始标识、会话内容或外部原始响应。

## 12. fail-closed 规则

出现以下任何情况时，候选生成、展示和复核推进均必须 fail-closed，并仅允许输出固定、低敏的阻断结果：

- provider 为 disabled。
- tenant authorization 不是 `authorized`。
- 外部能力为 `external_disabled`。
- payload 出现未知字段或敏感字段。
- tenant mismatch。
- mock/demo 数据与真实数据混用。
- 匹配依据不足。
- 多候选冲突尚未处理。
- parser 失败。
- 审计写入条件不满足。

## 14. 进入代码开发前置条件

任何代码开发必须先合并本 docs 契约并获得新的单独授权，且只能满足以下前提后再开始：

- 仅使用可识别、可隔离的 mock/demo 数据。
- 不连接数据库，不调用企业微信，不真实同步外部联系人。
- 不写入真实客户关系，不进入自动合并。
- 不提供真实客户触达或发送入口。
- 保持字段白名单、租户隔离、人工复核、审计和 fail-closed 规则。
