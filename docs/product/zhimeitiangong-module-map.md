## 模块关系

`客户档案 / 患者信息` 是中心对象。

`预约 / 到院` 与 `项目 / 治疗记录` 形成服务履约事实。

`SOP / 流程编排` 基于服务事实生成 `随访任务`、`复诊提醒`、`复购提醒` 和 `沉睡客户唤醒`。

`标签 / 分层`、`AI 辅助沟通` 和 `企业微信 / 微信触达` 服务于客户运营执行。

`HIS 数据接入`、`API / Webhook` 和其他第三方系统接入是数据来源和集成能力，不应替代产品主线。

`运营看板`、`权限 / 租户 / 审计` 是产品化和商业化所需的治理能力。

## V1-SCOPE-LOCK-01 模块判断

- 必须：客户档案、客户中心、客户时间线、预约 / 到院、项目 / 治疗记录摘要、治疗后摘要、随访任务、复诊提醒、基础工作台 / 看板、权限 / 租户 / 审计、平台租户与配额基础、隐私字段白名单。
- 简化：复购提醒、沉睡客户机会、标签 / 分层、SOP、AI 辅助沟通、企业微信 / 微信触达记录、HIS fake / 模拟 / 手工输入。
- 后置：真实 HIS 接入、真实企业微信 / 微信自动触达、API / Webhook、插件化、完整 BI、AI Agent、真实多来源数据接入。
- 待确认：客服工作台 / 客服记录是否进入 1.0，AI 是否真实调用模型，企微 / 微信是否进入试点，OneID / SceneID / Event 是否进入 1.0 基础模型。

## 需要避免的误判

- 不应把 HIS adapter 当成智美天工的核心产品模块。
- 不应把真实外网、真实凭证、scheduler、schema 扩展作为产品主线优先事项。
- 不应因为后续补充了 OneID、SceneID、Event、Webhook、插件化，就默认 1.0 必须实现全部平台能力。
- 不应把 AI 说成已经可以自动替代客服、咨询师或医生。
