### 2.3 异常处理预案

- 如果页面 503，先说明“当前是本地演示环境，数据服务可能需要重新启动”，再刷新或切换备用截图。
- 如果 demo seed 缺失，不在彩排中临时改数据库；记录为阻断问题。
- 如果登录失败，先切换备用账号说明文档和截图，不现场修改认证或代码。
- 如果网络、投屏或字体缩放影响观看，暂停并调整，不把环境问题解释成产品能力边界。
- 如果主线页面加载慢，主讲人先用脚本继续讲业务价值，技术兜底排查环境。

## 4. 彩排路线

### 4.1 15 分钟老板 / 院长版

目标：让老板、院长在短时间内理解“治疗后不漏随访、服务过程可追踪、平台侧可治理”。

| 顺序 | 页面 / 模块 | 演示动作 | 重点话术 |
| --- | --- | --- | --- |
| 1 | 机构工作台 | 登录机构端，从工作台开场。 | “今天先看治疗后运营闭环：客户、预约、随访任务统一进入运营视图。” |
| 2 | 客户中心 | 展示虚构 demo 客户列表。 | “客户不是散落在个人微信或表格里，而是沉淀到可管理的客户中心。” |
| 3 | 沈知夏客户详情时间线 | 打开主线客户 A。 | “客户服务有时间线，预约、治疗摘要、随访任务和审计记录能串起来。” |
| 4 | 治疗摘要管理 | 查看摘要列表和详情。 | “治疗后关键信息被结构化为摘要，不保存完整病历正文。” |
| 5 | active 摘要随访建议 | 查看 active 摘要的建议。 | “系统只给建议，必须人工确认后才创建内部随访任务。” |
| 6 | 智能随访 | 查看来源治疗摘要任务。 | “团队能看到今天谁要跟、为什么要跟、任务来自哪条治疗摘要。” |
| 7 | 机构审计日志 | 展示创建、编辑、作废、任务创建记录。 | “关键操作有审计，方便管理和复盘。” |
| 8 | 平台租户管理 / 商业化健康 / 平台审计 | 切到平台端收尾。 | “平台可看租户、套餐、配额和商业化健康，也能看到平台操作记录。” |

老板 / 院长版必须讲清：

- 治疗后不漏随访。
- 客户服务有时间线。
- 任务来源可追踪。
- 操作有审计。
- 平台可看租户、套餐、配额和商业化健康。
- HIS、企微、AI 是后续路线，当前不承诺已接入。

### 4.2 30 分钟运营负责人版

目标：让运营负责人理解日常工作流：今天谁要跟、为什么要跟、任务来自哪里、哪些动作不能自动发生。

| 顺序 | 页面 / 模块 | 演示动作 | 重点话术 |
| --- | --- | --- | --- |
| 1 | 工作台行动队列 | 查看今日重点和待人工确认动作。 | “运营每天先看今天谁要跟、哪些动作要人工处理。” |
| 2 | 客户中心分层 | 展示客户状态、优先级、负责人和下一步动作。 | “客户可以按治疗后、复诊窗口、高风险、已有来源任务来讲故事。” |
| 3 | 预约中心状态 | 展示面诊、治疗、复诊、取消、待确认。 | “预约只是客户旅程的一部分，不代表真实 HIS 同步。” |
| 4 | 客户详情时间线 | 展示预约、治疗摘要、随访任务、作废节点和审计。 | “服务过程沉淀在一条时间线，方便交接和复盘。” |
| 5 | 治疗摘要查看 / 编辑 / 作废 | 分别展示 active、edited、voided。 | “摘要可以受控修正；作废不是删除，历史仍保留。” |
| 6 | 作废摘要阻断 | 展示作废摘要不能继续生成建议或来源任务。 | “哪些摘要不能继续生成任务，要有稳定阻断。” |
| 7 | 智能随访来源任务 | 查看来源：治疗摘要、来源摘要 ID、建议 key。 | “任务来自哪条治疗摘要要可追踪，建议 key 用于来源追踪和避免重复创建。” |
| 8 | 审计复盘 | 查看机构审计日志。 | “创建、编辑、作废、任务创建和拒绝事件都可复盘。” |
| 9 | 平台端收尾 | 展示租户、套餐、配额、商业化健康和平台审计。 | “平台端只做收尾治理展示，不讲成完整计费后台。” |

运营负责人版必须讲清：

- 今天谁要跟。
- 为什么要跟。
- 任务来自哪条治疗摘要。
- 哪些摘要不能继续生成任务。
- 已有任务不会被系统自动取消。
- 任务不自动触达客户。

## 6. 评分表

评分使用 1-5 分，5 分最好。

| 评价项 | 评分 | 通过标准 | 改进项 |
| --- | --- | --- | --- |
| 主线清晰度 |  | 2 分钟内讲清“治疗后运营闭环”。 |  |
| 开场第一印象 |  | 机构工作台能自然进入业务主线。 |  |
| 客户故事完整性 |  | 至少讲清一个客户从预约到随访任务的过程。 |  |
| 治疗摘要生命周期 |  | 能讲清 active / edited / voided、查看、编辑、作废和历史追溯。 |  |
| 随访建议边界 |  | 明确系统只给建议，必须人工确认，不自动触达。 |  |
| 智能随访可理解性 |  | 运营负责人能看懂任务来源、状态和下一步动作。 |  |
| 审计价值表达 |  | 能讲清关键动作可追踪，且不展示敏感细节。 |  |
| 平台收尾价值 |  | 能讲清租户、套餐、配额、商业化健康和平台审计。 |  |
| 不过度承诺 |  | 未把 HIS、企微、AI、RAG、自动触达、支付等讲成已完成。 |  |
| 异常处理 |  | 503、空态、加载慢或登录异常时能切换话术或备份。 |  |
| 总分 |  | 满分 50 分。 |  |

评分规则：

- 单项低于 3 分必须记录改进项。
- 总分低于 36 分不建议对外演示。
- 出现 HIS、企微、AI、自动触达、支付、合同、发票等过度承诺时，需要重新彩排。
- 出现真实客户信息、真实手机号、身份证号、病历号原文、完整病历正文、图片 / 文件原文等敏感展示时，需要停止彩排并记录阻断问题。
