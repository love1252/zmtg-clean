# V0.8 05B 企业微信客户群发 proof 收口复盘与产品边界

## 1. 结论摘要

05B 已证明：系统可以在受控条件下创建企业微信客户群发任务。企业微信官方能力不是服务端直接私聊客户，而是创建客户群发任务，并由员工在企业微信客户端人工确认发送。

`task_created` 不等于客户已收到。用户反馈已在企业微信客户端人工确认发送给测试客户“烬”，但多轮官方 `send_result` 查询未能唯一匹配本地 task digest。因此系统没有写入 `succeeded`，没有增加 `completedCount`，sidecar 仍保持人工复核状态。

05B 真实 proof 的系统结论是：**真实任务创建完成，人工发送反馈完成，官方结果未闭环，系统成功态未完成。**

## 4. 产品边界

- 当前能力是“客户群发任务创建与受控 proof”，不是“服务端直接私聊客户”。
- 真实发送动作发生在企业微信客户端，由员工人工确认。
- 系统只能在官方结果唯一匹配且 finalize precondition 通过后，才能进入 `succeeded`。
- 在 `send_result` 未匹配时，系统必须保持人工复核或未完成态。
- 默认 provider 必须保持 disabled / fail-closed。
- 不允许把用户口头反馈直接转换为系统成功态。

## 5. 安全事件记录

- B3-A 阶段发生过 `.env.local` 自动加载违规风险：一次 Vite/Vitest 误在仓库根目录运行，可能加载 `.env.local`；未输出值，未外联，未调用企业微信。
- 05B-E 阶段也发生过一次类似早期误运行风险；未输出值。
- 后续涉及测试、build 或 typecheck 时，默认要求在排除 `.env*` 的 `/tmp` 临时镜像中执行，除非任务明确不涉及 Vite、Next 或 Vitest。
- 因此不能写“全程未读取 `.env.local`”，应按阶段如实记录风险事件。

## 6. 后续禁止事项

- 不自动继续查询 `send_result`。
- 不做宽范围轮询。
- 不把 `task_created` 当成 `succeeded`。
- 不把人工反馈当成系统成功态。
- 不绕过 finalize precondition。
- 不绕过 provider_disabled。
- 不直接进入真实外部联系人同步。
- 不直接接入会话内容存档。
- 不直接连接生产、staging 或云数据库。
- 不自动真实发送。
- 不输出 secret。
- 不在仓库根目录运行可能加载 `.env*` 的测试、build 或 typecheck。
