# 智美天工 1.0 范围

> 文档状态：PRODUCT-REBASE-01 初版，范围分级为资料恢复结果，不代表最终开发授权。

## 1.0 建议主线

当前可见资料共同指向：1.0 应优先验证“治疗后客户运营闭环”，而不是优先建设真实 HIS 连接平台。

建议主线为：

`客户档案 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访任务 -> 复诊提醒 -> 客户时间线 -> 运营看板 -> 审计追踪`

## 1.0 必须做

- 客户档案 / 患者档案基础信息。
- 项目 / 治疗记录的运营级记录。
- 预约 / 到院基础状态。
- 治疗后摘要或服务摘要。
- 随访任务创建、确认、执行、完成和沉淀。
- 复诊提醒的基础机制。
- 客户时间线。
- 基础运营看板。
- 权限、租户和审计的基础能力。
- 明确标识数据来源，避免误把模拟或人工录入数据说成真实 HIS 同步。

## 1.0 可以简化

- 客户标签 / 分层：可先支持人工标签、基础分层和少量固定标签。
- SOP / 流程编排：可先支持固定项目模板和固定随访路径。
- 复购提醒：可先做机会提示或待办，不做复杂推荐。
- 沉睡客户唤醒：可先做客户列表和人工召回任务，不做自动触达。
- AI 辅助沟通：可先做话术建议或模拟内容，不做真实 provider、RAG 或 Agent。
- 企业微信 / 微信：可先保留触达建议、触达记录或模拟结果，不做真实连接。
- HIS 数据：可先用人工录入、演示数据或轻量导入，不做真实外网连接。

## 1.0 不做

- 真实 HIS adapter。
- 真实 credential provider。
- 真实外网调用。
- scheduler、runner、worker、queue 等生产同步机制。
- 新 schema 或 migration，除非后续单独批准。
- 真实企业微信 / 微信自动触达。
- 真实短信、电话、营销自动化。
- 自动医疗建议。
- 无人工确认的 AI 决策。
- 完整插件市场。
- 完整 API / Webhook 开放平台。
- 完整 BI 分析平台。

## 后续增强

- OneID 统一身份。
- SceneID 场景标识。
- Event 业务事件体系。
- 标签画像和客户分层模型。
- 可配置 SOP 流程编排。
- API / Webhook。
- 插件化连接器。
- AI Agent。
- 多来源数据接入。
- 企业微信 / 微信真实触达。
- HIS / 第三方系统真实接入。

## 不被真实 HIS 阻塞

1.0 的成败应看客户运营闭环是否跑通，而不是看真实 HIS 是否接通。

HIS 数据可以作为未来增强或试点集成方向，但当前不应继续让 credential provider、HIS adapter、external network、scheduler、audit、schema 等 Phase 24 风险治理任务定义产品主线。

## 待人工确认

- 1.0 是否只面向医美机构，还是覆盖泛美业机构。
- 1.0 是否必须包含复购提醒和沉睡客户唤醒。
- 1.0 标签 / 分层做到什么粒度。
- 1.0 SOP 是固定模板还是轻量可配置。
- 1.0 AI 是否真实调用模型，还是只做产品占位与人工输入。
- 1.0 是否需要任何 API / Webhook 占位。
- 1.0 是否允许模拟 HIS 数据。
- 1.0 演示和试运行是否需要企业微信 / 微信真实接入。
