# 智美天工 1.0 范围

> 文档状态：V1-SCOPE-LOCK-01 锁定版。本文锁定 1.0 产品范围，不代表 runtime 授权。

## 1.0 一句话范围

智美天工 1.0 是面向医美 / 美业机构的 AI 客户运营中台，主线是治疗后客户运营闭环。

1.0 的首要目标不是完整 HIS 接入，不是完整 AI Agent，不是完整 SCRM，不是完整 BI，而是验证机构能否把治疗后的客户服务、复诊复购机会和运营动作稳定跑通。

## V1-SCOPE-LOCK-01 锁定结论

1.0 主线锁定为：

`客户档案 / 患者信息 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访任务 -> 复诊提醒 -> 复购机会 -> 沉睡客户机会 -> 人工确认 -> 基础运营看板 -> 审计追踪`

说明：

- “治疗后客户运营闭环”是 1.0 主线。
- “AI 客户运营中台”是 1.0 正式产品定位。
- 系统主线使用“客户档案”，医疗语境中可显示“患者信息”。
- SCRM 可以作为能力描述，但不是唯一正式产品定位。
- HIS、AI Agent、企微自动触达、开放 API、插件化、完整 BI 都不作为 1.0 阻塞项。

## 1.0 必须做

- 登录 / 租户 / RBAC / 审计。
- 客户中心。
- 客户时间线。
- 预约 / 到院基础记录。
- 项目 / 治疗记录的结构化摘要。
- 治疗后摘要。
- 随访任务。
- 复诊提醒。
- 复购机会轻量提示。
- 沉睡客户机会轻量提示。
- 人工确认机制。
- 基础工作台 / 看板。
- 平台租户与配额基础。
- 隐私字段白名单。
- 当前已有 HIS fake / 模拟 / 手工输入能力的安全保留，并明确不得描述为真实 HIS 同步。

## 1.0 可以简化

- 患者信息先按客户档案的一部分处理。
- 治疗记录只保留摘要，不做完整病历。
- SOP 用静态模板，不做可视化编排器。
- 复诊提醒先做内部任务，不做自动触达。
- 复购机会先做轻量提示，不做自动营销。
- 沉睡客户先做轻量机会识别，不做自动唤醒。
- 标签 / 分层先做轻量规则或状态字段，不做完整画像系统。
- 看板先做少量聚合指标，不做完整 BI。
- AI 辅助可以先做占位、草稿或人工辅助，不做自动决策。
- 企业微信 / 微信可以先做触达建议或记录，不做真实自动发送。
- HIS 数据可以先通过 fake / 模拟 / 手工输入，不做真实连接。

- schema / migration 扩张，除非后续 PROD-GAP-REVIEW-01 明确发现 1.0 必须项缺失并单独批准。
- 自动微信 / 企微 / 短信 / 电话触达。
- AI 自动客服。
- AI 自动医疗建议。
- AI Agent 自动执行。
- RAG / Agent 生产能力。
- 完整病历 / 图片文件 / 医疗影像管理。
- 支付 / 合同 / 发票。
- 开放 API / OAuth / Webhook 生产能力。
- 插件市场 / 连接器市场。
- 完整经营 BI / 复杂报表中台。
- 多来源真实数据接入生产能力。

## 不被真实 HIS 阻塞

1.0 的成败应看客户运营闭环是否跑通，而不是看真实 HIS 是否接通。

HIS 数据可以作为未来增强或试点集成方向，但当前不应继续让 credential provider、HIS adapter、external network、scheduler、audit、schema 等 Phase 24 风险治理任务定义产品主线。

1.0 不进入真实 HIS runtime，不进入自动触达，不进入 AI 自动决策。
