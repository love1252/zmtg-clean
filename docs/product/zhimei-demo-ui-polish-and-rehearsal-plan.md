## 2. UI 小打磨原则

UI 小打磨只服务演示顺畅度，不改变业务能力边界。

| 原则 | 说明 |
| --- | --- |
| 围绕主线 | 只打磨演示主线上的页面和状态，不扩展占位页面。 |
| 少讲工程阶段 | 页面上减少 `Phase`、内部代号、工程化标题和测试感文案。 |
| 强化业务叙事 | 文案优先解释客户、治疗、随访、审计和配额的业务价值。 |
| 明确人工确认 | 所有随访建议相关文案都必须强调“建议仅供内部参考，需要人工确认”。 |
| 明确不自动触达 | 不出现让人误解为自动发微信、短信、电话、企业微信或 AI 自动客服的表达。 |
| 保持安全边界 | 不展示 `tenantId`、真实手机号、身份证号、病历号原文、完整治疗记录正文、完整病历正文、咨询全文、图片 / 文件原文、SQL、stack、token、secret、`DATABASE_URL` 或连接串。 |
| 保持只读与写入边界 | 平台侧不暗示已支持租户创建、冻结、恢复、删除、计费、合同或发票。机构侧不暗示已支持完整病历、图片文件或外部系统同步。 |
| 不引入新能力 | 后续 UI PR 不新增 API、不改数据库、不改权限、认证或租户隔离。 |
| 控制变更粒度 | 每个 UI PR 只打磨少量页面，便于 smoke 回归和演示复盘。 |

## 3. 优先打磨页面

优先级按演示出现顺序和客户感知风险排序：

| 优先级 | 页面 | 为什么优先 |
| --- | --- | --- |
| P0 | 机构工作台 | 演示开场页面，决定第一印象和主线入口。 |
| P0 | 客户中心 | 承接“客户资产统一沉淀”，需要减少列表测试感。 |
| P0 | 客户详情时间线 | 最能体现客户服务连续性，是老板和运营负责人都要看的核心页面。 |
| P0 | 治疗摘要管理 | 承接录入、查看、编辑、作废、随访建议和来源治理，是演示中段核心。 |
| P0 | 智能随访 | 展示今天谁要跟、为什么要跟、任务来源是什么。 |
| P1 | 预约中心 | 用于补足客户旅程，不应喧宾夺主。 |
| P1 | 机构审计日志 | 展示操作可追踪，需减少技术噪音。 |
| P1 | 平台租户管理 / 商业化健康 | 展示 SaaS 管控、套餐和配额，不讲成完整计费后台。 |
| P1 | 平台审计日志 | 平台治理收尾页面，强调可审计和安全边界。 |
| P2 | 登录页 / 演示账号提示 | 只在内部彩排必要时轻量调整，不作为演示价值重点。 |

不优先打磨：

- 客服工作台
- 知识库
- 数据分析
- Open Platform 愿景页
- 开放连接中心
- 产品与套餐占位页
- 任何容易被误解为 HIS、企微、AI、支付或完整经营智能中心已完成的入口

## 4. 每个页面的打磨目标

| 页面 | 打磨目标 | 保持边界 |
| --- | --- | --- |
| 机构工作台 | 开场即展示“今日客户、预约、待处理随访、行动队列”，标题和空态更像真实机构运营入口。 | 不讲完整经营智能中心，不新增指标口径。 |
| 客户中心 | 让客户列表更容易讲出客户画像、状态、负责人和下一步动作。 | 不展示真实手机号、身份证、病历号原文或完整咨询内容。 |
| 预约中心 | 让面诊、治疗、复诊、取消、待确认等状态更适合口头串联。 | 不承诺已接真实 HIS 预约同步。 |
| 客户详情时间线 | 强化预约、治疗摘要、随访任务、作废状态和审计节点的连续故事。 | 不保存完整病历、完整治疗记录、图片或文件原文。 |
| 治疗摘要管理 | 摘要列表、详情、编辑、作废、随访建议和重复来源任务提示更容易被演示者解释。 | 作废不是删除；作废后不自动取消既有任务，不自动触达客户。 |
| 智能随访 | 让运营负责人一眼看懂“今天谁要跟、任务从哪里来、状态如何”。 | 不讲自动发微信、短信、电话、企微或 AI 自动客服。 |
| 机构审计日志 | 让创建、编辑、作废、任务创建和拒绝事件适合管理复盘。 | 不展示请求体、敏感字段或服务端错误细节。 |
| 平台租户管理 / 商业化健康 | 展示星澜医美中心套餐、配额、使用率和商业化健康信号。 | 不讲成支付、合同、发票或完整计费后台。 |
| 平台审计日志 | 展示平台管理员操作和拒绝事件可追踪。 | 平台可展示受控 `tenantId` 筛选，但不扩大机构端租户可见范围。 |

## 5. 页面文案规则

文案应使用机构老板、院长和运营负责人能直接理解的业务语言。

推荐表达：

- “治疗后随访建议”
- “人工确认后创建内部随访任务”
- “来源：治疗摘要”
- “作废摘要仅保留历史追溯”
- “不会自动取消既有任务”
- “不会自动触达客户”
- “操作可审计”
- “配额快照仅作运营参考”

避免表达：

- “Phase 14 / Phase 15 / Phase 16 / Phase 19”
- “mock records”
- “真实接入 AI”
- “自动营销”
- “自动发微信”
- “自动外呼”
- “已接 HIS”
- “已接企微”
- “完整经营智能中心”
- “完整病历管理”
- “支付 / 合同 / 发票已完成”

当必须保留技术缩写时，应放在边界说明中，避免成为主标题。API、HIS、CRM、SCRM、AI、RAG、Webhook、OAuth、demo、seed、smoke 可以保留英文，但不能暗示对应能力已经接入。

错误态文案应稳定、克制、可演示：

| 场景 | 推荐文案方向 |
| --- | --- |
| 403 | 当前账号没有访问该页面的权限。 |
| 503 | 数据服务暂时不可用，请稍后刷新或切换演示备份。 |
| 空列表 | 当前没有可展示的记录，可在 demo seed 数据准备后复查。 |
| 作废摘要 | 该治疗摘要已作废，仅保留历史追溯，不再作为后续运营依据。 |
| 重复来源任务 | 该建议已有进行中的随访任务，请在智能随访中继续处理。 |
| 配额风险 | 配额快照用于运营参考，不作为当前页面的强一致创建拦截说明。 |

## 6. 内部彩排清单

彩排前检查：

- 本地 dev server 可启动。
- 数据库或本地数据服务可用。
- demo seed 数据已存在，且主演示租户为“星澜医美中心”。
- 机构演示账号可登录。
- 平台演示账号可登录。
- 浏览器清理旧登录态和无关标签页。
- 演示脚本、不可承诺清单和备用截图已打开。
- 网络、投屏、字体缩放和浏览器窗口尺寸已确认。

数据检查：

- 客户中心有沈知夏、叶舒颜、顾安然、许若宁、唐以沫等可讲故事的虚构客户。
- 预约中心有面诊、治疗、复诊、取消或待确认预约。
- 治疗摘要管理有 active、已编辑、已作废、有风险等级、有 nextCareAction 的摘要。
- 至少一个 active 摘要可以展示随访建议并人工确认创建任务。
- 至少一个已作废摘要可以展示阻断建议和阻断来源任务创建。
- 智能随访有来源为治疗摘要的任务，并能展示待处理、超时、已完成或处理中状态。
- 客户详情时间线可以展示预约、治疗摘要、随访任务、作废节点和审计记录。
- 机构审计日志有创建、编辑、作废、任务创建、拒绝或配额拒绝事件。
- 平台端可展示租户、套餐、配额、商业化健康和平台审计。

路线检查：

1. 机构工作台开场。
2. 进入客户中心，打开主线客户详情时间线。
3. 展示预约和治疗摘要如何进入客户过程。
4. 进入治疗摘要管理，展示详情、编辑、作废和阻断。
5. 对 active 摘要查看随访建议并人工确认创建任务。
6. 进入智能随访，展示任务来源和状态。
7. 回到客户详情时间线，展示过程沉淀。
8. 打开机构审计日志，展示关键操作可追踪。
9. 切到平台端租户管理，展示套餐、配额和商业化健康。
10. 打开平台审计日志收尾。

边界检查：

- 不点击客服工作台、知识库、数据分析等占位入口，除非明确说明“当前不作为演示主线”。
- 不讲已接真实 HIS。
- 不讲已接企微。
- 不讲 AI 自动客服、RAG 问答或自动决策。
- 不讲自动发微信、短信、电话或企业微信。
- 不讲支付、合同、发票已完成。
- 不展示真实客户、真实手机号、身份证、病历号、图片、文件或完整医疗正文。

异常预案：

- 如果 503，先说明当前是本地演示环境，再刷新或切换备用截图。
- 如果数据不完整，不在客户面前临时改数据库或代码。
- 如果页面加载慢，主讲切到演示脚本文档继续讲业务主线。
- 彩排后记录异常页面、复现步骤、出现时间和是否阻断演示。

## 7. 彩排角色

| 角色 | 人员职责 | 关注点 |
| --- | --- | --- |
| 主讲人 | 按 15 分钟老板版和 30 分钟运营版各讲一遍。 | 节奏、话术、页面切换、边界表达。 |
| 老板 / 院长扮演者 | 从增长、复诊、二消、团队执行角度提问。 | 是否少讲技术、多讲经营价值。 |
| 运营负责人扮演者 | 从今天谁要跟、任务来源、重复任务、作废处理角度提问。 | 是否能解释日常工作流。 |
| 产品观察员 | 记录页面卡顿、占位感、文案误导和不顺畅步骤。 | 后续 UI 小打磨清单。 |
| 技术兜底 | 负责 dev server、数据库、账号、浏览器和备用截图。 | 环境稳定性，不现场改代码。 |
| 边界审查员 | 盯住 HIS、企微、AI、自动触达、隐私和试点承诺。 | 是否出现过度承诺。 |
| 记录员 | 记录问题、评分、结论和后续 PR 建议。 | 输出彩排复盘。 |

建议至少完成两轮彩排：

- 第一轮：15 分钟老板版，重点看第一印象和价值表达。
- 第二轮：30 分钟运营负责人版，重点看路径完整性和页面细节。
