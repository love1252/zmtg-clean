# 智美天工后期功能补充

> 文档状态：PRODUCT-REBASE-01 初版，所有后期功能均需后续单独确认，不构成本轮实现许可。

## 功能补充清单

| 功能设想 | 当前状态 | 是否进入 1.0 | 风险边界 | 备注 |
| --- | --- | --- | --- | --- |
| OneID | 待人工确认 | 倾向后续增强 | 可能牵涉跨来源身份合并、匹配规则和数据治理 | 可作为统一客户身份方向 |
| SceneID | 待人工确认 | 倾向后续增强 | 需要定义场景范围、事件归属和追踪粒度 | 可用于咨询、预约、治疗、随访、复诊、复购等场景 |
| Event 业务事件体系 | 已确认方向，范围待确认 | 1.0 可简化，完整体系后续增强 | 可能牵涉事件模型、幂等、审计和数据生命周期 | 当前产品主线需要业务事件思维，但不等于马上做开放平台 |
| 标签画像 | 已确认方向，范围待确认 | 可简化纳入 | 需避免过度算法化和黑箱决策 | 1.0 可先人工标签、基础分层、运营画像 |
| SOP 流程编排 | 已确认方向，范围待确认 | 可简化纳入 | 复杂编排器会放大实现和配置风险 | 1.0 可先固定模板和项目路径 |
| API / Webhook | 待人工确认 | 倾向不进入 1.0 | 牵涉签名、鉴权、幂等、审计、限流和外部网络 | 可后置为开放集成能力 |
| 插件化 | 待人工确认 | 不进入 1.0 | 牵涉连接器生命周期、权限、配置和运维 | 可作为长期平台化方向 |
| AI Agent | 待人工确认 | 不进入 1.0 或仅保留概念 | 牵涉自动化边界、人工确认、医疗合规和审计 | AI 当前更适合做辅助沟通和建议 |
| 多来源数据接入 | 已确认方向，范围待确认 | 1.0 可用模拟或轻量导入 | 真实多来源接入牵涉凭证、外网、映射和同步 | HIS、微信、企微、点评等都属于来源方向 |
| 企业微信触达 | 已确认方向，范围待确认 | 倾向 1.0 简化或后置 | 真实触达牵涉账号、授权、消息合规和回执 | 1.0 可先做触达建议或记录 |
| HIS / 第三方系统接入 | 已确认方向，但不是产品主线 | 1.0 不应被真实接入阻塞 | 真实接入牵涉凭证、adapter、external network、scheduler 和 schema | 可作为后续试点或单独审批事项 |

## 状态说明

- “已确认方向”表示当前仓库资料中反复出现，属于产品演进方向。
- “待人工确认”表示无法从可见资料中判断是否进入 1.0 或如何落地。
- “后续增强”表示不建议作为 1.0 闭环验证的必要前置。
- “暂不做”仅能由后续人工决策明确，本文件不替用户冻结最终取舍。

## 与产品主线的关系

后期补充功能应服务于客户运营主线，而不是替代主线。

OneID、SceneID、Event、API / Webhook、插件化和 AI Agent 可以增强系统平台化能力，但 1.0 仍应优先回答：医美 / 美业机构能否围绕客户档案、治疗记录、随访、复诊、复购和运营看板形成可执行闭环。
