# V1-DASHBOARD-EMPTY-STATE-COPY-01：基础运营看板空态与异常态文案契约

## 1. 背景与目标

本契约任务编号为 V1-DASHBOARD-EMPTY-STATE-COPY-01，任务性质为 docs-only / copy-contract。任务日期来自本地命令 `date "+%Y-%m-%d"`，结果为 2026-06-09；时区来自本地命令 `date "+%Z %z"`，结果为 CST +0800。

本文档基于智美天工 1.0 产品事实源和已完成 V1 契约。智美天工不是 HIS 系统。智美天工 1.0 是面向医美 / 美业机构的 AI 客户运营中台，主线是治疗后客户运营闭环。HIS 只是数据来源之一，不是系统主线，不阻塞 1.0。

本文档只定义基础运营看板相关文案口径，覆盖空态、异常态、demo / seed / mock 标记、试运行提示、三类机会、人工确认入口、指标下钻和客户时间线提示。本文档不修改 UI，不实现 dashboard runtime，不写 SQL，不写聚合函数，不做完整 BI。

本文档用于后续 UI-only / mock-only / copy-only 小 PR 的文案依据。后续如需把文案应用到页面、mock、测试或 runtime，必须由用户另行明确授权。

## 3. 文案设计原则

1. 文案服务治疗后客户运营闭环。
2. 文案必须避免把看板解释成 HIS。
3. 文案必须避免把指标解释成真实触达。
4. 文案必须避免把指标解释成成交。
5. 文案必须避免把指标解释成医疗效果。
6. 文案必须明确 demo / seed / mock 数据不是生产数据。
7. 文案必须明确试运行口径不是最终产品阈值。
8. 文案必须使用“客户”为主称呼，“患者信息”仅作医疗语境补充。
9. 空态文案不能误导为所有历史事项都已完成。
10. 异常态文案不能暴露高敏信息、raw payload、SQL、堆栈或外部错误全文。
11. 文案只描述内部运营状态，不触发任何动作。
12. 后续 UI 修改必须单独授权。

补充原则：

- 内部随访任务只表示机构内部工作项，不等于客户已收到消息。
- 预约意向只表示内部预约方向，不是真实预约，也不是 HIS 同步。
- 人工确认只表示内部人员选择处理方向，不代表客户已被触达。
- 看板提示只解释指标和入口，不得写成数据校验、修复或自动执行能力。
- 异常态只能提示“来源不完整 / 口径试运行 / 需人工确认”，不得透出请求体、响应体、连接串、错误全文或服务端堆栈。

## 17. 缺口与风险

### P1

- 看板空态文案不统一导致误读风险：如果“暂无”没有说明只代表当前人工处理范围，容易被理解为历史任务全部完成。
- demo / seed / mock 被误认为生产数据风险：当前看板已有受控 demo 指标，如果后续没有统一标记，演示指标可能被误读为生产经营结果。
- 指标被误读为成交 / 触达 / 医疗效果风险：复购、预约意向、完成等文案若不收口，容易被写成真实成交、真实预约或医疗效果。
- 异常态泄露高敏信息风险：来源缺失、状态异常或外部系统错误如果直接展示全文，可能泄露 raw payload、SQL、堆栈、凭证或高敏客户信息。

### P2

- 试运行阈值未说明导致产品误解风险：沉睡阈值、复购窗口和复诊规则如果不标注试运行，容易被误认为最终生产规则。
- 后续 UI-only PR 没有文案依据风险：复诊、复购、沉睡、人工确认、客户时间线和指标下钻可能各自写文案，导致口径不一致。
- 指标下钻空态不清风险：没有可展示低敏明细时，用户可能误解为系统异常或要求导出完整客户明细。

### P3

- 客户称呼和患者信息称呼仍需后续 UI 细化：主称呼应使用“客户”，医疗语境可补充“患者信息”。
- HIS 入口既有文案可能继续放大 HIS 误主线风险：后续如做 UI 文案应用，需要继续说明 HIS 不是 1.0 主线。
- 审计提示文案仍需后续测试计划细化：本文只定义文案契约，不替代 V1 审计测试计划。
