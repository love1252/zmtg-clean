# 智美天工标准演示脚本

> 状态：产品演示脚本文档。本文用于 Phase 5-19 已完成能力的内部产品演示和受控外部机构演示；不代表 Phase 20 已启动，不包含新功能开发需求。

## 1. 演示定位

当前系统适合做内部产品演示，也适合做受控的外部机构演示。演示对象可以是机构老板、院长、运营负责人、咨询主管和客服主管。

当前暂不建议直接进入真实机构试点。试点前仍需要补齐 demo seed 数据、演示脚本、演示路径 UI 打磨、试点边界、隐私说明、真实业务路径模板、触达闭环和经营报表。

本轮演示重点是“治疗后运营闭环”：

```text
客户进入系统
↓
预约 / 治疗
↓
录入治疗摘要
↓
治疗摘要可管理、可编辑、可作废
↓
系统给出随访建议
↓
人工确认创建随访任务
↓
任务进入智能随访
↓
客户详情时间线沉淀全过程
↓
审计日志保证可追踪
↓
平台端查看租户、套餐、配额和商业化健康
```

演示时不要把当前能力讲成完整 HIS / 企微 / AI / 自动触达 / 经营智能中心。可以讲长期路线，但必须明确当前版本不承诺已完成真实接入或自动触达。

## 4. 机构老板版话术

老板视角不要先讲技术，要先讲经营动作：

> 智美天工现在先帮机构解决“治疗后不漏随访”的问题。客户做完项目后，系统里会有治疗摘要，系统可以给出随访建议，但不会自动打扰客户，必须由员工确认后才会生成任务。

> 这样老板可以看到：客户有没有被跟进，治疗后的服务有没有标准化，任务是谁创建的，谁处理的，哪些操作有审计。未来复诊和二消机会也可以基于这些沉淀继续分析。

> 后续系统可以沿着 HIS 和企业微信方向继续接入真实治疗、消费和触达数据，但当前演示不承诺已经接入真实 HIS 或企业微信，也不承诺自动发消息。

老板版关键词：

- 治疗后不漏随访。
- 客户服务可追踪。
- 治疗摘要可录入、查看、编辑、作废。
- 员工动作有审计。
- 复诊和二消机会未来可分析。
- 后续可接 HIS / 企微，但当前不承诺已接入。

## 5. 运营负责人版话术

运营负责人关心的是每天怎么排事、怎么防漏、怎么复盘：

> 运营每天进来先看今天谁要跟。智能随访里会展示待处理、超时、已完成任务，也能看到任务来源。如果任务来自治疗摘要，系统会标记来源，避免同一条摘要反复创建重复任务。

> 治疗摘要管理页用于集中处理治疗后的摘要。摘要可以查看详情、编辑修正，也可以作废。作废后的摘要仍保留历史，但不能继续生成新的随访建议，也不能继续创建新的来源任务。

> 客户详情时间线能把预约、治疗摘要、随访任务、作废状态和审计记录串起来。运营负责人可以用它复盘客户服务过程，发现漏跟、重复跟和处理不及时的问题。

运营负责人版关键词：

- 今天谁要跟。
- 哪些客户处于治疗后。
- 哪些治疗摘要需要处理。
- 哪些随访任务来自治疗摘要。
- 哪些任务不能重复创建。
- 哪些操作有记录。

## 6. 演示问答表

| 问题 | 标准回答 |
| --- | --- |
| 能不能接 HIS？ | 这是长期路线之一。当前已经有标准治疗事件模型作为技术地基，但本次演示不承诺已经接入真实 HIS，也不展示真实 HIS 同步。 |
| 能不能接企业微信？ | 后续可以作为试点方向评估。当前系统不会自动发企业微信，也不承诺已完成企业微信接入。 |
| 能不能自动发微信？ | 当前不自动发微信、短信、电话或企业微信。系统先生成建议和任务，由员工人工确认和执行。 |
| 能不能自动回复客户？ | 当前没有 AI 自动客服，也没有自动回复客户。未来如接 AI，也必须有人审阅和合规边界。 |
| 能不能看复诊率 / 二消率？ | 当前可以演示治疗摘要、随访任务和来源追踪，完整复诊率、二消率和路径分析还需要后续经营报表和业务事件体系。 |
| 能不能导入老客户？ | 当前演示不承诺批量导入老客户。后续可以评估手工导入或模拟 HIS 输入，但必须避免真实隐私原文泄露。 |
| 数据安全吗？ | 当前系统的设计重点包含租户隔离、RBAC、DTO 白名单、PII 防泄露和审计。真实试点前仍需要单独确认数据范围、账号权限和合规边界。 |
| 能不能管理完整病历？ | 当前不做完整病历管理，也不保存完整治疗记录正文。治疗摘要只保留后续运营所需的结构化信息。 |
| 能不能上传照片？ | 当前不支持图片 / 文件原文管理，也不建议在演示阶段引入真实图片或文件。 |
| 怎么收费？ | 当前可以展示套餐、配额和商业化健康视图，但不承诺已完成支付、合同、发票和正式计费流程。 |
| 多久能上线？ | 当前适合演示和受控评估。真实试点前建议先完成 demo seed 数据增强、演示路径 UI 打磨、隐私边界和试点准备清单。 |

## 7. 不可承诺清单

演示时不能说以下能力已经完成：

- 真实 HIS 接入。
- 企业微信接入。
- 自动发微信 / 短信 / 电话。
- AI 自动客服。
- RAG 知识库问答。
- 完整经营智能中心。
- 自动识别所有客户身份。
- 支付 / 合同 / 发票。
- 完整病历管理。
- 图片 / 文件原文管理。

推荐说法：

> 当前版本重点验证治疗后运营闭环、任务来源治理、审计和套餐配额管理。HIS、企微、AI、自动触达、经营智能中心属于后续路线，不能在演示中承诺已经完成。

## 8. 演示前检查清单

### 环境检查

- dev server 是否启动。
- 数据库或本地数据服务是否可用。
- 机构演示账号是否可登录。
- 平台演示账号是否可登录。
- 浏览器是否清理了不必要的旧登录态。

### 数据检查

- demo 数据是否存在。
- 客户中心是否有 5-8 个可讲故事的客户。
- 预约中心是否有面诊、治疗、复诊、取消或待确认预约。
- 治疗摘要管理页是否有 active、已编辑、已作废、有风险等级、有 nextCareAction 的摘要。
- 客户详情时间线是否可打开，并能展示预约、治疗摘要、随访任务、作废节点和审计记录。
- 智能随访是否有来源为治疗摘要的任务。
- 是否存在一个作废摘要阻断随访建议 / 阻断创建任务的场景。
- 平台端租户、套餐、配额、商业化健康是否可展示。

### 路线检查

- 先演示机构工作台，再演示客户中心和客户详情。
- 治疗摘要管理页要展示录入、详情、编辑、作废和随访建议。
- 智能随访只展示任务和来源治理，不讲自动触达。
- 平台端只展示租户、套餐、配额、商业化健康和审计。

### 不要点击的页面

- 客服工作台。
- 知识库。
- 数据分析。
- AI 模型相关愿景页面。
- 开放连接中心。
- 计费与订单。
- 任何容易让外部用户误解为已完成 HIS / 企微 / AI / 支付的页面。

### 503 或本地数据服务异常处理

- 先确认 dev server 和数据库服务是否启动。
- 刷新当前页面前，先说明“当前是本地演示环境，数据服务可能需要重新启动”。
- 不在外部客户面前临时修改代码或数据库。
- 如果短时间无法恢复，切换到演示文档和截图备份，继续讲业务主线。
- 会后记录异常页面和错误时间，作为演示环境稳定性问题处理，不把它解释成产品能力边界。
