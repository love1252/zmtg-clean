## 一句话定位

智美天工是面向医美 / 美业机构的 AI 客户运营中台，不是 HIS 系统，也不是单纯 CRM 或 AI 聊天工具。

V1-SCOPE-LOCK-01 锁定后，1.0 正式定位优先使用“AI 客户运营中台”。SCRM 可以作为能力描述，但不作为唯一正式产品定位。

## 服务对象

- 医美机构经营者、院长、门店负责人。
- 咨询师、客服、运营人员、复诊复购负责人。
- 需要统一客户运营、随访、复诊、复购和沉睡客户唤醒流程的美业机构。
- 平台侧运营、租户管理、套餐配额和审计治理人员。

## 核心业务价值

智美天工的核心价值是把医美 / 美业机构分散在客户档案、预约、治疗、咨询、随访、复诊、复购和外部触达渠道中的信息，沉淀为可执行、可追踪、可审计的客户运营闭环。

当前可见资料中最稳定的产品主线是：

`客户进入系统 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访建议 -> 人工确认任务 -> 智能随访 -> 客户时间线 -> 运营看板 -> 审计追踪`

V1-SCOPE-LOCK-01 锁定 1.0 主线为：

`客户档案 / 患者信息 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访任务 -> 复诊提醒 -> 复购机会 -> 沉睡客户机会 -> 人工确认 -> 基础运营看板 -> 审计追踪`

1.0 范围来源以 `docs/product/zhimeitiangong-v1-scope.md` 为准。

## 医美 / 美业 / 机构运营的位置

医美 / 美业场景是产品主场景，机构运营是系统主线。系统关注的不是单次治疗记录本身，而是围绕治疗前后形成的客户关系经营、复诊复购、服务质量、运营效率和可追踪合规。

## HIS 的位置

HIS 是重要的数据来源和未来连接对象之一，但不是智美天工的产品主线。

V1-SCOPE-LOCK-01 锁定：HIS 是数据来源之一，不是 1.0 主线，不阻塞 1.0。

在当前可见资料中，HIS 的合理位置是：

- 提供预约、治疗、消费、项目、客户或患者相关数据。
- 作为多来源数据接入的一类外部系统。
- 支撑客户运营闭环的数据补全，而不是替代客户运营中台。
- 1.0 可用模拟数据、人工录入或轻量导入先完成闭环验证。

当前不应把真实 HIS 连接、真实凭证、真实外网调用、生产级 HIS adapter、scheduler 或 schema 扩展作为产品事实源的前置条件。

1.0 可安全保留已有 HIS fake / 模拟 / 手工输入能力，但不得描述为真实 HIS 同步或真实 HIS 健康探测。

## AI 的位置

AI 在智美天工中是辅助客户运营的能力，不是自动替代人工决策的主体。

V1-SCOPE-LOCK-01 锁定：AI 是建议、草稿、标签、提醒、运营洞察和低风险 SOP 回复草稿的辅助能力，必须保留人工确认，不做自动医疗决策。

当前可见资料中，AI 更适合承担：

- 随访话术建议。
- 客户沟通辅助。
- 治疗后关怀内容辅助。
- 标签画像、客户分层、复诊复购机会提示的辅助分析。
- 后续可演进为 AI Agent，但需要单独确认边界、风险、审计和人工确认机制。

截至 V0.3，系统已具备基于平台端 provider 配置的真实模型低敏试问、AI 用量记录和平台端用量聚合。但这仍是受控体验能力，不等于完整 AI 客服、RAG、AI Agent、自动医疗建议或自动触达能力。

1.0 不做 AI 自动客服、AI 自动医疗建议、AI Agent 自动执行或 RAG / Agent 生产能力。

### AI 多厂商与真实调用基线（2026-06-27 更新）

截至 2026-06-27，项目已从 2026-06-19 的只读配置和 dry-run smoke，推进到 V0.3 受控真实调用闭环：

- **平台端 provider 配置**：真实厂商配置从 `platform_ai_provider_configs` 读取，凭证经服务端加密和解密边界处理。
- **真实低敏模型调用**：机构端知识库页面可发起低敏 AI 试问，服务端真实调用已配置厂商模型。
- **高敏输入拒绝**：身份证、病历全文、支付、合同、密钥等高敏内容在调用前被拒绝。
- **用量记录**：记录租户、机构、操作者、provider、model、token 用量、状态和时间。
- **平台端聚合**：平台端可按租户查看 AI 调用次数、成功 / 失败次数和 token 总量。
- **知识库上传解析**：机构端支持 `.txt`、`.md`、`.csv`、`.json` 上传解析和片段查看。

### AI 安全边界

当前 AI 相关能力必须遵守以下安全边界：

- 低敏字段：只展示模型名称、厂商、配置状态、用量摘要等低敏信息。
- 不泄露 secret：AI Provider Key 经服务端加密底座保护，前端不展示凭证明文、`credentialRef`、API Key 原文、`baseUrl`、`Authorization` 或环境变量。
- 不保存完整请求体：用量记录不应保存 API Key、`baseUrl`、`Authorization`、完整请求体或高敏正文。
- 不做 RAG：V0.3 的 AI 试问不把知识库片段作为检索上下文进入 prompt，不宣称向量库或完整 RAG。
- 不做 Agent：V0.3 不包含 AI Agent、长期记忆、工具调用编排或自动执行。
- 不做自动触达：AI 不能自动发送短信、企微、个微、电话或营销消息。
- 不做医疗决策：AI 只可用于低敏试问、辅助说明和运营建议，不能替代医生或机构人员决策。
- 不修改 schema 或 migration 而未授权：AI 多厂商相关 schema 和 migration 的变更必须单独审批。
- 遵守当前架构和权限边界：平台端使用 `platform_admin`，机构端使用既有租户隔离和 RBAC，不新增权限角色或放宽访问控制。

### 侧边聊天 AI 客服参考材料（2026-06-27 补充）

侧边聊天资料中提到的百引 AI 智能助手材料，可作为后续 AI 客服、知识库应用、工作台托管和用量统计的产品参考。它反映的成熟产品方向包括客服工作台、知识库应用、AI 应用配置、人工接管、消息延时、消息拆解、多模态素材发送和 token 用量统计。

该材料对智美天工的启发是：AI 能力后续不应停留在单次问答，而应逐步形成“知识库 -> AI 应用 -> 客服 / 运营工作台 -> 人工接管 -> 用量统计”的产品链路。

当前边界必须明确：V0.3 已具备知识库上传解析、真实 AI 低敏试问、用量记录和平台聚合等底座能力，但尚不等同于完整 AI 客服托管系统。企微 / 个微自动接待、AI 人设编排、转人工、消息延时、消息拆解、多模态素材自动发送、token 预充值扣费和客服账号托管启用方式，均属于后续增强方向，进入 runtime 前必须单独审批。

## SCRM / 客户运营的位置

SCRM、客户运营、随访、复诊、复购和沉睡客户唤醒属于产品主线。

SCRM 是能力描述，表示客户运营、客户分层、随访、复诊、复购、触达和关系维护等能力集合；正式产品定位仍优先使用“AI 客户运营中台”。

系统应围绕客户生命周期推进：

- 新客户进入和档案建立。
- 预约、到院、项目、治疗记录沉淀。
- 治疗后随访与关怀。
- 复诊提醒与复购机会识别。
- 沉睡客户唤醒。
- 标签、分层和 SOP 流程编排。
- 企业微信 / 微信等触达渠道接入。
- 运营看板与审计追踪。

## 企业微信 / 微信的位置

企业微信 / 微信触达是后续增强能力。

1.0 可以保留内部提醒、话术草稿、触达建议、触达记录和人工确认，不做自动微信发送、自动企微发送、自动营销或自动客服。

## 当前不是哪些系统

- 不是 HIS。
- 不是电子病历系统。
- 不是财务收费系统。
- 不是真实第三方系统连接平台的完整实现。
- 不是已经具备自动外呼、自动企微触达、真实 Webhook 或真实外网同步的系统。
- 不是无人工确认的医疗建议自动化系统。

## 下一阶段候选方向

以下事项是产品方向候选，不自动进入开发：

- 套餐权益真实限制闭环：让套餐权益、容量、连接器和机构端可用能力真正联动。
- AI 用量配额与限制：把 AI 调用额度、失败记录、超额策略和平台端聚合进一步闭合。
- 知识库服务端检索 / RAG 独立设计：单独设计检索、引用、权限、审计和安全边界，不混入当前 AI 试问。
- 对外演示资料 / 销售演示脚本：把 V0.3 可体验路径整理成面向非技术用户的演示材料。
- 产品基线持续维护机制：每次体验版能力进入 main 和测试服后，更新产品事实源、决策日志和不可宣称边界。
