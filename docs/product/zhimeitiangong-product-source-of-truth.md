## 一句话定位

智美天工是面向医美 / 美业机构的 AI 客户运营中台，不是 HIS 系统，也不是单纯 CRM 或 AI 聊天工具。

V1-SCOPE-LOCK-01 锁定后，1.0 正式定位优先使用“AI 客户运营中台”。SCRM 可以作为能力描述，但不作为唯一正式产品定位。

## 服务对象

- 医美机构经营者、院长、门店负责人。
- 咨询师、客服、运营人员、复诊复购负责人。
- 需要统一客户运营、随访、复诊、复购和沉睡客户唤醒流程的美业机构。
- 平台侧运营、租户管理、套餐配额和审计治理人员。

## 核心业务价值

智美天工的核心价值是把医美 / 美业机构分散在客户档案、预约、治疗、咨询、随访、复诊、复购和外部触达渠道中的信息，沉淀为可执行、可追踪、可审计的客户运营闭环。

当前可见资料中最稳定的产品主线是：

`客户进入系统 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访建议 -> 人工确认任务 -> 智能随访 -> 客户时间线 -> 运营看板 -> 审计追踪`

V1-SCOPE-LOCK-01 锁定 1.0 主线为：

`客户档案 / 患者信息 -> 预约 / 到院 -> 项目 / 治疗记录 -> 治疗后摘要 -> 随访任务 -> 复诊提醒 -> 复购机会 -> 沉睡客户机会 -> 人工确认 -> 基础运营看板 -> 审计追踪`

1.0 范围来源以 `docs/product/zhimeitiangong-v1-scope.md` 为准。

## 医美 / 美业 / 机构运营的位置

医美 / 美业场景是产品主场景，机构运营是系统主线。系统关注的不是单次治疗记录本身，而是围绕治疗前后形成的客户关系经营、复诊复购、服务质量、运营效率和可追踪合规。

## HIS 的位置

HIS 是重要的数据来源和未来连接对象之一，但不是智美天工的产品主线。

V1-SCOPE-LOCK-01 锁定：HIS 是数据来源之一，不是 1.0 主线，不阻塞 1.0。

在当前可见资料中，HIS 的合理位置是：

- 提供预约、治疗、消费、项目、客户或患者相关数据。
- 作为多来源数据接入的一类外部系统。
- 支撑客户运营闭环的数据补全，而不是替代客户运营中台。
- 1.0 可用模拟数据、人工录入或轻量导入先完成闭环验证。

当前不应把真实 HIS 连接、真实凭证、真实外网调用、生产级 HIS adapter、scheduler 或 schema 扩展作为产品事实源的前置条件。

1.0 可安全保留已有 HIS fake / 模拟 / 手工输入能力，但不得描述为真实 HIS 同步或真实 HIS 健康探测。

## AI 的位置

AI 在智美天工中是辅助客户运营的能力，不是自动替代人工决策的主体。

V1-SCOPE-LOCK-01 锁定：AI 是建议、草稿、标签、提醒、运营洞察和低风险 SOP 回复草稿的辅助能力，必须保留人工确认，不做自动医疗决策。

当前可见资料中，AI 更适合承担：

- 随访话术建议。
- 客户沟通辅助。
- 治疗后关怀内容辅助。
- 标签画像、客户分层、复诊复购机会提示的辅助分析。
- 后续可演进为 AI Agent，但需要单独确认边界、风险、审计和人工确认机制。

当前不应宣称已经具备真实 AI provider、RAG、AI Agent、自动医疗建议或自动触达能力。

1.0 不做 AI 自动客服、AI 自动医疗建议、AI Agent 自动执行或 RAG / Agent 生产能力。

## SCRM / 客户运营的位置

SCRM、客户运营、随访、复诊、复购和沉睡客户唤醒属于产品主线。

SCRM 是能力描述，表示客户运营、客户分层、随访、复诊、复购、触达和关系维护等能力集合；正式产品定位仍优先使用“AI 客户运营中台”。

系统应围绕客户生命周期推进：

- 新客户进入和档案建立。
- 预约、到院、项目、治疗记录沉淀。
- 治疗后随访与关怀。
- 复诊提醒与复购机会识别。
- 沉睡客户唤醒。
- 标签、分层和 SOP 流程编排。
- 企业微信 / 微信等触达渠道接入。
- 运营看板与审计追踪。

## 企业微信 / 微信的位置

企业微信 / 微信触达是后续增强能力。

1.0 可以保留内部提醒、话术草稿、触达建议、触达记录和人工确认，不做自动微信发送、自动企微发送、自动营销或自动客服。

## 当前不是哪些系统

- 不是 HIS。
- 不是电子病历系统。
- 不是财务收费系统。
- 不是真实第三方系统连接平台的完整实现。
- 不是已经具备自动外呼、自动企微触达、真实 Webhook 或真实外网同步的系统。
- 不是无人工确认的医疗建议自动化系统。

## 本轮边界

PRODUCT-REBASE-01 只做产品事实源收口；V1-SCOPE-LOCK-01 只做 1.0 范围锁定。二者都不做任何 runtime 实现，不继续推进 Phase 24 HIS 风险治理任务。

本文件中的后续方向、增强项和候选任务，都不是开发许可。进入 runtime 前必须由用户在后续任务中明确授权。
