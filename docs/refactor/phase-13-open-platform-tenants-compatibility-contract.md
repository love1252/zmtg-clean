# 第十三阶段：开放平台 tenants 路由族兼容契约

## 路由族

`/api/open-platform/tenants`

## 当前入口

| 实际入口 | 方法 | 当前职责 |
|---|---|---|
| `/api/open-platform/tenants` | GET | 读取租户管理列表 |
| `/api/v1/open-platform/tenants` | POST | 创建租户并绑定套餐 |

## 静态证据结论

- 两个入口只是在移除 `/v1` 后归入同一路由族。
- 两个入口没有相同的 HTTP 方法。
- 非版本化入口要求 `tenant/read_detail` 权限。
- 版本化入口要求 `tenant/manage_status` 权限。
- 两个入口使用不同的仓储、服务和响应契约。
- 它们不是行为等价的旧版／新版别名。

## 当前决策

- 不建立简单代理。
- 不建立 HTTP 重定向。
- 不删除任一入口。
- 不移动任一路由文件。
- 不将 GET 与 POST 合并为所谓统一兼容入口。
- 保持现有权限和租户隔离行为不变。

## 后续门槛

1. 先决定完整的租户管理 API 资源模型。
2. 明确列表读取和租户创建是否应统一进入同一版本命名空间。
3. 分别建立 GET 和 POST 的契约测试。
4. 核对仓库外客户端、网关和文档调用。
5. 明确兼容期、弃用信号、观测和回退。
6. 未完成以上条件前，不修改路由实现。

## 安全边界

- 本阶段不修改 API 或源码。
- 本阶段不连接数据库。
- 本阶段不执行真实租户创建。
- 本阶段不修改权限、租户隔离或错误响应。
