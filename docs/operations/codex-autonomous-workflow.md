# Codex 自主执行工作流

> 日期：2026-05-29  
> 状态：执行规则  
> 目标：让 Codex 在「智美天工 Clean」项目中自主安排分支、测试、提交、PR、开发日志和风险升级，减少人工过程管理。

## 1. 总原则

- 默认由 Codex 主动拆解任务、建立分支、实现、验证、提交、推送和创建 PR。
- PR、提交说明、开发日志默认使用中文；分支名、代码标识符、文件名、API 路径和环境变量使用英文。
- `main` 始终代表稳定版本；功能开发默认在 `codex/*` 分支完成。
- 每个阶段都要留下可追踪记录：分支、PR、验证命令、风险、下一步。
- 高风险模块必须先输出方案，再实现；不得边猜边改。

## 2. 分支策略

| 场景 | 分支规则 | 示例 |
| --- | --- | --- |
| 页面、样式、静态壳 | `codex/<scope>` | `codex/visual-foundation` |
| 普通功能模块 | `codex/<module>-<feature>` | `codex/auth-demo-session` |
| Bug 修复 | `codex/fix-<issue>` | `codex/fix-login-redirect` |
| 文档和流程 | `codex/docs-<topic>` | `codex/docs-workflow` |
| 高风险架构 | `codex/plan-<topic>` 先放方案 | `codex/plan-rbac` |

如果当前正在 `main` 且存在未提交开发变更，先创建对应 `codex/*` 分支，再提交。

## 3. PR 规则

默认需要 PR：

- 用户可见页面、登录页、工作台、平台后台变更。
- 新增或修改 API。
- 新增业务模块。
- 修改共享组件、工具函数、测试配置或构建配置。
- 修改认证、权限、租户、审计、AI、知识库、开放平台、计费等核心模块。

可以不单独开 PR 的情况：

- 已经在当前功能分支内的小型补充提交。
- 同一 PR 内补测试、补文档、修 lint。
- 尚未推送的本地同一阶段整理。

PR 默认创建为 Draft，满足以下条件后可转 Ready：

- `pnpm lint` 无错误。
- `pnpm test` 全部通过。
- `pnpm typecheck` 通过。
- `pnpm build` 通过。
- 浏览器预览完成，关键页面无明显错位或横向溢出。
- PR 正文写明风险和未完成项。

## 4. `main` 合并/推送规则

默认不直接向 `main` 推送开发代码。

允许自动合并到 `main` 的情况：

- 仅文档、流程、README、开发日志等低风险变更。
- 静态页面或视觉壳，且本地完整验证通过。
- PR 已清楚标注风险，且没有认证、权限、数据库、生产配置影响。

必须等待用户确认后才能合并或直接推 `main`：

- 数据库 schema 或迁移。
- 租户隔离、RBAC、权限策略。
- API Key、OAuth、Webhook 签名。
- Agent 工具调用权限。
- 知识库/RAG 架构。
- 客户画像、标签、事件模型。
- 支付、计费、生产配置、环境变量。
- 删除文件或大规模重构。

## 5. 测试策略

每次 PR 至少执行：

```bash
pnpm lint
pnpm test
pnpm typecheck
pnpm build
```

页面和视觉变更额外执行：

- 浏览器打开相关页面。
- 检查桌面端关键页面。
- 检查移动端是否有横向溢出。
- 必要时保存截图并在总结中附上。

API、认证、权限、数据模块额外要求：

- 先写测试或补测试。
- 覆盖成功路径、失败路径、越权路径。
- 明确输入校验和错误返回。
- 涉及租户数据时必须验证租户边界。

## 6. 开发日志规则

开发日志放在：

```text
docs/devlog/YYYY-MM-DD.md
```

每次阶段性提交或 PR 后追加一条记录，格式如下：

```text
## HH:mm 阶段名称

- 分支：
- PR：
- 目标：
- 完成：
- 修改文件：
- 验证：
- 风险：
- 下一步：
```

开发日志用于记录项目真实演进，不替代 PR 描述；PR 记录代码变更，开发日志记录阶段决策和上下文。

## 8. 风险升级规则

Codex 可以自动推进低风险和中风险任务，但以下情况必须先停下来写方案：

- 需要修改数据库模型。
- 需要定义租户隔离或权限边界。
- 需要设计开放平台接口。
- 需要处理 API Key、OAuth、Webhook、签名或密钥存储。
- 需要把 mock/demo 逻辑切换为真实生产逻辑。
- 需要删除旧文件、替换架构、跨模块大重构。

方案至少包含：

- 目标和范围。
- 影响文件。
- 数据结构或接口变化。
- 安全风险。
- 测试计划。
- 回滚策略。

## 9. 当前可用能力

当前项目自动执行主要使用：

- Superpowers：规划、测试驱动、系统化调试、完成前验证。
- GitHub：分支、推送、PR、PR 评论。
- Browser：本地页面预览和截图验证。

暂时不需要额外安装新 skill。若后续进入 UI 设计探索、文档生成、CI 修复或 OpenAI API 接入，再按具体任务选择对应 skill。
