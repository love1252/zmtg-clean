# 开放平台基础治理第一阶段

## 范围

本阶段只建立开放平台治理基准：租户隔离原则、角色权限边界、API Key / OAuth / Webhook 生命周期展示、审计事件词汇和平台端可视化入口。

本阶段不实现真实数据库、不生成或保存真实密钥、不处理 OAuth 授权回调、不签名或投递 Webhook、不新增外部回调和第三方集成。

## 租户隔离基准

- 租户身份只能来自后续可信服务端上下文，不能信任浏览器缓存、前端参数或 URL 中的租户标识。
- 平台端默认展示跨租户聚合状态，不能默认展示机构客户明细、治疗记录、咨询记录或其他敏感个人信息。
- 机构管理员只能查看本租户资源和本租户开放连接状态，不能读取其他租户配置或平台级策略。
- 敏感数据默认不可见，任何明细读取都必须在后续真实权限体系中单独审批、审计和测试。

## 权限边界基准

- 平台超级管理员：可管理租户运营状态和策略草案，但第一阶段不能读取租户客户 PII。
- 平台运营：可查看平台聚合运营状态和平台健康，不修改安全策略。
- 安全审计员：可查看审计事件和导出审计报告，不轮换凭证、不修改租户状态。
- 机构管理员：只能查看本租户开放连接态势，不能管理平台级策略。

## 生命周期基准

- API Key：草稿、启用、轮换中、已吊销。
- OAuth 应用：草稿、已配置、已发布、已暂停。
- Webhook：草稿、已启用、降级、已停用。

这些状态当前只是可视化和术语基准，不能被解释为真实密钥、真实授权或真实外部投递已经可用。

## 审计事件基准

第一阶段统一四类审计事件词汇：

- 租户边界事件
- 权限策略事件
- 开放连接生命周期事件
- 安全审查事件

每类事件后续进入真实实现时至少需要包含：事件 ID、操作者 ID、操作者角色、租户范围、资源类型、资源 ID、动作、结果、发生时间。

## 合并前检查

- 检查新增文件是否只涉及前端静态治理模型、页面面板、测试和文档。
- 检查没有新增 API 路由、数据库模型、迁移文件、环境变量或外部网络回调逻辑。
- 检查页面文案没有展示真实凭证、令牌、私钥、签名密钥或第三方回调目标。
- 运行 lint、测试、类型检查、构建。
- 通过浏览器检查 `/open-platform` 桌面端和移动端，确认治理面板不挤压现有平台端视觉。

## 后续阶段准入条件

进入真实 API Key / OAuth / Webhook 实现前，必须先完成单独方案评审，覆盖：

- 租户上下文来源和服务端强制校验。
- 权限策略存储、审批流和越权测试。
- 凭证哈希、加密、轮换、吊销和脱敏展示策略。
- OAuth 授权范围、回调域名校验、令牌生命周期和撤销策略。
- Webhook 签名、重试、幂等、死信和投递审计策略。
- 审计日志不可篡改、查询权限、导出权限和保留周期。
